> 📄 **论文**：ClawBench: Can AI Agents Complete Everyday Online Tasks?
> 🔗 **arXiv**：[2604.08523](https://arxiv.org/abs/2604.08523)
> 🏢 **机构**：多家机构联合（Yuxuan Zhang, Yubo Wang et al., 21位作者）

## 一句话总结

ClawBench 是首个在真实生产网站上评估AI智能体日常在线任务能力的基准，覆盖144个平台的153项任务，测试揭示最强的 Claude Sonnet 4.6 仅能完成33.3%的任务，远低于在沙盒基准上的表现。

## 背景与问题

AI智能体在受控沙盒环境中的基准测试上表现越来越好——Claude和GPT在WebArena等基准上达到65-75%的成功率，看起来已经接近可用。然而，真实世界的任务复杂度远超沙盒测试。

**现有基准的三大局限性：**

1. **沙盒环境失真**：大多数基准使用预先录制的网站快照或模拟环境，而不是真实的动态网页
2. **任务类型偏差**：主要评估信息查找和导航，忽略了大量需要实际提交表单的"写重型"任务
3. **平台覆盖不足**：许多基准只涵盖3-15个网站，而真实用户日常使用数百个平台

ClawBench 的出发点是：**如果AI助手不能帮我在真实网站上购物、预约、申请职位，它再智能也没有实际价值。**

## 核心方法

### 基准设计

**任务覆盖：**
- 153项任务，反映真实日常网络活动
- 涵盖144个真实在线平台（购物、预订、求职等）
- 8个高级分组 × 15个细粒度类别

![任务分类](https://arxiv.org/html/2604.08523v1/x4.png)
*图：ClawBench任务分类体系——内圈8个大类，外圈15个细分类别*

| 大类 | 示例任务 |
|-----|---------|
| Daily（日常） | 购物、订餐 |
| Finance（金融） | 转账、理财申请 |
| Work（工作） | 求职申请、项目管理 |
| Dev（开发） | GitHub提交、包管理 |
| Academic（学术） | 论文投稿、数据库查询 |
| Travel（出行） | 机票预订、酒店预订 |
| Social（社交） | 论坛发帖、内容创作 |
| Pets（宠物） | 宠物服务预约 |

### 安全拦截机制（关键创新）

真实网站评估面临的核心挑战：如何防止智能体真正提交表单、完成实际购买？

![评估流程图](https://arxiv.org/html/2604.08523v1/x3.png)
*图：ClawBench评估流程——从任务设置到执行再到评估的完整链路*

解决方案：**Chrome扩展 + CDP（Chrome DevTools Protocol）拦截**

```
用户浏览 → 所有请求正常通过
        ↓
终端提交请求 → 被拦截并阻断（只拦截这一个）
        ↓
记录完整请求体 → 与人工标注的ground truth对比
```

- 100%准确率：在人工运行中零误拦截导航流量
- 零真实世界副作用：没有真实订单被提交

### 五层轨迹记录

| 层次 | 内容 | 工具 |
|-----|------|------|
| 会话录制 | 完整视频 | Xvfb + FFmpeg |
| 操作截图 | 每步截图 | CDP |
| HTTP流量 | 完整请求 | CDP |
| 智能体消息 | 推理链+工具调用 | 日志 |
| 浏览器操作 | 点击/输入/滚动 | Playwright |

### 评估协议

使用 Claude Code 子智能体作为评估器，对比智能体轨迹与人工参考轨迹，输出：
- 二元判决（成功/失败）
- 结构化理由（字段级检查）

### 与传统基准的差距

| 基准 | Claude Sonnet 4.6 | GPT-5.4 |
|-----|-------------------|---------|
| OSWorld | ~65-75% | ~65-75% |
| WebArena | ~65-75% | ~65-75% |
| **ClawBench** | **33.3%** | **6.5%** |

性能断崖式下跌说明：**在受控环境中的优秀表现无法迁移到真实世界任务**。

### 任务失败原因分析

主要失败模式：
- 多步导航中的决策错误
- 复杂表单填写（需要准确填写大量字段）
- 文档理解不足（服务条款、规则说明）
- 动态网页交互适应性差

## 总结

ClawBench 填补了AI智能体研究中的重要空白：一个真实、多样、覆盖广泛的在线任务评估平台。测试结果令人警醒——即便是最强的前沿模型，在帮助普通用户完成日常网络任务方面仍然差强人意。

这项研究对AI助手产品化具有重要的现实意义：现有基准测试的高分并不意味着产品可用性，我们需要更接近真实场景的评估。

**局限性**：实验结果随网站更新可能发生变化（网站是动态的）；153个任务样本量较小，某些类别仅有少数任务；拦截机制只针对最终提交请求，不覆盖中间的数据读取操作；评估协议中LLM评判者本身也可能存在偏差。
