> 📄 **论文**：TRUST-SQL: Tool-Integrated Multi-Turn Reinforcement Learning for Text-to-SQL over Unknown Schemas
> 🔗 **arXiv**：[2603.16448](https://arxiv.org/abs/2603.16448)
> 🏢 **机构**：美团（Meituan）

## 一句话总结

TRUST-SQL 将文本到 SQL 任务建模为部分可观测马尔可夫决策过程，通过四阶段协议和双轨 GRPO 策略，在不预加载数据库模式的条件下，相比基础模型平均提升 30.6%（4B）和 16.6%（8B）的性能。

## 背景与问题

Text-to-SQL 技术近年来取得了显著进展，但几乎所有成功都建立在一个理想化假设上：**完整模式假设（Full Schema Assumption）**——即将数据库的全部表结构预先提供给模型。

然而，在真实的企业生产环境中，这一假设往往不成立：

- **规模庞大**：企业数据库可能包含数百甚至数千张表，全部注入上下文会超出模型的最大 token 限制
- **元数据噪声**：表名、列名可能模糊、冗余或具有误导性
- **动态变化**：数据库 schema 会随业务发展不断变化

这催生了**未知模式（Unknown Schema）**场景：模型无法预先知道完整的数据库结构，必须像侦探一样主动探索、识别并验证与当前查询相关的表和列。

## 核心方法

TRUST-SQL（Truthful Reasoning with Unknown Schema via Tools）将任务形式化为**部分可观测马尔可夫决策过程（POMDP）**，并设计了结构化的探索-推理协议。

### 四阶段结构化协议

![TRUST-SQL 系统架构](https://arxiv.org/html/2603.16448v1/x1.png)
*图1：TRUST-SQL 四阶段协议示意图，展示智能体如何从模糊查询到精确 SQL 的完整推理流程。*

**阶段一：问题理解与初步探索**
解析自然语言查询意图，识别关键实体和关系，制定探索策略。

**阶段二：模式探索与验证**
通过工具调用（如 DESCRIBE TABLE、SHOW COLUMNS 等）主动查询数据库元数据，逐步构建对相关 schema 的理解。所有元数据通过工具调用动态获取，而非预先注入。

**阶段三：候选 SQL 生成**
基于已验证的 schema 知识，生成候选 SQL 查询。

**阶段四：执行验证与修正**
执行 SQL 并根据执行结果（成功/错误/空结果）进行验证和迭代修正。

![四阶段协议详情](https://arxiv.org/html/2603.16448v1/x2.png)
*图2：TRUST-SQL 四阶段协议的详细说明，包括每个阶段使用的工具和推理步骤。*

### 双轨 GRPO：解决信用分配问题

在强化学习训练中，TRUST-SQL 面临一个独特的信用分配挑战：多轮交互中的**探索奖励**（成功找到相关 schema）和**执行奖励**（成功生成并执行正确 SQL）在性质上截然不同，如果简单混合会导致训练信号相互干扰。

**双轨 GRPO（Dual-Track GRPO）**通过**token 级掩码优势**（Token-Level Masked Advantages）将两类奖励信号分离：
- **探索轨迹**：仅对 schema 探索相关的 token 施加探索奖励梯度
- **执行轨迹**：仅对 SQL 生成相关的 token 施加执行奖励梯度

这种精细的信用分配使得每类行为都能获得准确的训练信号，相比标准 GRPO 取得了 **9.9% 的相对性能提升**。

## 实验结果

TRUST-SQL 在 5 个 Text-to-SQL 基准上进行了评估，涵盖不同规模和复杂度的数据库场景。

| 模型 | 平均改进 | 基准表现 |
|------|----------|----------|
| TRUST-SQL-4B | **+30.6%**（vs. 基础模型）| 与模式预填充基线持平或更优 |

## 总结

TRUST-SQL 将真实企业环境中的 Text-to-SQL 挑战推进了关键一步。通过 POMDP 建模和双轨 GRPO 训练策略，系统能够像经验丰富的数据工程师一样，从未知的数据库环境中主动探索并验证相关 schema，最终生成准确的 SQL 查询。

当前局限性包括：多轮工具调用增加了延迟；对于极度混乱的 schema（大量无意义的表名）仍然具有挑战性；对超过数千张表的超大规模数据库的可扩展性有待验证。
