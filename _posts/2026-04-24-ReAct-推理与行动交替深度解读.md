## 基本信息

- **作者**: Shunyu Yao, Jeffrey Zhao, Dian Yu, Nan Du, Izhak Shafran, Karthik Narasimhan, Yuan Cao
- **机构**: Princeton, Google Research
- **发表**: ICLR 2023
- **arXiv**: [2210.03629](https://arxiv.org/abs/2210.03629)

## 一句话总结

提出 **ReAct (Reasoning + Acting)**——把 **Chain-of-Thought(纯推理)和 Action(调用工具/环境)两条本来分开的路线合成一条** 交替循环:LLM 输出 `Thought → Action → Observation → Thought → Action → ...`,用 CoT 来计划下一步做什么,用 Action 得到外部反馈后再更新推理。这个看似朴素的 prompting 范式,把"静态推理"升级为"可与外界互动的 agent",成为之后几乎所有 LLM agent 的事实基石。Hotpot QA / FEVER / ALFWorld / WebShop 上全面超过单纯 CoT 和单纯 Act。

## 背景:两条分离的路线

### 只推理(CoT)的局限

CoT(Wei 2022)让 LLM 输出中间推理步骤:

```
Q: 23 × 17 = ?
A: Let me think. 23 × 17 = 23 × 10 + 23 × 7 = 230 + 161 = 391
```

问题:**完全内部推理,不能访问外部信息**。遇到需要事实(比如"奥巴马的出生年"),CoT 只能凭记忆——而 LLM 的事实记忆经常错。

### 只行动(Act)的局限

一些早期 agent(WebGPT, 纯 RL agent)只输出动作,没有 thought:

```
Action: Search("Obama birth year")
Observation: 1961
Action: Answer("1961")
```

问题:**盲目操作,无法规划多步任务**。复杂任务里每一步都要"拍脑袋"决定,容易钻牛角尖。

### ReAct 的融合

ReAct 让两者**交替出现**:

```
Thought: I need to find Obama's birth year first.
Action: Search("Obama birth year")
Observation: 1961
Thought: Now I need the year the Beatles formed.
Action: Search("Beatles formation")
Observation: 1960
Thought: So Obama was born 1 year after Beatles formed. Answer: 1.
Action: Finish("1")
```

**推理指导下一步动作,观察修正推理**——这是 ReAct 的灵魂。

## 核心机制

### Prompt 格式

ReAct 用**少量 in-context 示例**教模型这种交替格式:

```
Question: ...
Thought: <reasoning about what to do>
Action: <tool call with args>
Observation: <tool return>
Thought: <update reasoning>
Action: ...
...
Thought: I have the final answer.
Action: Finish(<answer>)
```

Agent 循环:

1. LLM 续写 Thought + Action
2. 系统解析 Action,调用对应工具/环境
3. 把 Observation 追加到 prompt
4. 回到 1,直到看到 `Finish()`

### 关键设计细节

**Thought 的"自由格式"**:不强制格式,让模型自然地做以下任一:

- 分解任务("我应该先 ..., 再 ...")
- 跟踪状态("我已经知道 A 和 B, 还缺 C")
- 注入常识("这个结果不太对, 可能是 ... 原因")
- 决定何时停("我已经有答案了")

**Action 的有限集**:对每个任务定义小型 tool 集,如 Hotpot QA 只有 `Search[entity]` / `Lookup[keyword]` / `Finish[answer]` 三个。

## 实验结果

### 1. 知识密集任务(Hotpot QA, FEVER)

![在 Hotpot QA 上 ReAct 比纯 CoT 准确率提升 4-5 分,比纯 Act 提升 20+ 分。结合 ReAct→CoT-SC(失败时 fall back 到 CoT self-consistency)达到最佳。](/assets/img/react/x2.png)
_Figure 2:Hotpot QA 和 FEVER 上各种方法对比_

| 方法 | Hotpot EM | FEVER Acc |
|------|-----------|-----------|
| CoT | 29.4 | 56.3 |
| CoT-SC | 33.4 | 60.4 |
| Act-only | 25.7 | 58.9 |
| **ReAct** | **27.4** | **60.9** |
| ReAct → CoT-SC | **35.1** | **64.6** |

ReAct 单独略逊于 CoT-SC(因为外部 search 偶尔失败),但**组合策略**(先用 ReAct,失败再用 CoT-SC)表现最佳。

### 2. 决策任务(ALFWorld, WebShop)

ALFWorld(具身家务任务)和 WebShop(网购模拟)是 action-heavy 场景——CoT 无法用(无工具)。

![ALFWorld 上 ReAct 成功率 71%,BUTLER(纯 RL agent)45%。在 WebShop 上 ReAct 的成功率和得分都领先。](/assets/img/react/x3.png)
_Figure 3:ALFWorld / WebShop——决策任务上 ReAct 碾压 Act-only_

| 方法 | ALFWorld 成功率 |
|------|----------------|
| BUTLER(RL) | 26% |
| Act-only | 45% |
| **ReAct** | **71%** |

Thought 的加入让 **成功率几乎翻倍**。原因:复杂任务需要规划、回溯、错误诊断——这些都是 Thought 的自然功能。

### 3. 失败模式分析

![ReAct 的常见失败:Thought 走偏、Search 返回的结果不相关、达到最大步数仍未完成。这些分析启发了后续 Reflexion 等工作。](/assets/img/react/x5.png)

## 工程影响

### 1. 所有现代 agent 框架的默认范式

LangChain、LlamaIndex、AutoGPT、BabyAGI、Claude Code 等**几乎所有 LLM agent 框架默认都用 ReAct**(或其变体)。

### 2. Tool calling / Function calling 的思想原型

OpenAI Function Calling(2023)、MCP(2024)本质上都是"结构化的 ReAct"——Thought 进 assistant message,Action 进 tool call,Observation 进 tool response。这条技术演进线直接起源于 ReAct。

### 3. 启发了 Reflexion / LATS 等后续工作

Reflexion 在 ReAct 之上加**反思步骤**;Tree of Thoughts 把 Thought 扩成**树搜索**;LATS 把整个循环做成 **MCTS**。ReAct 是它们的 scaffold 祖先。

### 4. Prompt-only 胜过 fine-tune

ReAct 证明**不需要任何微调,仅靠 in-context 示例**就能解锁复杂 agent 能力。这让 agent 研究的门槛大幅降低。

---

## 局限

### 1. 长 horizon 任务容易失败

步数超过 10-20 步时,Thought 可能偏离、重复、遗忘早期信息。对长 horizon(如写整个软件项目)ReAct 不够。

### 2. 错误不可恢复

ReAct 默认"前进式"——Thought 错了就一路错下去。Reflexion / LATS 加反思和回溯就是为解决这点。

### 3. Tool 设计影响巨大

Action 的命名、参数、返回格式对 ReAct 表现影响巨大。SWE-Agent 的贡献之一就是提出 ACI(Agent-Computer Interface)规范化这些。

### 4. 依赖 base model 的推理能力

弱模型(< 7B)运行 ReAct 质量差。强模型(GPT-4, Claude)才能充分利用这个范式。

## 读完这篇你真正该带走的 4 件事

<callout emoji="white_check_mark" background-color="light-green" border-color="green">
1. **推理和行动不是对立的,是互补的**:Thought 指导 Action,Observation 修正 Thought——这个闭环是所有 agent 的灵魂
2. **Prompt 格式本身就是一种架构**:ReAct 看起来只是个 prompt 模板,但它定义了 LLM 与环境交互的"协议",是工程层面的架构
3. **内部推理 + 外部交互 = agent**:纯 LLM(CoT)解决不了需要实时信息的任务;纯 tool use 解决不了需要规划的任务。合起来才是 agent
4. **简单 + 通用 = 范式**:ReAct 没有新模型、新算法,只是一个 prompt 框架。但它的通用性和简单性让它成为 agent 时代的"HTTP"——每个 agent 都用它
</callout>
