## 一句话总结

Mellum 2 是 JetBrains 推出的 12B 参数 MoE 代码语言模型（每 token 激活 2.5B），专为 IDE 软件工程场景设计，支持 128K 上下文，推理速度与 Qwen2.5-7B 持平甚至更优。

## 背景与问题

大型语言模型已深刻改变开发者的工作方式，从代码补全、调试到代理式编程助手。JetBrains 此前的 Mellum 4B 是一个专注代码补全的密集模型，而 Mellum 2 是其后继者，目标是在保持低推理延迟的同时，大幅扩展能力范围：
- 代码生成与编辑
- 调试与多步推理
- 工具使用与函数调用
- 代理式编程
- 对话式编程助手

核心设计约束：**以商用 GPU 的推理效率作为架构设计的硬约束**，而非单纯追求性能最大化。

## 核心方法

### 模型架构

*图1：不同隐维度和层数的 MoE 架构（64 专家，8 激活）等延迟映射。*

![等延迟映射（Dense）](https://arxiv.org/html/2605.31268v1/x2.png)
*图2：密集模型 Qwen3 架构（4 个 KV 头）等延迟映射，虚线标注 Mellum 4B 和 Qwen2.5-7B 的延迟基准。*

**关键架构选择**（均经过消融验证）：

| 组件 | 配置 |
|------|------|
| 总参数量 | 12B |
| 激活参数量 | 2.5B / token |
| 专家配置 | 64 个专家，每 token 激活 8 个 |
| 注意力机制 | 分组查询注意力（4 个 KV 头） |
| 滑动窗口注意力 | 每 4 层中的 3 层使用 SWA |
| 多 Token 预测头 | 既作预训练辅助目标，又作投机解码草稿模型 |

![SWA 延迟对比](https://arxiv.org/html/2605.31268v1/x3.png)
*图3：带 SWA 的 MoE 模型与 Qwen2.5-7B 在不同输入长度下的延迟对比。即使在 2 倍上下文长度下，延迟仍与 Qwen2.5-7B 持平。*

### 预训练

**数据规模**：约 10.6 万亿 token，三阶段渐进式课程：
- 阶段一：多样化网络数据为主（代码占比 23%）
- 阶段二：代码和数学内容比例逐步提升
- 阶段三：高质量代码和数学内容（代码占比 42%）

### 长上下文扩展

从 8K → 128K 上下文，采用**层选择性 YaRN** 方法：仅对全局注意力层（非 SWA 层）应用 YaRN 位置编码调整。

![RULER 评分](https://arxiv.org/html/2605.31268v1/x7.png)
*图7：三种长上下文方案在不同评估上下文长度下的 RULER 评分对比。*

## 实验结果

![训练与验证准确率](https://arxiv.org/html/2605.31268v1/x12.png)
*图12：Instruct RL 运行的训练与验证准确率（任务宏平均）曲线。*

**核心性能亮点**：
- 推理延迟与 Qwen2.5-7B 持平甚至更优（尽管总参数 12B）
- SWA 架构确保长上下文推理效率不随上下文长度线性增长
- MTP 头作为投机解码草稿模型，进一步提升实际推理吞吐量

## 总结

Mellum 2 代表了 JetBrains 在"实用性优先"方向上的技术探索：以推理效率为硬约束进行架构设计，通过 MoE + SWA + MTP 的组合实现能力与效率的平衡。三阶段预训练课程 + 异步 GRPO 后训练的完整流程，以及详细的消融实验和系统工程细节，为社区提供了宝贵的参考。

作为 IDE 内置代码助手，低延迟和商用 GPU 友好是其区别于纯学术模型的核心差异化特征。
