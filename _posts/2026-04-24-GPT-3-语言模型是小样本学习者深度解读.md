## 基本信息

- **作者**: Tom B. Brown, Benjamin Mann, Nick Ryder 等(OpenAI)
- **机构**: OpenAI
- **发表**: NeurIPS 2020 (Best Paper)
- **arXiv**: [2005.14165](https://arxiv.org/abs/2005.14165)
- **全名**: *Language Models are Few-Shot Learners*

## 一句话总结

OpenAI 的里程碑之作——**GPT-3**:把 Transformer 语言模型从 GPT-2 的 1.5B 参数规模推到 **175B 参数**,训练数据规模 **300B tokens**。最重要的发现不是 benchmark 数字,而是一个**全新现象**:**In-Context Learning (ICL)**——不更新任何参数,只给几个例子放在 prompt 里,模型就能"学会"新任务,效果接近 fine-tune。这个发现改变了整个 NLP 范式——从"为每个任务训一个模型"变成"一个大模型通过 prompt 适配所有任务"。GPT-3 是大模型时代真正的起点,后续 ChatGPT、Claude、Gemini 都直接建立在它确立的范式上。

![GPT-3 的核心范式:In-context learning 有三种变体——zero-shot(无示例)、one-shot(1 个示例)、few-shot(K 个示例)。不需要参数更新,仅靠 prompt 就能让模型适配新任务。](/assets/img/gpt3/x1.png)
_Figure 1:In-Context Learning 的三种形式_

## 背景:Fine-tune 范式的痛点

### NLP 的 "finetune per task" 时代

2018-2020 年 NLP 主流范式是 **BERT-style pretrain → finetune**:

1. 预训练一个 encoder(BERT、RoBERTa 等)
2. 对每个下游任务(QA、NER、分类)加一个 task head
3. 在 task-specific 数据上 fine-tune

每个任务一个模型——存储、部署、更新都很麻烦。

### GPT-2 的线索

GPT-2(2019)发现:纯语言模型**不 fine-tune 也能做一些任务**(如 QA、翻译)——只要规模够大。GPT-2 在 WMT 翻译上 zero-shot 准确率有一定表现(虽然远不如专门 finetune)。

这给 OpenAI 团队一个假设:**继续 scale,也许 zero-shot 就能追上 finetune**。

### GPT-3 的雄心

- **175B 参数**:比 GPT-2 大 **117×**
- **300B 训练 token**:高质量 Common Crawl + WebText + Books + Wikipedia
- **不做任何 fine-tune**,只用 pretrained model + prompt 评估

结果震惊了世界。

## 核心发现:In-Context Learning

### 三种 prompt 形式

![In-Context Learning 的三种形式:zero-shot 只有任务描述,one-shot 加一个示例,few-shot 加 K 个示例。无需改权重,只在 prompt 里"描述任务"。](/assets/img/gpt3/x2.png)
_Figure 2:ICL 的三种 prompt 格式_

**Zero-shot**:只给任务描述

```
Translate English to French:
cheese =>
```

**One-shot**:描述 + 1 个例子

```
Translate English to French:
sea otter => loutre de mer
cheese =>
```

**Few-shot**:描述 + K 个例子

```
Translate English to French:
sea otter => loutre de mer
peppermint => menthe poivrée
plush girafe => girafe peluche
cheese =>
```

K 典型是 1-50。

### 惊人结果

![GPT-3 在多个 benchmark 上的 few-shot vs 模型大小曲线:随着模型从 125M 到 175B,few-shot 性能持续提升,175B 时部分任务接近或超过 SOTA finetune 模型。](/assets/img/gpt3/x3.png)
_Figure 3:随规模增长,few-shot 性能持续涌现_

- **Translation**:GPT-3 175B few-shot BLEU 接近 SOTA supervised
- **SuperGLUE**:71.8%,接近 finetuned T5-11B 的 89.3%(差距仍有,但 ICL 已经 workable)
- **TriviaQA**:71.2%,**超过 fine-tuned SOTA**
- **算术**:2 位数加法 few-shot 接近 100%

关键观察:**few-shot 性能随模型规模 smoothly 提升**——这是可 predict 的 scaling,意味着更大模型能解锁更强 ICL 能力。

## 其他关键实验

### 1. 算术能力随规模涌现

![GPT-3 的 2 位数加法、减法、乘法能力:小模型几乎为 0,13B 开始显著,175B 接近 100%(加法)。这是能力涌现的清晰证据。](/assets/img/gpt3/x4.png)
_Figure 4:算术能力的 scaling 曲线_

- 2 位数加法:175B few-shot ≈ 100%
- 3 位数加法:80%
- 2 位数乘法:50%

小模型(< 1B)这些任务几乎全错——**能力在 scale 到某个阈值后涌现**。

### 2. 写作能力

GPT-3 能生成以假乱真的新闻文章——人类判别"AI 生成"准确率只有 52%(接近随机)。这让大家第一次意识到**大模型在生成质量上的跳跃**。

### 3. Novel task

GPT-3 能处理从未见过的 novel task(如 "把词里字母顺序倒过来"、"把句子按奇偶位拆分")——**仅凭 few-shot 示例学会规则**。

## 训练细节

### 架构

- **96 层** Transformer
- **12288 hidden size**
- **96 heads** × 128 head dim
- **Context length: 2048**
- **Sparse attention 模式**(稀疏 local + 密集 global 交替,降低 $O(N^2)$ 开销)

### 数据

- **Common Crawl**(过滤)410B tokens
- **WebText2** 19B
- **Books1** 12B
- **Books2** 55B
- **Wikipedia** 3B

总计 500B tokens,实际训练采样 300B。**按"质量"做 reweighting**——高质量数据被采样更多次。

### 训练成本

- **3640 PF-days** 算力
- 按 2020 年 GPU 价格约 **$4.6M** 成本
- 在当时是 unprecedented 的 compute 投入

## 局限(OpenAI 自己承认)

### 1. ICL ≠ 真学习

ICL 的示例只是 "prime" 模型,模型没有真的从示例学到新知识——**换一种 prompt 可能全错**。这让 ICL 对 prompt engineering 高度敏感。

### 2. 偏见和有害内容

- GPT-3 生成文本中包含性别、种族、宗教偏见
- 可以被 prompted 生成 misinformation、fake news

这些问题在 InstructGPT / RLHF 之后才得到部分缓解。

### 3. 仍然不懂"常识"

**Physical reasoning** 上 GPT-3 经常犯低级错——比如 "If I put cheese in the fridge, will it melt?"。这提示模型学的是统计模式,不是因果理解。

### 4. Context 限制 2048 tokens

对长文档 QA、长程对话无力。后续工作才把 context 扩到 128K、1M。

## 历史影响

### 1. 开启大模型时代

GPT-3 之前,模型一般 < 1B。GPT-3 后,各大厂商比赛做更大模型:PaLM 540B、GPT-4(估计 1T+)、LLaMA 等。**"大"成为默认策略**。

### 2. 催生 Prompt Engineering

ICL 的发现让 prompt 成为一种可调的"程序"。这催生了 prompt engineering 作为一门学科,以及后来的 CoT、ToT 等 reasoning scaffold。

### 3. API 商业模式

GPT-3 API(2020 年 6 月公测)是第一个以 API 形式提供的大模型。这个 API-as-a-service 模式后来被所有大模型公司采用。

### 4. 引爆了 ChatGPT 的前奏

InstructGPT(2022-01)基于 GPT-3 + RLHF 对齐,成为 **ChatGPT(2022-11)的前身**。可以说 ChatGPT = GPT-3 + RLHF + Chat UI。

### 5. 确立了 decoder-only 架构的主导

GPT-3 之前,encoder-only(BERT)和 encoder-decoder(T5)还有竞争力。GPT-3 的成功让 **decoder-only autoregressive 成为 LLM 标准**,之后 LLaMA、Mistral、Qwen、DeepSeek 全部走这条路。

## 读完这篇你真正该带走的 4 件事

<callout emoji="white_check_mark" background-color="light-green" border-color="green">
1. **In-Context Learning 是 scale 的涌现礼物**:GPT-3 没有 fine-tune,但 175B 的 ICL 能力让"一个模型应对所有任务"成为现实。这个范式转换是大模型时代的定义性事件
2. **能力不是连续涌现,而是阈值涌现**:算术能力在 GPT-3 规模下从 0 跳到 ~100%——这种 "phase transition" 成为后续 scaling law、emergent abilities 研究的核心话题
3. **Scale 本身就是 insight**:GPT-3 论文没提新架构、新算法,但它证明 "把同一件事做大 100 倍" 会带来质变。这个简单道理后来被反复印证(参数、数据、test-time compute)
4. **每个工程师都应该读 GPT-3 论文**:这是 LLM 时代的 "圣经"。后续所有大模型工作都可以追溯到这里——理解它就是理解现代 AI 的起点
</callout>
