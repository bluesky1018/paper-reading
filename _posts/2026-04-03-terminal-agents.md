> 📄 **论文**：Terminal Agents Suffice for Enterprise Automation
> 🔗 **arXiv**：[2604.00073](https://arxiv.org/abs/2604.00073)
> 🏢 **机构**：ServiceNow；Mila – Quebec AI Institute；Université de Montréal

## 一句话总结

仅配备终端和文件系统的极简"终端智能体"（Terminal Agent），通过直接调用平台 API 即可与 GUI 智能体和 MCP 工具智能体相媲美，且成本低 5 倍，颠覆了"复杂工具越多越好"的传统观念。

## 背景与问题

企业级任务自动化是大语言模型（LLM）最具价值的应用场景之一。当前主流的 Agent 范式主要分为三类：

1. **MCP 智能体**：通过 Model Context Protocol 提供结构化工具调用接口，平台需要预先定义好每个操作的工具描述
2. **Web 智能体**：通过浏览器（如 Playwright）操作 GUI 界面，利用截图和 DOM 操作完成任务
3. **终端智能体**：仅有 Shell 和文件系统，通过编写代码直接调用 API

实践中普遍认为：MCP 工具越多越好，GUI 智能体能处理更复杂场景，而终端智能体因缺乏"向导"而能力受限。本文对这一假设发起挑战。

ServiceNow 等企业平台拥有数十到上百个 MCP 工具，但构建和维护这些工具集需要大量工程投入，且随着 API 版本更新需要持续维护。**是否有更简单高效的方式？**

## 核心方法

### 核心设计原则

StarShell 的工作机制：
- **动态能力发现**：Agent 通过查看 API 文档、测试端点等方式自主发现平台功能，无需预定义工具模式
- **技能积累（Skills）**：将成功完成的任务抽象为可复用的脚本，存储在文件系统中供后续调用

![技能积累曲线](https://arxiv.org/html/2604.00073/x1.png)
*图3：随任务数量增加，StarShell 积累的可复用技能不断增多，后续任务成本和时间持续下降*

### 三种范式对比

| 范式 | 工具 | 特点 |
|------|------|------|
| MCP 智能体 | 预定义工具注册表 | 结构化但受限于工具覆盖范围 |
| Web 智能体 | 浏览器 + DOM 操作 | 灵活但成本高、脆弱 |
| **终端智能体** | **Shell + 文件系统** | **极简、高效、可编程** |

## 实验结果

实验在三个企业平台上开展，涵盖 ServiceNow（330 任务，93 个 MCP 工具）、GitLab（192 任务，107 个工具）和 ERPNext（207 任务，7 个工具），使用 Claude Sonnet 4.6、Claude Opus 4.6、GPT-5.4 Thinking、Gemini 3.1 Pro 四款模型进行测试。

### 主要结果（成功率 % vs 平均成本/任务）

| 模型 | MCP 成功率 | Web 成功率 | **终端成功率** | MCP 成本 | **终端成本** |
|------|-----------|-----------|-------------|---------|------------|
| Claude Sonnet 4.6 | 32.9% | 72.2% | **72.7%** | $0.51 | **$0.56** |
| Claude Opus 4.6 | 39.2% | 79.9% | **78.7%** | $0.58 | **$1.22** |
| GPT-5.4 Thinking | 38.8% | 73.4% | **73.5%** | $0.23 | **$0.19** |
| Gemini 3.1 Pro | 37.1% | 68.9% | **77.5%** | $0.11 | **$0.09** |

**关键发现：** 终端智能体在 12 个平台-模型组合中的 7 个超越 Web 智能体，且成本通常低 **5 倍**。

![工具调用分布](https://arxiv.org/html/2604.00073/x2.png)
*图4：成功任务与失败任务的工具调用类型分布对比*

### 技能（持久记忆）效果

| 平台 | 无技能成功率 | 有技能成功率 | 成本变化 |
|------|------------|------------|---------|
| ERPNext | 基准 | **+5.8pp** | −16.8% |
| ServiceNow | 基准 | **+3.6pp** | **−43.7%**（$0.78→$0.44） |
| GitLab | 基准 | +1.6pp | 微降 |

技能主要存储字段映射、有效值、API 特殊规则等程序性知识，显著提升复杂任务成功率。

### 混合智能体（Opus 4.6）

| 配置 | ServiceNow 成功率 | 成本/任务 |
|------|-----------------|---------|
| Web | 77.6% | $4.21 |
| 终端 | 79.1% | $1.94 |
| **混合** | **83.0%** | $2.57 |

对于少量需要 GUI 操作的任务（如图表读取、模拟登录），混合模式额外提升约 4pp。

### ERPNext 异常现象

ERPNext 仅有 7 个通用 CRUD 工具的 MCP 服务器，表现反而优于 ServiceNow 的 93 个专用工具——**"少而精的通用工具比大量窄化工具更有效"**，对企业 API 设计哲学有重要启示。

## 总结

本文有力证明了：终端智能体结合直接 API 调用，在企业自动化任务中既有效又高效。核心贡献包括：（1）系统比较三种 Agent 范式；（2）提出 StarShell 极简 Agent 实现；（3）揭示了工具设计哲学的深刻洞见——平台应优先暴露稳定的可编程接口，而非构建大量抽象工具层。

局限性：当前研究聚焦于单平台任务，多平台协作和长程规划场景仍需进一步探索。此外，对于少数需要 GUI 交互（如图表阅读、视觉验证码）的任务，纯终端方案仍存在盲区，混合架构是更完善的解决方案。
