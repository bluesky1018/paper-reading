## 一句话总结

Miles v0.1 是一套面向 frontier 级大模型的全栈、生产就绪后训练系统，围绕"组件可验证、代码干净、高度可定制"的核心原则设计，以 744B 参数 GLM-5.2 在 64 块 NVIDIA GB300 GPU 上的异步 agentic RL 训练为案例，验证了系统的生产可用性。

## 背景与问题

Frontier 级大模型的后训练（Post-Training）已不再是简单的"生成-更新"循环：
- **Rollout 规模爆炸**：现代 RL 训练需要跨多轮交互、工具调用、在外部环境中行动的长程 episode
- **模型规模极大**：训练对象常常是万亿参数量级的 MoE 架构
- **系统一致性难题**：Rollout 引擎与 Trainer 之间的数值差异可能静默地使优化目标失效
- **效率与可靠性矛盾**：延迟敏感的 Rollout 与吞吐量导向的训练争抢 GPU 资源

现有系统要么缺乏透明度（Monolithic 黑箱），要么不具备真正的生产级可靠性。Miles v0.1 的目标是：**以第一性原理重新设计每个环节，将准确性、效率、可靠性和可扩展性作为头等目标**。

## 核心方法

### 系统架构：三阶段循环

Miles 的 RL 训练循环分三阶段：

```
Rollout（轨迹生成）→ Training（策略更新）→ Weight Update（权重同步）
```

每个阶段都围绕"可验证、干净、可定制"原则独立设计。

### Rollout 引擎

**1. 基于 SGLang 的快速 Agentic Rollout**
- 基于 SGLang 构建的生成引擎，支持 FP8 量化推理和 FP8 KV 缓存
- 支持多 Token 预测（MTP）加速生成
- 通过请求路由保持 KV 缓存局部性（cache locality）

**2. 完全异步 RL（Fully Asynchronous RL）**
- 生成与训练完全解耦，消除 GPU 空闲
- Rollout 节点和训练节点独立运行，不相互等待

**3. Token-In-Token-Out（TITO）**

TITO 是解决 train-rollout mismatch 的关键机制。多轮 agentic RL 中，若 token 序列在消息解析、工具执行、聊天模板渲染等环节发生任何变化，Trainer 看到的就不是 policy 真正采样的轨迹，导致重要性比率偏离1，梯度失效。

TITO Session Server 的设计：
- 服务端而非客户端控制 tokenization
- 每轮结束后 checkpoint 完整的 prompt+output token IDs、log-probabilities 和路由的专家信息
- 保证训练序列是 Rollout 的精确还原
- TITO 是三个关键机制的前提：**Rollout Routing Replay（R3）**、**On-Policy Distillation（OPD）**、**True-On-Policy Alignment**

**4. Rollout Routing Replay（R3）**

MoE 模型在 rollout 和 training 时因 expert 选择差异会产生不同的 log-prob。R3 机制确保训练时重放 rollout 时的确切 expert 路由，消除这一差异。

### 训练组件

**低精度训练配置**：

| 精度格式 | 块大小 | 成熟度 | 测试模型 |
|---------|--------|--------|---------|
| BF16 | - | 基线 | 全部 |
| FP8 blockwise | 128×128 | 正式可用 | Qwen3-4B, DeepSeek-V4等 |
| MXFP8 | 1×32 | Beta | Qwen3-30B-A3B等 |
| NVFP4 (E2M1) | 1×16 | Beta | Qwen3-30B-A3B |

**双训练后端**：
- NVIDIA Megatron-LM（流水线+张量+专家并行）
- PyTorch FSDP（灵活分片）

**内存优化**：支持 Optimizer State 到节点本地磁盘的流式 offload，使 744B MoE 在 32 张 GPU 上可行。

### 权重同步

三种权重传输策略，适应不同部署拓扑：

| 传输方式 | 路径 | 适用场景 |
|---------|------|---------|
| Broadcast（默认） | NCCL 广播到所有 rollout rank | 共享 NCCL fabric |
| Peer-to-Peer | RDMA 直写 rollout rank 内存 | rank 间直接可达 |
| Disk-Delta | 仅发布变更字节到共享存储 | 无共享 fabric 或传输瓶颈 |

### 其他后训练配方

Miles 还支持：
- **LoRA RL**：参数高效的 RL 微调
- **On-Policy Distillation（OPD）**：在线策略蒸馏，依赖 TITO 保证 token 对齐
- **True-On-Policy Alignment**：彻底消除 rollout 与训练时策略的数值差异
- **Miles-Diffusion**：将同一架构扩展到扩散模型后训练

## 案例研究：64 NVIDIA GB300 GPU 上的 GLM-5.2 Agentic RL

**配置**：

| 设置项 | 值 |
|--------|---|
| 模型 | GLM-5.2，744B 总参数 / 40B 激活参数 |
| 任务 | Terminal-bench-2 终端编程任务 |
| 环境 | OpenEnv + Daytona 沙箱（每 episode 一个） |
| 硬件 | 64 NVIDIA GB300 GPU（32 Rollout / 32 Training） |
| 训练并行度 | TP 2 / PP 4 / CP 4 / EP 8 |
| 推理配置 | 8个 DP-attention 引擎（DP 4），MTP 开启 |
| 精度 | Training: BF16；Rollout: FP8 权重 + FP8 KV Cache |
| 最大序列长度 | 65,536 tokens/session |
| 训练 Batch | 64 轨迹（8 任务 × 8 次尝试） |
| 调度方式 | 完全异步 |

**关键性能指标**：前 30 个测量步的中位步时间为 **263 秒**，在 744B 参数量、多 GPU 集群的完全异步 agentic RL 训练中展现出可实用的吞吐量。

**模型与硬件覆盖**（Day-0 支持）：
- 模型：Qwen3 系列、DeepSeek 系列、GLM 系列等主流 frontier 模型
- 硬件：NVIDIA GB300 / H100 / H200 等多种 GPU

## 总结

Miles v0.1 提供了一套"透明的工程学"：不掩盖权衡，不夸大某些路径的覆盖范围，而是明确指出什么已经过广泛测试、什么还处于 Beta 阶段。

**主要贡献**：
- 全栈 RL 后训练系统：从 Rollout 到 Training 到 Weight Update 的完整链路
- TITO 精确 token 保真机制，消除 train-rollout mismatch
- R3 expert 路由回放，解决 MoE 模型的额外数值差异
- 完全异步 RL 框架，支持 744B 级别模型高效训练
- 开放源码，面向研究者和企业均可使用

**局限性**：部分精度格式（MXFP8, NVFP4）仍处于 Beta 阶段；部分权重传输路径仅覆盖特定模型家族；案例研究仅来自单一配置，普适性需进一步验证。
