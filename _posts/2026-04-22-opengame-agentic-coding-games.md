## 一句话总结

OpenGame 是首个面向端到端 Web 游戏自动生成的开源智能体框架，通过进化模板库与活跃修复协议，配合专训的 GameCoder-27B 模型，在游戏生成基准上创下新的最优成绩。

## 背景与问题

游戏开发是软件工程中最复杂的任务之一，需要同时管理游戏引擎、实时循环与跨文件状态。虽然大语言模型（LLM）在代码生成领域已取得显著进步，但在生成完整可玩游戏方面仍面临三大挑战：

1. **跨文件不一致性**：游戏涉及多个模块（物理、渲染、音效、逻辑），LLM 容易在不同文件间产生接口不匹配、状态冲突等问题。
2. **框架专业知识缺乏**：游戏开发框架（如 Phaser.js）有大量特有 API 和模式，通用 LLM 对此掌握有限。
3. **调试循环难以自动化**：游戏 Bug 往往需要多轮执行-观察-修复才能解决，现有智能体缺乏系统化的修复记忆。

现有工作如 GPT-5.1、Claude Sonnet 4.6 等虽能生成部分游戏代码，但构建健壮度（Build Health）普遍不足，游戏完整性难以保证。

## 核心方法

### GameCoder-27B：游戏专用代码模型

基于 Qwen3.5-27B 骨干，经三阶段训练打造：

1. **持续预训练（CPT）**：摄入大量开源 Phaser/JS/TS 仓库、文档和教程
2. **监督微调（SFT）**：使用 gpt-codex5.1 生成的提示与 minimax2.5 解答构建合成 QA 对
3. **执行强化学习（RL）**：基于单文件组件的单元测试执行反馈，实现执行基础的强化学习

### OpenGame 智能体工作流（6阶段）

1. **物理优先分类**：根据规则（如"有重力且无地面 → 平台跳跃"）自动判断游戏类型
2. **脚手架搭建**：通过Shell命令复制原型模块
3. **游戏设计文档（GDD）生成**：结合原型特有的 API 约束
4. **多模态资产合成**：图像、瓦片地图、ABC音符格式的音效
5. **代码实现**：采用"三层阅读法 + 模板方法（Hook覆盖）"
6. **验证循环**：静态审查 → `npm run build` → `npm run test` → 修复

### 游戏技能库（Game Skill）

**模板技能（Template Skill）**：从元模板 ℳ₀ 出发，进化出5个游戏家族：
- 重力侧视图（Gravity Side-View）
- 俯视连续（Top-Down Continuous）
- 离散网格（Discrete Grid）
- 路径波次（Path-and-Wave）
- UI驱动（UI-Driven）

**调试技能（Debug Skill）**：维护活跃协议 𝒫，包含（错误特征、根因、已验证修复方案）三元组；支持资产键不匹配、配置字段缺失、场景切换无效等预执行检查。

## 实验结果

### OpenGame-Bench 主要结果（150个任务，5种游戏类型）

评分维度：构建健壮度（BH）、视觉可用性（VU）、意图对齐（IA），满分100

| 系统 | BH↑ | VU↑ | IA↑ |
|------|-----|-----|-----|
| Qwen-3.5-Max（直接生成） | 51.8 | 35.5 | 38.9 |
| MiniMax m2.5 | 39.7 | 39.3 | 31.8 |
| Claude Sonnet 4.6 | 58.5 | 50.8 | 50.3 |
| GPT-5.1 | 57.4 | 52.9 | 49.4 |
| Cursor + Claude Sonnet 4.6 | 66.8 | 61.4 | 58.9 |
| **OpenGame + GameCoder-27B** | **63.9** | **57.0** | **54.1** |
| **OpenGame + Claude Sonnet 4.6** | **72.4** | **67.2** | **65.1** |

### GameCoder-27B 训练消融

| 训练阶段 | BH | VU | IA |
|---------|-----|-----|-----|
| Base Qwen-3.5-27B | 62.8 | 53.8 | 49.8 |
| + CPT | 63.2 | 54.7 | 50.6 |
| + CPT + SFT | 63.5 | 55.7 | 52.5 |
| + CPT + SFT + RL | **63.9** | **57.0** | **54.1** |

### 游戏技能库消融

| 模板库 | 调试策略 | BH | VU | IA |
|-------|---------|-----|-----|-----|
| 静态 ℳ₀ | 静态检查表 | 60.5 | 54.8 | 51.2 |
| 5-family ℒ | 静态检查表 | 66.3 | 60.7 | 57.9 |
| **5-family ℒ** | **完整活跃协议** | **72.4** | **67.2** | **65.1** |

### 各类型游戏 IA 得分（OpenGame）

| 类型 | IA |
|------|-----|
| 平台跳跃 | **76.8** |
| 俯视射击 | 71.4 |
| 经典街机 | 66.5 |
| 策略 | 58.2 |
| 解谜/UI | 52.6 |

## 总结

OpenGame 的核心创新在于将"记忆"引入游戏开发智能体——无论是通过不断进化的模板库积累结构性知识，还是通过活跃修复协议积累调试经验。这种经验积累机制使智能体在面对同类问题时能持续改进，而非每次从零开始。

GameCoder-27B 的执行基础强化学习（execution-grounded RL）也为代码 LLM 的专业化训练提供了新思路：让模型在真实执行反馈中学习，而非依赖人工标注。

局限性方面，OpenGame 目前主要针对 Web 游戏（Phaser.js），对其他游戏引擎（Unity、Unreal）的迁移性有待验证；解谜/UI 类游戏的意图对齐得分（52.6）也显著低于其他类型，说明此类高自由度设计仍是挑战。
