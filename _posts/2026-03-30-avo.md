## 一句话总结

AVO 将大语言模型从"候选方案生成器"升级为"自主变异算子"，赋予智能体完整的工具链（查阅文档、执行代码、分析性能分析结果、自主调试），在 NVIDIA B200 GPU 上连续进化 7 天，最终发现的 MHA 注意力内核超越 cuDNN 最高 3.5%、超越 FlashAttention-4 最高 10.5%。

---

## 背景与问题

### 进化搜索与变异算子

在标准进化搜索中，维护一个种群 $\mathcal{P} = \{(x_i, f(x_i))\}$，每次迭代通过变异算子产生新候选：

$$\mathcal{P}_{t+1} = \text{Update}(\mathcal{P}_t,\ (x_{t+1}, f(x_{t+1}))),\quad x_{t+1} = \text{Vary}(\mathcal{P}_t)$$

**以往 LLM 增强方法（FunSearch、AlphaEvolve、ReEvo 等）** 将变异拆分为两步：

$$\text{Vary}(\mathcal{P}_t) = \text{Generate}(\text{Sample}(\mathcal{P}_t))$$

- **Sample**：固定算法（MAP-Elites、玻尔兹曼选择、PUCT 规则等）从历史种群中挑选亲本
- **Generate**：LLM 仅被提示生成一个候选方案，**无法主动查阅参考资料、测试改动、解析反馈或修正策略**

这一"单轮约束"对于需要迭代调试的高难度优化任务（如超越专家精心调优的 GPU 内核）存在根本性局限。

### 注意力内核的挑战

注意力计算 $O = \text{softmax}(QK^\top / \sqrt{d})V$ 的朴素实现受限于 $N \times N$ 分数矩阵的内存带宽。FlashAttention 通过分块处理与在线 softmax 统计将瓶颈从内存带宽转移到计算。在 Blackwell（B200）架构上，FA4 采用了精心设计的 Warp 专化方案：
- **MMA Warp**：执行 QK 与 PV 矩阵乘法
- **Softmax Warp**：在线 softmax 计算
- **Correction Warp**：当 running maximum 变化时重缩放输出累加器
- **Load/Epilogue Warp**：通过 TMA 负责数据搬运

在如此复杂的硬件专化实现上进一步提升性能，需要同时推理同步机制、内存排序、流水线调度、寄存器分配等多个硬件子系统——这正是 AVO 的目标场景。

## 核心方法

### AVO 的形式化定义

AVO 将变异算子替换为一个自主智能体：

$$\text{Vary}(\mathcal{P}_t) = \text{Agent}(\mathcal{P}_t,\ \mathcal{K},\ f)$$

其中：
- $\mathcal{P}_t$：完整的解演化谱系 $\{(x_1, f(x_1)), \ldots, (x_t, f(x_t))\}$
- $\mathcal{K}$：领域知识库（CUDA 指南、PTX ISA 文档、Blackwell 规格书、FA4 源码）
- $f$：评分函数（正确性 + 吞吐量 TFLOPS）

与以往方法的关键区别在于：**LLM 不再是流水线中的一个步骤，而是整个变异过程的驾驶者**，自主决定查阅什么、修改什么、何时提交。

![AVO 总体框架示意](https://arxiv.org/html/2603.24517/x1.png)

### 一次变异步骤的内部流程

单个变异步骤 $x_t \to x_{t+1}$ 是一个自主智能体循环：

1. **回顾谱系**：检查多个历史实现，比较性能分析特征
2. **查阅文档**：从知识库 $\mathcal{K}$ 获取硬件约束信息
3. **实现优化**：编写候选内核代码
4. **调用评分函数**：测试正确性与吞吐量
5. **诊断-修订循环**：若失败，分析原因，修正方案，重新测试
6. **提交**：仅当候选方案通过正确性检验且性能达标时才提交为 $x_{t+1}$

早期步骤聚焦结构性改动，后期步骤转向由性能分析反馈和谱系规律引导的微架构调优。

### 持续进化机制

AVO 以持续循环方式运行，每次提交的版本均以 git commit 形式保存（含性能分数）。针对两种失效模式：
- **停滞**：智能体耗尽当前探索方向
- **无效循环**：反复修改但无法提升分数

设计了**自监督机制**：检测上述情形后，智能体自主回顾整体轨迹，并转向新的候选优化方向。

## 实验结果

### 实验设置

- **硬件**：NVIDIA B200 GPU（Blackwell 架构）
- **软件**：CUDA 13.1，PyTorch 2.10.0
- **基线**：cuDNN v9.19.1、FlashAttention-4（commit 71bf77c）
- **基准配置**：head_dim=128，BF16 精度，前向预填充吞吐量
- **序列长度**：4096 / 8192 / 16384 / 32768，总 token 数固定为 32768

### 多头注意力（MHA）结果

![MHA 性能对比](https://arxiv.org/html/2603.24517/x2.png)

**因果注意力**：AVO 在所有配置下均优于两条基线
- vs. cuDNN：+0.4% 至 +3.5%
- vs. FA4：+5.0% 至 +10.5%

**非因果注意力**：在较长序列下取得稳定提升
- vs. cuDNN：序列长度 ≥16384 时 +1.8% 至 +2.4%
- 较短序列在测量噪声范围内

### 分组查询注意力（GQA）结果

GQA 内核通过提示 AVO 对已进化的 MHA 内核进行适配，**全程约 30 分钟，无需人工干预**。

![GQA 性能对比](https://arxiv.org/html/2603.24517/x3.png)

**因果 GQA**（32 查询头，4 KV 头，组大小 8，对应 Qwen3-30B-A3B；及 32 查询头，8 KV 头，组大小 4，对应 Qwen3-8B）：
- vs. cuDNN：最高 +7.0%
- vs. FA4：最高 +9.3%

**非因果 GQA**：
- vs. cuDNN：最高 +6.0%
- vs. FA4：最高 +4.5%

这证明智能体在 MHA 进化中发现的优化并不局限于训练时使用的 MHA 配置。

### 进化轨迹分析

![进化轨迹](https://arxiv.org/html/2603.24517/x4.png)

7 天进化共产生 **40 个提交版本**，代表超过 **500 个候选优化方向**中的成功结果。吞吐量呈**阶梯式跃升**而非平滑增长，五次最大收益对应关键架构转折点：

| 版本 | 优化内容 |
|------|---------|
| v8  | QK-PV 交错执行 + 位掩码因果遮蔽 |
| v13 | 重构单遍 softmax 计算 |
| v20 | 无分支累加器重缩放 + 轻量内存屏障 |
| v30 | Correction/MMA 流水线重叠 |
| v33 | 跨 Warp 组寄存器重新分配 |

前 20 个版本贡献最大绝对收益；版本 21–40 通过指令级调度和精细资源分配实现复合式小幅提升。

## 智能体发现的关键优化深度解析

### 优化 1：无分支累加器重缩放（v19 → v20，+8.1% 非因果）

**问题（v19）**：在线 softmax 要求当 running row-maximum 变化时重缩放累加器 $O$。v19 使用条件分支检查是否有 warp 线程需要重缩放，在每个 K-block 循环迭代中引入 warp 同步开销，并阻止使用轻量内存屏障。

**AVO 的解法（v20）**：用**无分支投机路径**替代条件分支——始终计算重缩放因子，在不需要时通过 predicated select 替换为 1.0。"不必要的乘以 1 的代价，远小于它所替换的同步开销。" 消除分支还同时消除了 warp 分歧，使得可以将阻塞型内存屏障替换为更轻量的非阻塞排序屏障。

**结果**：+8.1%（非因果）/ +1.6%（因果）。非对称性来自：无分支路径仅适用于完全未遮蔽的 K-block 迭代，因果注意力对遮蔽块保留了分支逻辑。

### 优化 2：Correction/MMA 流水线重叠（v29 → v30，+1.1% 非因果）

**问题（v29）**：双 Q-stage 设计并发处理两个 Q-tile，每个需要 PV GEMM 后接 correction warp 归一化。v29 在 MMA 到 correction 的边界处串行执行——correction warp 等待两个 PV GEMM 都完成后才归一化任何一个输出。

**AVO 的解法（v30）**：重构流水线，使 correction warp 在第一阶段的 PV GEMM 完成后立即开始归一化其输出，与第二阶段的 PV GEMM 重叠执行。

**结果**：+1.1%（非因果）/ +0.4%（因果）。

### 优化 3：跨 Warp 组寄存器重新分配（v32 → v33，+2.1% 非因果）

**问题（v32）**：Blackwell 每 SM 有 2048 个 warp 寄存器。v32 沿用 FA4 的分配方案：8 个 softmax warp 分配 192 个寄存器，4 个 correction warp 分配 80 个，其余 4 个 warp 分配 48 个。性能分析显示 correction warp 组溢出到更慢的本地内存，而 softmax 组有余量。

**AVO 的解法（v33）**：从 softmax 组向其他两组各重分配 8 个寄存器 → 184/88/56 分配。可行原因：AVO 的 softmax 以"小片段+压缩算术"处理分数值，峰值寄存器使用率较低。经流水线重叠优化（v30）后，correction warp 在关键路径上与第二个 PV GEMM 并发运行，寄存器增益尤为显著。

**结果**：+2.1%（非因果）/ ~0%（因果）。

### 综合讨论

每项优化都需要**同时推理多个硬件子系统**（同步与内存排序、流水线调度、寄存器分配），而非孤立地调节单一参数。这种深度，通过与文档和性能分析反馈的迭代交互才得以实现，表明智能体变异算子可作为专家级内核优化的有效机制。

---

## 总结

AVO 的核心贡献在于**重新定位 LLM 在进化搜索中的角色**：从受限于固定框架的"候选生成器"，提升为拥有完整工具链的"自主变异算子"。

| 维度 | 以往方法 | AVO |
|------|---------|-----|
| LLM 角色 | 固定流水线中的 Generate 步骤 | 整个变异过程的自主驾驶者 |
| 信息访问 | 仅历史候选方案 | 历史谱系 + 知识库 + 评分函数 |
| 交互方式 | 单轮生成 | 多轮调试-验证循环 |
| 停滞处理 | 依赖外部调度 | 自监督机制自动转向 |

**关键结论**：
- 7 天、500+ 候选方向探索、40 个提交版本，MHA 内核最高超越 cuDNN 3.5%、超越 FA4 10.5%
- GQA 适配仅需 30 分钟自主工作，最高超越 cuDNN 7.0%、FA4 9.3%
- AVO 在变异算子层面操作，不绑定特定领域，为性能关键型软件系统的自主优化指出了更广泛的路径

**局限性与未来方向**：本文研究单一谱系设置，AVO 与基于档案的或岛屿进化等种群结构的结合仍是开放问题；此外，当前实验聚焦于注意力内核，在其他领域（编译器优化、数值算法等）的泛化能力有待验证。
