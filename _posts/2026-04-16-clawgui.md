> 📄 **论文**：ClawGUI: A Unified Framework for Training, Evaluating, and Deploying GUI Agents
> 🔗 **arXiv**：[2604.11784](https://arxiv.org/abs/2604.11784)
> 🏢 **机构**：浙江大学（Zhejiang University）

## 一句话总结

ClawGUI 是首个统一 GUI 智能体训练（RL 基础设施）、评测（跨论文可复现基准）与部署（多平台真实设备）全流程的开源框架，通过新提出的 GiGPO 算法实现了相对 GRPO +17.9% 的成功率提升，并在 6 个基准、11+ 模型上达到 95.8% 的评测复现率。

## 背景与问题

随着多模态大语言模型（MLLM）的快速发展，GUI 智能体（GUI Agent）——即能够理解屏幕截图并操作图形界面以完成用户任务的 AI 系统——正成为 AI 应用落地的重要方向。然而，该领域的研究生态存在严重的碎片化问题，使得研究成果难以在现实中真正转化为可用产品。

论文作者识别出阻碍 GUI 智能体发展的三大核心问题：

1. **训练生态封闭**：主流 GUI 智能体的强化学习（RL）训练基础设施大多为商业机构内部使用，开源社区缺乏可靠的并行设备管理、奖励设计与 RL 算法支持，研究者难以复现或改进 SOTA 方法。

2. **评测标准严重失对齐**：不同论文在评测同一模型时，往往因为所用提示词（prompt）、截图分辨率、坐标归一化方式、输出格式解析逻辑等细节差异，导致结果无法直接比较。这种"评测噪声"掩盖了方法本身的真实优劣。

3. **研究到部署的链条断裂**：学术论文中展示的 GUI 智能体往往只能在受控基准环境下运行，缺乏将其接入真实用户场景（如通过即时通讯软件下达指令、在真实手机上执行操作）的完整工程链路。

为了系统性地解决上述问题，浙江大学团队提出了 ClawGUI，一个覆盖训练、评测、部署三个环节的统一开源框架。

![ClawGUI 整体架构](https://arxiv.org/html/2604.11784/x1.png)
*图 1：ClawGUI 整体架构——集成了 RL 训练、跨 6 个基准/11+ 模型的可复现评测，以及通过 12+ 聊天平台驱动的真实设备部署*

## 核心方法

ClawGUI 由三个相互独立又协同工作的子系统组成：ClawGUI-RL（训练）、ClawGUI-Eval（评测）和 ClawGUI-Agent（部署）。

### ClawGUI-RL：首个开源 GUI 强化学习基础设施

ClawGUI-RL 的核心挑战是如何在大规模并行设备环境中稳定地进行强化学习训练。

**环境管理器（Environment Manager）** 采用基于 Docker 的 Android 模拟器集群，支持同时运行 64 个并行虚拟环境。系统内置健康检查机制、崩溃自动恢复和备用服务器轮换策略，确保长时间训练过程中的稳定性。

**奖励设计（Reward Design）** 是 GUI RL 训练的关键。ClawGUI-RL 采用二元结果奖励与密集步骤级奖励相结合的混合奖励：

```
R = R_outcome + R_step
```

其中 R_outcome 是任务完成的二元奖励，R_step 是由 Process Reward Model（PRM）生成的每步密集奖励，PRM 使用 Qwen3.5-72B 作为评判模型。

**支持的 RL 算法**：GRPO、GiGPO、PPO、Reinforce++、GSPO，底层基于 verl 和 verl-agent 框架构建。

![ClawGUI-RL 架构](https://arxiv.org/html/2604.11784/x2.png)
*图 2：ClawGUI-RL——具备多任务并行 rollout、健康检查和 MLLM-as-judge 奖励的环境管理器*

#### GiGPO：组内组策略优化

论文的重要技术贡献是提出了 **GiGPO（Group-in-Group Policy Optimization）**，解决了 GRPO 在长时序任务上奖励信号稀疏的问题。

**GRPO 的局限性**：GRPO 对一个轨迹（episode）中的每一步分配相同的情节级别优势（episode-level advantage），这对于需要多步操作的 GUI 任务来说过于粗粒度——早期关键步骤和后期收尾步骤获得了相同的信用，无法进行精细的步骤级别信用分配。

**GiGPO 的核心机制——锚状态分组（Anchor-State Grouping）**：

GiGPO 在情节级别分组的基础上，引入了第二层分组。具体地，对于一个任务，GiGPO 收集多条轨迹，识别其中遇到相同中间状态（anchor state）的步骤，将这些步骤聚合为一个"子组"。在子组内部，通过折扣回报归一化（discounted return normalization）估计每个步骤的微优势（micro-advantage），从而实现步骤级别的精细信用分配。

这种层级式优势估计使模型能够识别"哪一步是真正关键的"，而不是对整条轨迹的所有步骤一视同仁。

### ClawGUI-Eval：标准化三阶段评测流水线

ClawGUI-Eval 采用 **Infer → Judge → Metric** 三阶段流水线，将所有可能引入差异的评测细节（提示词模板、坐标处理、输出解析）标准化并固化。

**支持的 6 个基准测试**：
- ScreenSpot-Pro
- ScreenSpot-V2
- UI-Vision
- MMBench-GUI
- OSWorld-G
- AndroidControl

**支持的 11+ 模型**：Qwen3-VL、Qwen2.5-VL、UI-TARS、MAI-UI、GUI-G2、UI-Venus、StepGUI、Gemini、Seed 1.8 等

**Zoom 范式**：针对闭源模型（不支持坐标输出）的特殊评测策略，采用两阶段裁剪-定位（crop-then-ground）方法，先让模型框选目标区域，再在裁剪后的局部图像上进行精确定位，绕过闭源模型无法直接输出像素坐标的限制。

![ClawGUI-Eval 架构](https://arxiv.org/html/2604.11784/x3.png)
*图 3：ClawGUI-Eval——标准化的 Infer→Judge→Metric 流水线，在 48 个评测单元中实现 95.8% 的复现率*

### ClawGUI-Agent：多平台真实设备部署

ClawGUI-Agent 解决了从研究模型到真实用户交互的"最后一公里"问题。

**设备支持**：Android、HarmonyOS（鸿蒙）、iOS

**12+ 聊天平台接入**：飞书、钉钉、Telegram、Discord、Slack、QQ 等，用户可直接通过日常使用的即时通讯软件向 GUI 智能体下达自然语言指令。

**混合 CLI + GUI 控制**：在支持命令行的场景优先使用 CLI 操作（效率更高、更稳定），在 CLI 不可用时自动降级到 GUI 截图-点击操作，兼顾效率与通用性。

**个性化记忆系统**：基于向量嵌入存储用户偏好和历史事实，采用 top-k 检索和重复合并机制，使智能体能够跨会话记住用户习惯（如"用户偏好深色主题"、"默认搜索引擎为 Bing"）。

**远程与本地双模式**：支持远程控制真实设备（适合服务器端部署）和本地直接控制（适合个人使用场景）。

## 实验结果

### MobileWorld GUI-Only 基准（117 个任务）成功率对比

MobileWorld 是一个端到端 GUI 任务完成的交互式基准测试，要求模型在真实 Android 环境中完成完整的多步任务。

| 模型 | 成功率 (SR%) |
|------|------------|
| Gemini-3-Pro + UI-Ins-7B | **55.6** |
| GPT-5 + UI-Ins-7B | 54.0 |
| Doubao-1.5-UI-TARS | 26.3 |
| MAI-UI-8B | 19.7 |
| **ClawGUI-2B（GiGPO）** | **17.1** |
| UI-Venus-72B | 16.4 |
| MAI-UI-2B（基线） | 11.1 |
| Qwen3-VL-32B | 11.9 |
| GUI-Owl-7B | 7.7 |

ClawGUI-2B 基于 MAI-UI-2B 训练，仅有 2B 参数，却超越了 UI-Venus-72B（72B 参数）和 Qwen3-VL-32B（32B 参数），充分说明高质量 RL 训练的价值。

### GiGPO vs GRPO 奖励机制消融实验

| 方法 | 奖励类型 | 成功率 (SR%) |
|------|---------|------------|
| GRPO | 二元情节级别奖励 | 14.5 |
| **GiGPO** | **密集步骤级别奖励** | **17.1** |

GiGPO 相比 GRPO 实现了 **+2.6% 绝对提升，+17.9% 相对提升**，验证了步骤级密集奖励监督对长时序 GUI 任务的重要性。

### 评测复现率验证

ClawGUI-Eval 在 48 个"模型×基准"评测单元上与官方发布结果对比：

| 模型 | 基准 | 官方结果 | 复现结果 | 状态 |
|------|------|---------|---------|------|
| GUI-Owl 1.5-8B | ScreenSpot-Pro | 71.10% | 70.08% | 复现成功 |
| UI-Venus 1.5-8B | ScreenSpot-V2 | 95.90% | 95.83% | 复现成功 |
| Gemini 3.0 Pro | ScreenSpot-Pro | 72.70% | 75.08% | 复现成功 |
| （2 个单元） | — | — | — | 失败（原论文配置未公开） |

**总体复现率：95.8%（46/48）**。2 个失败案例均可追溯到原论文未公开评测配置细节，而非 ClawGUI-Eval 本身的问题，反向证明了评测标准化的必要性。

### 训练配置

- **基础模型**：MAI-UI-2B
- **硬件**：8× NVIDIA A6000（48GB）GPU
- **并行环境数**：64 个虚拟 Android 设备
- **GiGPO 超参数**：rollout 组大小 8，温度 0.7，学习率 1e-6，训练 3 个 epoch
- **PRM 评判模型**：Qwen3.5-72B

## 总结

ClawGUI 的核心贡献在于其**系统性**而非单一算法突破：它识别了 GUI 智能体研究到应用全链路上的三个关键断点，并为每个断点提供了具体的工程解决方案。

从技术角度看，GiGPO 是论文最具新颖性的算法贡献。通过锚状态分组实现的层级式优势估计，将 GRPO 的粗粒度情节级别信用分配细化到步骤级别，在 2B 参数量级模型上取得了超越 72B 模型的任务成功率，证明了训练方法本身的价值远大于单纯堆砌模型规模。

ClawGUI-Eval 的 95.8% 复现率是该领域难得的量化可信度指标。在 GUI 智能体评测长期被"评测噪声"困扰的背景下，这一数字为未来论文提供了可对标的基准。

**局限性与未来方向**：当前 GiGPO 的实验仅在 MobileWorld 一个基准上验证，且基础模型为 2B 规模；更大模型（如 7B、72B）上的 RL 训练成本和效果仍待探索。此外，PRM 依赖 Qwen3.5-72B 作为评判模型，对计算资源有较高要求，如何设计更轻量的步骤级奖励机制是值得研究的方向。随着 ClawGUI 开源生态的完善，GUI 智能体从实验室到真实用户的落地路径有望大幅缩短。
