> 📄 **论文**：Agentic Context Management: Solving Agent Memory and Cost by Treating Them as Lifecycle and Architecture Problems
> 🔗 **arXiv**：[2607.21503](https://arxiv.org/abs/2607.21503)
> 🏢 **机构**：Maximem AI

## 一句话总结

论文提出"Agentic Context Management（ACM）"框架，将Agent的记忆问题重新定义为一个跨越五个原语的完整生命周期管理问题，从根本上解决多轮对话中的Token成本爆炸和记忆缺失难题。

## 背景与问题

生产级 AI Agent 的失败很少是由于推理能力不足，更多是因为无法管理推理上下文中的内容——包括对话历史、大型提示词、大量工具定义和膨胀的工具输出。它们淹没在自己积累的历史记录中，同时为每轮增长的 Token 成本付费。

现有"记忆"框架将这一问题视为**存储与检索问题**，但这个定性本身就是局限所在。围绕"存储"构建的系统只优化写入和读取两个时刻，忽略了从记忆获取到记忆退役的完整生命周期。

**核心代价**：在朴素的"完整追加"模式下，第 $k$ 轮的输入 token 数约为 $k \cdot t$，累计 Token 成本为 $O(n^2)$（$n$ 为对话轮数），成本随对话长度**二次增长**。

## 核心方法

论文提出 **Agentic Context Management（ACM）**，定义为"在整个从上下文获取到上下文退役的完整生命周期中，决定 Agent 应该在上下文中持有什么、何时、持有多久以及成本多少"的学科，分解为**五个原语**：

![五个原语的上下文生命周期](https://arxiv.org/html/2607.21503v1/x1.png)
*图1：五个原语的上下文生命周期——架构→摄入→定域→预测→压缩与整合，形成持续循环*

### 五大原语

1. **架构（Architecting）**：在存储任何记忆之前，决定特定 Agent 的记忆形状——哪些信息类别重要、如何提取、存储在哪里、持久多久
2. **摄入（Ingesting）**：将原始信号（对话轮次、多模态文档、工具调用及响应）转化为结构化、可检索的记忆
3. **定域（Scoping）**：在摄入和检索时，决定所知内容中哪个部分与当前和未来相关，以及在什么范围内
4. **预测（Anticipating）**：预判接下来可能需要什么，提前预取和预处理
5. **压缩与整合（Compacting & Consolidation）**：在不失真的前提下压缩上下文以适应预算

### 参考实现：Maximem Synap

![系统架构](https://arxiv.org/html/2607.21503v1/x5.png)
*图5：参考架构：SDK → API（REST + streaming）→ 管理器/Pipeline → 多种存储，五个原语标注在对应组件上*

系统实现了：
- **按 Agent 定制的记忆架构**：非通用 Schema，而是根据 Agent 用途自动生成专属架构
- **带质量合约的压缩**：每次压缩都返回验证分数和压缩比，验证失败则自动重试
- **多租户隔离**：存储层（per-tenant 命名空间）和查询层（范围谓词）均强制执行隔离

关键经济数据：
- 有界上下文 vs 完整追加，在 100 轮对话时节约 **6倍** Token 成本，200 轮时节约 **13倍**
- 压缩检索 vs 关键词检索，在 MRR 上的提升（图4），同时引入的"向量税"延迟可接受

## 总结

ACM 框架通过重新定义问题的性质，从"记忆存储"升级为"上下文生命周期管理"，提供了一个更完整的解决方案。其五个原语的分解清晰且实用，参考实现 Maximem Synap 在公开基准上取得了强劲的结果。

局限性在于：五个原语的完整实现需要显著的工程投入；架构自动生成的质量依赖于对 Agent 用途的准确描述；压缩验证引入了额外的 Token 开销（但论文已论证这是值得的代价）。
