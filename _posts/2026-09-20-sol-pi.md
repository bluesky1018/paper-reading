> 📄 **论文**：SoL-Pi: Recursively Scaling Auto-Research Loops for Efficient Agent Harness
> 🔗 **arXiv**：[2609.20519](https://arxiv.org/abs/2609.20519)
> 🏢 **机构**：NVIDIA、NTU、MIT

## 一句话总结

SoL-Pi 通过 RSI（递归自我改进）启发的自动研究循环，在 Harness 层发现了四种 token 效率机制，使 GPT-5.6 驱动的智能体 token 消耗降低 49%、API 成本降低 33%，并在跨模型迁移中保持效果。

## 背景与问题

编码智能体的推理能力快速提升，但随之带来的 token 消耗和 API 成本也急剧增加。一次长上下文的 Agent 任务往往消耗数百万 token，在大规模应用中成本高昂。

现有优化思路主要集中在模型本身（量化、蒸馏），而 **Harness 层**（上下文管理、工具调用协议、观测存储策略）的优化潜力尚未被充分挖掘。SoL-Pi 的核心思路是：让 AI 自动研究并改进 AI 的 Harness，形成递归改进循环。

## 核心方法

### 自动研究框架

AI 优化器以迭代方式改进 Harness：

**两重准入门控**：
1. 能力指标（任务完成率等）必须维持在预设容忍范围内
2. 至少一项效率指标必须改善

**保留集隔离**：EdgeBench 保留集（40个任务）的结果**永远不会**反馈到搜索循环，保证最终评估的独立性。

### 宽到深搜索

- **外层**：在 6 个方向族（上下文、进度、工具、委托、提示/策略、改进/评估）中提出 152 个候选方向
- **内层**：独立的 Ralph 循环（提出→实现→审查→评估）开发每个假设
- 独立分析器检测轨迹中的重复动作、上下文增长、大观测值和稀疏诊断

### 搜索环境

535 个可执行环境：
- 495 个仓库派生任务（GitHub issue/PR 对；测试必须在 patch 前失败、patch 后通过）
- 40 个验证器驱动任务（Terminal-Bench-2 风格）

### 四个发现的机制

![四种机制执行路径](https://arxiv.org/html/2609.20519/x4.png)
*图：四种机制的执行路径——动作融合（3→2 API 调用）、上下文压缩触发、ObservationPack 归档、证据保留 Reducer 及其 fallback*

**1. 动作融合（Action Fusion）**

将文件修改 + 后续验证命令合并为一次 API 请求，将 API 调用从 3 次降为 2 次。开发经历了 27 次迭代：oracle 分析预测 11.5% token 节省，但纯提示触发不稳定，最终通过扩展工具 Schema 直接支持。

**2. 在线上下文压缩（Online Context Compact）**

在计划步骤边界评估是否需要压缩，用成本门控（比较预期节省 vs 缓存重写成本）决策。避免不必要的摘要带来的额外成本。

**3. ObservationPack**

对 >10 KiB 的输出进行归档：前 2 次请求返回完整内容，之后替换为"句柄 + 1 KB 摘录"。既保证首次访问的完整信息，又防止上下文因大输出膨胀。

**4. 证据保留 Reducer（Evidence-Preserving Reducer）**

对 ≥4 KiB 的构建/测试日志，用低成本模型提取关键证据；确定性验证器检查结果；失败时 fallback 到完整内容。使用 GPT-5.6 Luna 以高设置运行。

## 实验结果

### EdgeBench（51 个公开任务，GPT-5.6 Sol）

| Harness | 总 Token (B) | API 成本 ($) | 平均分数 | 成本/分 |
|---------|------------|------------|---------|--------|
| Codex | 3.0537 | 1,787 | 34.738 | 1.0086 |
| Pi | 2.1538 | 1,339 | 44.833 | 0.5855 |
| **SoL-Pi [效率版]** | **1.0990** | **894** | 42.003 | **0.4174** |
| SoL-Pi [性能版] | 2.0224 | 1,271 | **47.208** | 0.5280 |

- **SoL-Pi [效率版]**：token 减少 **49.0%**，成本减少 **33.2%**，保留 Pi 得分的 93.7%
- **SoL-Pi [性能版]**（仅 ObservationPack）：得分提升 **5.3%**，token 减少 6.1%

### 跨模型迁移（Opus 5，未重新搜索）

| Harness | 总 Token (B) | 成本 ($) | 平均分数 |
|---------|------------|--------|---------|
| Claude Code | 2.0045 | 2,535 | 43.689 |
| Pi | 2.3697 | 1,741 | 44.756 |
| SoL-Pi [效率版] | 1.3101 | 1,158 | 42.224 |
| SoL-Pi [性能版] | 2.1016 | 1,605 | **50.482** |

迁移到 Opus 5（搜索时未使用）：保留 94.3% 得分，token 减少 **44.7%**，成本减少 **33.5%**。

### Terminal-Bench 4 & IMO 2026

- Terminal-Bench 4：SoL-Pi 总成本降低 26.3%，每题成本降低 11.6%（解题数相同）
- IMO 2026（6 题 Lean 4 验证）：解题数相同（3/6），每题成本从 25.32 降至 **20.90**

### 高效 Agent 蜂群（2 小时内核优化）

| 配置 | 最佳周期数 | API 成本 ($) |
|------|---------|------------|
| 单 Codex | 1,333 | 39.20 |
| Pi 蜂群（20 workers） | 1,366 | 82.12 |
| **SoL-Pi 蜂群（20 workers）** | **1,127** | **60.11** |

SoL-Pi 蜂群：成本降低 26.8%，Pi 蜂群未达速度阈值，SoL-Pi 通过所有 8 个阈值。

## 总结

SoL-Pi 展示了 RSI 启发的 Harness 层自动优化的可行性：无需改动模型本身，仅通过改进调用协议和上下文管理策略，即可将成本降低约 1/3。四个机制跨模型族保持迁移效果，在蜂群场景中也显著降低集体成本。

未来方向包括：**预训练 Harness**（像预训练模型一样积累 Harness 优化知识）、**多后端训练**、以及**递归高效改进**（用更高效的 Harness 运行更便宜的搜索，再发现更高效的 Harness）。
