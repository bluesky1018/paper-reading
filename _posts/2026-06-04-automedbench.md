> 📄 **论文**：AutoMedBench: Towards Medical AutoResearch with Agentic AI Models
> 🔗 **arXiv**：[2606.01961](https://arxiv.org/abs/2606.01961)
> 🏢 **机构**：UC Santa Cruz & NVIDIA（Junqi Liu, Salena Song, Pengfei Guo, Daguang Xu 等）

## 一句话总结

AutoMedBench 是首个工作流感知的医疗 AI 自动研究评测基准，将 Agent 执行分解为五阶段（规划→配置→验证→推断→提交），覆盖 24 个任务，揭示当前 Agent 的核心瓶颈在于**验证和提交失败**（分别占错误代码的 37.7% 和 38.1%），而非领域知识不足。

## 背景与问题

大语言模型 Agent 正从被动问答向自主研究辅助转变。医疗 AI 是这一方向极具挑战性的测试床：一个典型任务需要 Agent 解读临床目标、处理异构影像、选择合适算法、解决依赖、验证中间输出、大规模运行推理，并按严格格式提交结果。

**现有医疗 Agent 基准的局限**：主要评估最终输出（如问答准确率），而无法揭示 Agent 在研究过程中哪个阶段失败。在长时序工作流中，单一终态得分会掩盖真实的失败原因——到底是任务理解、环境配置、中间验证还是提交格式出了问题？

## 核心方法

### 五阶段统一工作流

AutoMedBench 将每次 Agent 运行组织为统一的 **S1-S5 工作流**：

| 阶段 | 名称 | 内容 |
|------|------|------|
| S1 | **Plan（规划）** | 理解任务目标，选择方法和策略 |
| S2 | **Setup（配置）** | 安装依赖，加载模型，准备环境 |
| S3 | **Validate（验证）** | 运行试点案例，检查中间输出，修复错误 |
| S4 | **Inference（推断）** | 全量运行推理，生成预测结果 |
| S5 | **Submit（提交）** | 验证提交格式，提交评估产物 |

每次运行平均 **33 个 Agent 交互轮次**，需要跨多阶段维持上下文。

### 评测设计

**任务覆盖**：24 个任务，5 大医疗研究方向
- 分割（Segmentation）
- 图像增强（Image Enhancement）
- 视觉问答（VQA）
- 报告生成（Report Generation）
- 病变检测（Lesion Detection）

成像模态：CT、MRI、X-ray、病理切片、显微镜、牙科影像、医疗视频

**双难度层次**：
- **Lite**：提供方法、环境和技能脚手架
- **Standard**：Agent 自主选择方法和环境（仅提供规划指导）

**双重评分体系**：
1. **Agentic 得分**：基于 S1-S5 工作流完成度的过程级得分
2. **Task 得分**：基于私有参考的确定性最终结果评估

**错误代码诊断**：按五类原因模式标注运行失败原因：任务理解、数据/模型配置、验证与恢复、实现与执行、交付物提交。

### 基础设施

提供开源执行框架和沙盒：
- 容器化 Agent 运行环境（隔离工作空间）
- 私有评估参考（防止 Agent 访问 ground truth）
- 违规自动警告/终止机制

## 实验结果

对 6 个前沿 LLM Agent 进行评测（数千次运行记录）：

![总体排行榜](https://arxiv.org/html/2606.01961/x1.png)
*图1：6 个 Agent 的整体、Agentic 和 Task 得分排行榜。整体得分平均 Agentic 得分和 Task 得分。*

**关键发现：**

| 发现 | 详情 |
|------|------|
| 最弱阶段 | **Validate（验证）** 是平均最弱的工作流阶段 |
| 最强阶段 | **Setup（配置）** 是平均最强阶段 |
| 主要错误 | 验证失败 **37.7%**、提交错误 **38.1%** |
| 任务理解 | 任务理解错误极少，仅占 **0.9%** |
| 错误影响 | 触发 1 个错误代码的运行得分比零错误运行低 **48%** |

**具体失败模式**：模型加载失败、形状 bug、跳过验证、空输出、格式错误的提交文件。

这些发现表明：**当前医疗 AI 研究 Agent 的核心瓶颈不是领域知识，而是鲁棒的工程执行能力、中间验证和工作流错误恢复**。

## 总结

AutoMedBench 为医疗 AI 自动研究领域提供了首个工作流感知的评测框架。与现有专注于最终输出的基准不同，它通过阶段级评分和错误代码诊断，揭示了 Agent 研究工作流中隐藏的失败模式。

研究发现的核心洞察：当前 LLM Agent 擅长让流水线"可运行"（Setup 阶段强），但拙于验证流水线的可靠性（Validate 阶段弱）。这为未来 Agent 设计指明了重要改进方向：强化中间验证和错误恢复机制。

局限性：任务主要来自医疗影像领域，对基因组学、药物研发等其他医疗 AI 研究方向的覆盖有限；当前实验仅评估 6 个 Agent，更多模型的对比有待扩展。
