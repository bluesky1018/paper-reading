- **机构**: MIT, Shanghai Jiao Tong University, NVIDIA, MIT-IBM Watson AI Lab

- **arXiv**: [2306.00978](https://arxiv.org/abs/2306.00978)

## 一句话总结

提出 **AWQ (Activation-aware Weight Quantization)**——用一个反直觉的发现把 INT4 量化质量推到新高度:**决定哪些权重"重要"的不是权重自身的大小,而是对应的 activation 的大小**。具体做法:找出 activation 幅度大的那 **1% salient channels**,在量化时对这些列**乘一个放大因子** $s$ 再量化、解量化时除以 $s$——用 FP16 同样的公式,但这 1% 的权重获得了 effectively 更高的精度。结果:**INT4 的 PPL 损失减半**,且无 Hessian 计算、速度比 GPTQ 快 ~3×。AWQ 拿下 MLSys 2024 Best Paper,是现在 LLM INT4 量化的事实标准。

![AWQ 的核心发现:保留 1% 最重要的 weight channel 为 FP16,INT4 的 PPL 从 43 降到 13;但反过来"不保留"则无效。重要性由 activation 决定,不是 weight 自身。](/assets/img/awq/x1.png)
_Figure 1:1% salient weight 的保护带来决定性质量提升_

## 背景:GPTQ 之后,还有改进空间吗?

GPTQ(2022)证明 Hessian-based 误差补偿能让 W4 量化几乎无损。但它有两个缺点:

1. **慢**:量化 175B 要 4 小时(虽然比 OBQ 快 1000× 还是慢)
2. **复杂**:Hessian 计算 + Cholesky + lazy update,工程实现不简单

AWQ 的动机:**能不能用更简单的方法,达到更好的效果?** 答案是 Yes——关键是换一个视角看"哪个 weight 重要"。

---

## 核心发现:Weight 的重要性由 activation 决定

### Ablation:保留什么最有效?

![三种方案对比:(1) 按 weight 自身大小保留前 1%,提升微小;(2) 按 activation 大小保留对应列的 weight,PPL 提升 70%+;(3) 随机保留,也没用。结论:activation 决定 weight 的重要性。](/assets/img/awq/x2.png)
_Figure 2:Ablation——按 activation 选最有效_

作者做了一个关键实验:

- **方案 A**:Naive INT4 量化(RTN),PPL = 43.2
- **方案 B**:找出 weight 幅度最大的 1% channel,保留为 FP16,PPL = 42.8(**几乎不变**)
- **方案 C**:找出 **activation 幅度最大**的 1% channel 对应的 weight,保留为 FP16,**PPL = 13.0**
- **方案 D**:随机选 1%,PPL = 42.5

方案 C 的 PPL 从 43 跳到 13 — 这一 1% 的 channel 承载了 70%+ 的精度损失。

### 为什么 activation 决定重要性?

对于一层输出 $Y = XW$,某列 $w_j$ 的量化误差 $\Delta w_j$ 对 $Y$ 的影响是:

$$
\Delta Y_j = X_j \cdot \Delta w_j
$$

$X_j$(activation 第 $j$ 列的 magnitude)**决定了** $\Delta w_j$ 在输出中的"放大倍数"。

- 如果 $\|X_j\|$ 大 → 同样的 $\Delta w_j$ 会产生巨大 $\Delta Y_j$ → 这列 weight 必须精确量化
- 如果 $\|X_j\|$ 小 → $\Delta w_j$ 被"滤掉" → 这列 weight 可以宽松量化

这就是 AWQ 的理论基础——**weight 的"重要性"取决于它的 activation 上下文,不是它本身**。

## 核心机制:Per-Channel Scaling

### 保护 1% 为 FP16 不实用

直接让 1% channel 为 FP16、99% 为 INT4 会破坏矩阵乘法的规整性,kernel 实现麻烦,也失去 INT4 的 tensor core 加速。

AWQ 的聪明之处:**用一个 scale $s$ 把"保护"编码进 INT4 本身**。

### Scaling 公式

对每个 output channel $j$ 选一个 scale $s_j$:

$$
w_j^{quantized} = \text{Quant}(s_j \cdot w_j) / s_j
$$

含义:量化前先把 $w_j$ **乘以 $s_j$(通常 $s_j > 1$ 对 salient channel)**,量化后再除回来。

**关键**:在一个有限的量化 grid 下,放大后再 round-off,等效于**那一列获得了更高的 effective 精度**。

### 和 SmoothQuant 的对偶关系

SmoothQuant:$Y = (X/s)(sW)$——把 activation 压小,weight 放大。
AWQ:$Y = X \cdot (\text{Quant}(sW)/s)$——对 salient 列放大后量化。

两者用**同一套数学基础**,但方向不同:

- **SmoothQuant**:追求让 **activation 容易量化**(为了 W8A8)
- **AWQ**:追求让 **salient weight 精确**(为了 W4A16)

### 选最优 $s_j$

![Scale 因子 $s$ 和 PPL 的关系:$s$ 太小等于不保护,太大则其他列精度下降。存在一个甜蜜点 $s^* \approx 2$。AWQ 用 grid search 自动找这个点。](/assets/img/awq/x3.png)
_Figure 3:Scale 与 PPL 的曲线——存在最优点_

$s_j$ 的选择公式:

$$
s_j = (\max |X_j|)^{\alpha},\quad \alpha \in [0, 1]
$$

$\alpha$ 是 hyperparameter。用 128 个样本 grid search(20 个 $\alpha$ 值)找最优。整个搜索过程对 175B 模型只要**几分钟**。

## 算法流程

![AWQ 的完整 pipeline:(1) 运行校准数据;(2) 收集每层 activation 的 per-channel max;(3) grid search 最佳 $\alpha$;(4) 应用 scaling 和标准 INT4 量化。没有 Hessian 计算,没有顺序依赖。](/assets/img/awq/x4.png)
_Figure 4:AWQ 完整流程——比 GPTQ 简单得多_

1. **校准**:前向 128 个样本,记每层 activation $X$ 的 per-channel max
2. **Grid search**:对每个 linear layer 搜索最优 $\alpha$(20 个点)
3. **应用 scale**:$\hat w_j = s_j w_j$,scale 可以合并到前层 LayerNorm 的 $\gamma$
4. **标准 INT4 量化**:对 $\hat W$ 做 per-group(默认 group_size=128)INT4 量化

**关键优势**:

- 无 Hessian 计算
- 无列间依赖,完全并行
- 175B 量化从 GPTQ 的 4 小时 → **~20 分钟**

## 实验结果

### 质量:全面超过 GPTQ

![AWQ 在 OPT、LLaMA、Vicuna 系列上的 PPL 对比 FP16/RTN/GPTQ:各模型、各尺寸都领先。](/assets/img/awq/x5.png)
_Figure 5:AWQ 在主流模型上的 PPL 对比_

关键数字(LLaMA-7B, WikiText-2 PPL):

| 方法 | bits | PPL |
|------|------|-----|
| FP16 | 16 | 5.68 |
| RTN | 4 | 6.43 |
| GPTQ | 4 | 5.83 |
| **AWQ** | **4** | **5.72** |

AWQ 离 FP16 只差 0.04——**几乎无损**,且优于 GPTQ 0.11。

### 速度:量化速度 + 推理速度

- **量化速度**:LLaMA-70B 量化时间 GPTQ ~2 小时,**AWQ ~20 分钟**
- **推理速度**:AWQ 的 INT4 kernel(后续 TinyChat、Marlin)在 4090 上 **3-4× 快于 FP16**

### 泛化性

AWQ 在**多模态模型**(LLaVA)、**Instruction-tuned 模型**(Vicuna)、**Code 模型**(CodeLLaMA)上都有效——这是因为它不依赖特定任务,只依赖"activation 的重要性"这个通用信号。

## 工程影响

### 1. 成为 INT4 LLM 量化的事实标准

2023 年下半年起,HuggingFace、vLLM、TensorRT-LLM、Ollama 等几乎所有推理引擎都把 **AWQ 作为默认 INT4 格式**。你在 HuggingFace 上看到的 `-AWQ` 后缀的模型,都用的这个方法。

### 2. TinyChat / TinyLLM 边缘部署

AWQ 作者同时推出 **TinyChat**——配套的 INT4 推理框架,能让 7B 模型在 RTX 4090 / Jetson Orin 等消费级硬件上以**实时交互速度**运行。这直接催生了"笔记本跑 LLM"的实用性。

### 3. 简单性是 AWQ 胜出的关键

GPTQ 数学更深奥,实现有 ~1000 行代码。AWQ 的核心逻辑只有 ~200 行,任何人都能看懂。这种**"简单正确"** 的方法更容易被社区采纳、移植、扩展。

### 4. "Activation 信息指导量化"成为通用思路

AWQ 的"看 activation 决定 weight 重要性"思想,被后续很多工作继承:

- **SpQR** (2023):用 activation 找 outlier,用专门 sparse 存储
- **OmniQuant** (2023):让 scale 变 learnable
- **QuIP#** (2024):在 scaled weight 上做 vector quantization

## 局限

### 1. Salient 1% 是跨 input 平均

AWQ 假设 "1% salient channel" 是固定的。实际上不同 input 可能有不同的 salient channel。这在大 batch 下无损,但对某些 adversarial input 可能不准。

### 2. Calibration 数据敏感

Grid search 依赖 128 个样本的分布。如果与实际部署场景差别大,质量会下降。论文建议用 target domain 的样本。

### 3. Per-group 量化的固定 group_size

group_size=128 是经验值。极致低 bit(如 W3)下可能需要更小的 group——但会增加 scale 存储 overhead。

### 4. 不原生支持 activation 量化

AWQ 是纯 weight-only(W4A16)方案。激活要量化需要搭配 SmoothQuant 或后续工作(QServe)。

## 读完这篇你真正该带走的 4 件事

<callout emoji="white_check_mark" background-color="light-green" border-color="green">
1. **Weight 的重要性不是它自己决定的,而是 activation 决定的**:$\Delta Y_j = X_j \cdot \Delta w_j$——这个一眼就能看出的恒等式暗示的道理被忽略多年,AWQ 第一个系统化利用它
2. **Per-channel scaling 是"连续版"的混合精度保护**:不像 LLM.int8() 搞硬切分 FP16/INT8,AWQ 用 scale 把"保护"编码在 INT4 内部——量化本身机构不变,但效果等同于给重要列更多 bit
3. **"简单正确"胜过"数学复杂"**:AWQ 代码比 GPTQ 简单 5×,质量更好,速度快 10×——研究中"Occam's razor"常常被低估
4. **AWQ 格式 + INT4 kernel = 消费级 GPU 跑大模型**:这是 2024 年开源 LLM 爆发的核心技术基座。理解 AWQ 就理解了个人设备部署 LLM 为什么变得可能
</callout>
