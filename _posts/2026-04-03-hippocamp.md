> 📄 **论文**：HippoCamp: Benchmarking Contextual Agents on Personal Computers
> 🔗 **arXiv**：[2604.01221](https://arxiv.org/abs/2604.01221)
> 🏢 **机构**：南洋理工大学（NTU）等

## 一句话总结

HippoCamp 构建了首个模拟真实用户个人文件环境的 AI Agent 基准，包含 42.4 GB 数据、2000+ 真实文件和 581 个问答对，发现即便顶尖商业模型在用户画像任务上也仅能达到 48.3% 准确率，主要瓶颈在于多模态感知和证据定位能力。

## 背景与问题

现有计算机使用 Agent（Computer-Use Agent）的研究和评测，主要聚焦于通用任务（如打开应用、浏览网页），而忽视了一个核心现实：**真正有价值的 AI 个人助理必须理解和利用用户的个人上下文**。

个人计算机中存储着极其丰富的个人信息：工作文档、照片、聊天记录、PDF 报告、代码项目……这些跨模态、大规模的个人文件构成了"个人数字知识库"，是实现个性化服务的关键基础。

然而，现有 Agent 基准几乎都在"干净"的通用环境中测试，没有考虑：
- 如何在海量个人文件中检索相关证据
- 如何跨文件类型（图片、PDF、Word、代码）进行多模态推理
- 如何构建准确的用户画像以支持个性化任务

HippoCamp（参考海马体在大脑中负责记忆整合的功能）正是为填补这一空白而设计。

## 核心方法

### 数据集规模

| 维度 | 数值 |
|------|------|
| 总数据量 | **42.4 GB** |
| 真实文件数 | **2,000+** |
| 问答对数量 | **581 个** |
| 标注轨迹数 | **46,100+** |

### 三类评测任务

**1. 用户画像构建（User Profiling）**
Agent 需要通过分析用户的历史文件（邮件、文档、图片等），推断用户的职业、爱好、日常习惯等个人特征。这要求 Agent 进行跨文件的证据整合和高层次的语义推理。

**2. 证据感知（Evidence Perception）**
给定一个具体问题，Agent 需要在密集个人文件系统中定位相关证据文件，考验多模态检索和感知能力。

**3. 多步推理（Multi-Step Reasoning）**
需要跨多个文件、多个推理步骤才能回答的复杂问题，考验 Agent 的长程规划和上下文维护能力。

### 细粒度步骤级失败诊断

HippoCamp 不仅关注最终结果，还通过 **46,100+ 标注轨迹**对每一步操作进行失败分析，识别错误发生的具体位置（文件定位错误？模态理解错误？推理错误？），为模型改进提供精准指导。

## 实验结果

### 主要性能指标

| 模型 | 用户画像准确率 | 证据感知准确率 |
|------|------------|------------|
| 顶尖商业模型（最优） | **48.3%** | - |
| 其他前沿模型 | < 48.3% | 显著低于人类 |
| 人类参考水平 | ~85%+ | 高 |

即便是表现最优的商业模型，在用户画像任务上也只能达到 **48.3%** 的准确率，表明现有 MLLM 在理解真实个人文件环境方面存在根本性缺陷。

### 主要瓶颈分析

通过步骤级诊断，研究识别了三大核心瓶颈：

| 瓶颈类型 | 描述 |
|---------|------|
| **多模态感知能力不足** | 模型难以准确理解图片、PDF、混合格式文档中的详细信息 |
| **证据定位困难** | 在数千个文件中精确找到相关证据文件的能力显著不足 |
| **跨模态推理薄弱** | 整合来自不同类型文件的信息进行联合推理存在明显缺陷 |

### 思维链效应

扩展推理能力对长程检索任务有一定帮助，但提升有限；对于需要"感知"而非"推理"的证据定位任务，更长的思维链并没有带来显著提升。

## 总结

HippoCamp 的核心贡献在于：（1）首次构建真实规模的个人计算机 Agent 评测环境；（2）提出用户画像 + 证据感知 + 多步推理三维评测框架；（3）通过细粒度轨迹分析实现精准的失败诊断。项目页面：hippocamp-ai.github.io。

局限性：数据集构建成本高（42.4 GB 真实数据），难以大规模扩展；隐私敏感性限制了数据共享方式；当前主要评测的是静态文件理解能力，对动态交互（如边聊天边查阅文件）的支持有限。未来工作应探索更强的跨文件推理机制和用户隐私保护下的个性化 Agent 训练方法。
