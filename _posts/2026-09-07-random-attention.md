> 📄 **论文**：Random Attention: Rethinking KV Cache Eviction for Efficient Reasoning
> 🔗 **arXiv**：[2609.03430](https://arxiv.org/abs/2609.03430)
> 🏢 **机构**：Salesforce AI Research

## 一句话总结
在大模型推理中，随机淘汰 KV 缓存中的 token 与精心设计的评分策略效果相当，且吞吐量提升 32-43%，揭示了现有 KV 缓存压缩方法的核心机制。

## 背景与问题
大语言模型在需要扩展推理（extended reasoning）的任务上（如数学、代码、逻辑推理）表现卓越，但长链式思维（Chain-of-Thought, CoT）使 KV 缓存成为严重的内存瓶颈。以 32K token 的推理上下文为例，KV 缓存可能占用数 GB 显存。

现有的 KV 缓存压缩方法（如 SnapKV、H2O、ScissorHands 等）都遵循同一范式：**对每个缓存的 token 打分（估计其未来重要性），保留得分最高的 token**。这些方法的评分函数各不相同，但都付出了额外的计算开销。

**核心问题**：这些精心设计的评分函数究竟贡献了多少价值？

## 核心方法
**Random Attention 极其简单**：
- **保留所有 prompt token**（完整保留输入提示）
- **在每个注意力头内随机均匀淘汰**推理轨迹（reasoning trace）中的 token
- **不计算任何得分**，零开销选择

这种方法的背后有深刻的机理解释：

**机理 1：Prompt 是 KV 缓存中最脆弱的部分**
实验表明，选择器之间的性能差距主要来自它们是否碰巧保留了 prompt token。一旦 prompt 被保护，评分函数的边际价值接近于零。

**机理 2：推理轨迹具有内置冗余**
推理过程中，模型在两个层面上保护自己：
- **文本层面**：模型在推理过程中会不断重述当前需要的信息（"记住之前我们得到了 X..."）
- **注意力头层面**：每个头都维护推理轨迹的独立副本

因此，随机淘汰后，剩余 token 中仍保留足够多的推理轨迹副本，无需评分即可保持性能。

## 实验结果
在 **4 个模型 × 6 个推理任务** 的全面测试中：

| 方法 | 性能 | vLLM 吞吐量提升 |
|------|------|--------------|
| 最强评分淘汰器（基线） | ~ 相同 | 基准 |
| Random Attention（本文） | **匹配最强** | **+32-43%** |

**控制实验发现**：
- 保护 prompt 后，随机选择与最优选择性能相差无几
- 32K token 上下文中，perplexity 差距随位置增大而**缩小**，印证了冗余机制

代码已开源：https://github.com/SalesforceAIResearch/Random-Attention

## 总结
Random Attention 以"奥卡姆剃刀"式的简洁性揭示了 KV 缓存压缩领域的重要洞见：现有评分方法的性能优势几乎完全来自对 prompt 的隐式保护，推理轨迹本身的冗余设计使得随机淘汰足以胜任。

这一发现对领域有深远影响：它不仅提供了一个高吞吐、零计算开销的实用方案，更呼吁研究者反思复杂评分函数的必要性，并将目光转向 prompt 保护策略和推理冗余机制的更深入研究。局限性在于：对极低 KV 预算（<10%）场景的适用性仍需验证。
