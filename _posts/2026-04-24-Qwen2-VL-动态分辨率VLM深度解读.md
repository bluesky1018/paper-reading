- **机构**: Alibaba
- **发表**: arXiv 2024-09
- **arXiv**: [2409.12191](https://arxiv.org/abs/2409.12191)

## 一句话总结

阿里开源的 **Qwen2-VL** 系列(2B / 7B / 72B)——开源 VLM 的**当代顶点之一**。两个关键技术创新:(1) **Naive Dynamic Resolution**——不再强制 resize 到固定大小,模型直接处理**任意分辨率**图像(从 224 到 3000+ 像素),视觉 token 数量随图像动态变化;(2) **M-RoPE (Multimodal Rotary Position Embedding)**——把 RoPE 扩展到三维(时间 + 高度 + 宽度),让同一套位置编码自然支持文本、图像和视频。在 MMMU、MathVista、DocVQA 等 benchmark 上 **72B 版本全面对标 GPT-4o 和 Claude 3.5 Sonnet**。Qwen2-VL 是开源 VLM 真正能做"生产级视觉 Agent"的起点,UI-TARS、computer-use 等都基于它。

![Qwen2-VL 的架构:ViT + Dynamic Resolution → 动态数量 visual tokens → Qwen2 LLM。关键是不 resize 图像,让小图少 token、大图多 token,保持原始视觉信息完整。](/assets/img/qwen2vl/x1.png)

## 背景:固定分辨率的桎梏

### LLaVA / BLIP-2 的问题

传统 VLM 把所有图像 **resize 到固定分辨率**(224, 336, 448):

- 小图被 padding / upscale——浪费 token
- 大图被 downscale——丢失细节
- **文档、OCR、图表**这些任务严重受损——细节是关键

### AnyRes 等切图方案

LLaVA-NeXT 的 AnyRes:把大图切成多个 tiles,每个处理后拼起来。有效但:

- 处理边界不自然
- Token 数量仍有硬上限
- 不同 aspect ratio 处理不优雅

### Qwen2-VL 的激进方案

**完全取消"固定分辨率"的概念**——ViT 直接处理任意分辨率,视觉 token 数量随图动态。

## 核心机制

### 1. Naive Dynamic Resolution

![Dynamic Resolution 的处理:输入图可以是任意 H×W,ViT patch 化后 token 数量 = (H/14) × (W/14)。从小图的几十 token 到大图的数千 token,完全弹性。](/assets/img/qwen2vl/x2.png)
_Figure 2:Dynamic Resolution_

做法:

1. ViT 的 patch size = 14
2. 图像 $H \times W$ 产生 $(H/14) \times (W/14)$ patches
3. 所有 patches **flatten 成序列**送入 ViT
4. ViT 输出相同数量的视觉 token 给 LLM

优势:

- **小图省 token**:256×256 图只需 ~300 token
- **大图保留细节**:2000×1500 文档图可能 1万 token
- **原生 aspect ratio**——不 distortion

为了控制 token 数量,设置一个 **max_pixels** 上限(默认 ~1M 像素),超过会 resize。

### 2. M-RoPE(Multimodal RoPE)

![M-RoPE 把位置编码从 1D 扩展到 3D:时间、高度、宽度。文本 token 只有时间维有效,图像 token 有高和宽,视频有三者。所有模态共享统一位置编码,自然对齐。](/assets/img/qwen2vl/x3.png)
_Figure 3:M-RoPE 的三维位置编码_

传统 RoPE 是 1D——适合文本但不适合视觉。Qwen2-VL 扩展到 3D:

- 时间维(对视频):帧 id
- 高度维(对图像):patch 的 row
- 宽度维(对图像):patch 的 column

对不同模态:

- **文本**:只有时间维有意义,height 和 width 设为常数
- **图像**:时间维设为常数,用 height + width
- **视频**:三个维度都用上

**关键**:三维各分到 head_dim 的 1/3——让一个 Transformer 自然处理不同模态。

### 3. Multimodal Data

![Qwen2-VL 的训练数据覆盖:单图 VQA、多图推理、视频理解、文档理解、OCR、GUI 操作、agent tasks 等。~1.4T tokens 的视觉 + 文本混合数据。](/assets/img/qwen2vl/x1.png)
_Figure 4:Qwen2-VL 的训练数据构成_

- **Multi-aspect ratio 数据**:各种形状的图
- **高分辨率文档 / 图表**:细节丰富的图
- **视频**:长达几分钟
- **GUI 截图**:为 computer-use 准备
- **多图数据**:多图推理
- **合成数据**:用 GPT-4/Claude 生成指令数据

总量估计 **1.4T tokens**(视觉 + 文本混合)。

### 4. 三阶段训练

1. **Stage 1: Vision Pretrain**
   - 训 ViT + projector
   - Data: image-text pairs
   - LLM frozen

2. **Stage 2: Multimodal Pretrain**
   - 全模型训练
   - Data: interleaved image-text, OCR, documents
   - 大量数据,长时间

3. **Stage 3: Instruction Tuning**
   - Data: 指令数据、agent 数据、对话
   - 多任务 SFT

## 实验结果

### MMMU (Multi-discipline)

| 模型 | 参数 | MMMU |
|------|------|------|
| GPT-4o | - | 69.1 |
| Claude 3.5 Sonnet | - | 68.3 |
| LLaVA-NeXT 72B | 72B | 60.7 |
| **Qwen2-VL-72B** | **72B** | **64.5** |

接近闭源前沿。

### MathVista

| 模型 | MathVista |
|------|-----------|
| GPT-4o | 63.8 |
| Claude 3.5 | 67.7 |
| Qwen2-VL-72B | **70.5** |

**开源第一个在视觉数学上超过 Claude 3.5 Sonnet**。

### DocVQA(文档理解)

Dynamic resolution 最能发挥优势的地方:

| 模型 | DocVQA |
|------|--------|
| GPT-4o | 92.8 |
| **Qwen2-VL-72B** | **96.5** |

**大幅超过 GPT-4o**——高分辨率 + 原生 aspect ratio 让文档识别质变。

### 视频理解

**Qwen2-VL 支持小时级视频**(几百帧):

- VideoMME:GPT-4o 71.9,Qwen2-VL-72B **71.2**(接近)
- MLVU(长视频):Qwen2-VL 领先

## 工程影响

### 1. 开源 VLM 追上闭源

Qwen2-VL 72B 在 MMMU、MathVista、DocVQA 等多项 benchmark 匹配或超过 GPT-4o——**开源 VLM 第一次在 2024 年达到闭源前沿**。

### 2. Dynamic Resolution 成为新标准

Qwen2-VL 之后,许多 VLM 采用 dynamic resolution:

- LLaVA-NeXT AnyRes 变体
- InternVL 2.5 动态图块
- MiniCPM-V 2.6

### 3. M-RoPE 启发多模态位置编码

统一 3D 位置编码是优雅的设计。Qwen2.5-VL、未来更多多模态模型都会用类似思路。

### 4. 视觉 Agent 的基础

Qwen2-VL 成为 **UI-TARS、computer-use agent、手机 GUI agent** 的核心 base。其视觉感知质量使其能准确 click、type、scroll。

### 5. 中国开源 VLM 的代表

Qwen2-VL(和 InternVL、MiniCPM-V)让中国在开源 VLM 方向**第一次达到并超过美国开源**(LLaVA, IDEFICS 等)。

## 局限

### 1. Token 爆炸问题

极大图像(5000×5000)会产生数万 token,**context 可能爆炸**。需要限制 max_pixels 或在应用层做 crop。

### 2. 视频长度仍有限

几分钟视频 OK,**超长视频(1 小时+)** 仍困难——时间维度的压缩需要更好的方案。

### 3. 3D 空间理解弱

Qwen2-VL 仍然把图像当 2D——对 depth、3D reasoning 弱。这是所有 2D VLM 的共同问题。

### 4. 推理成本高

72B + 动态 token 让推理比 LLaVA 贵很多。对成本敏感场景仍需小模型。

## 读完这篇你真正该带走的 4 件事

<callout emoji="white_check_mark" background-color="light-green" border-color="green">
1. **Dynamic Resolution 是 VLM 的自然进化**:固定分辨率是 CNN 时代的遗留——ViT 架构本来就支持任意尺寸。Qwen2-VL 只是"让它真的动态化",这个决定是 2024 年 VLM 的重要架构进化
2. **统一位置编码优雅处理多模态**:M-RoPE 用 3D 位置编码统一文本/图像/视频——不需要模态 specific embedding,一个 transformer 自然 handle
3. **开源 VLM 已真正 competitive**:Qwen2-VL 72B 对标 GPT-4o 和 Claude 3.5——开源 VLM 已经不再是"学术玩具"
4. **VLM 是 Agent 的基础设施**:Qwen2-VL 的视觉质量让 computer-use agent 变得真正可行。后续 UI-TARS、GUI agent、具身 agent 都依赖这种级别的 VLM
</callout>
