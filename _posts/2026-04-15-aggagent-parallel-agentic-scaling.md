# AggAgent：通过智能聚合实现长时域智能体任务的并行扩展

> **论文信息**
> arXiv: [2604.11753](https://arxiv.org/abs/2604.11753)
> 机构：普林斯顿语言与智能实验室（PLI）
> 作者：Yoonsang Lee, Howard Yen, Xi Ye, Danqi Chen
> 代码：[princeton-pli/AggAgent](https://github.com/princeton-pli/AggAgent)（`pip install aggagent`）

---

## 1. 背景：为什么并行扩展在智能体任务中失效？

### 1.1 测试时计算扩展的成功与局限

近年来，测试时计算扩展（Test-Time Compute Scaling）已被证明是提升 AI 系统性能的有效手段：

- **短形式推理任务**（数学题、代码题）：运行 K 条推理路径，用多数投票（Majority Vote）选出最终答案，效果显著
- **搜索增强生成**：多次检索-生成循环，聚合结果

然而，这些方法直接迁移到**长时域智能体任务**时遭遇根本性障碍。

### 1.2 长时域智能体任务的特殊性

所谓"长时域智能体任务"，是指需要模型：
1. 自主规划多步行动序列（网页搜索、深度研究、医疗咨询）
2. 执行数十乃至上百次工具调用（搜索 API、浏览器操作、代码执行）
3. 动态调整策略（基于中间结果决定下一步行动）
4. 最终生成开放性、长篇幅的答案（而非单一类别或数字）

### 1.3 并行 K 路 Rollout 的两难困境

对于长时域任务，运行 K 条独立的智能体轨迹（parallel rollout）在直觉上很有吸引力——不同路径可能发现不同的信息、采用不同的策略。但**如何聚合 K 条轨迹的结果**成为了核心难题：

| 聚合挑战 | 短形式推理 | 长时域智能体任务 |
|---------|---------|--------------|
| 答案形式 | 离散类别/数字 | 开放性长文本 |
| 多数投票可行？ | 可行 | **不可行**（答案无法直接比较） |
| 直接拼接 K 条轨迹？ | 不适用 | **超出上下文窗口**（K×N tokens） |
| 评估哪条轨迹"更好"？ | 简单 | **困难**（需要理解任务目标） |

现有的启发式方法（随机选一条、取最长答案、置信度加权）都缺乏系统性，无法充分利用 K 条轨迹中的互补信息。

## 2. AggAgent：将聚合本身变成一个智能体任务

### 2.1 核心洞见

AggAgent 的关键创新在于：**将聚合过程本身建模为一个元智能体（Meta-Agent）任务**。

与其用固定规则从 K 条轨迹中选一条，AggAgent 让一个 LLM 智能体：
1. **主动审查**所有 K 条轨迹的最终答案
2. **识别分歧**：不同轨迹在哪些细节上存在矛盾？
3. **按需深挖**：针对疑点，直接查阅原始轨迹的中间步骤和工具调用记录
4. **交叉验证**：对比多条轨迹的证据质量
5. **综合输出**：整合最优信息，生成最终答案

这一设计将聚合从"盲目规则"升级为"主动推理"。

### 2.2 可检查的环境设计

AggAgent 将 K 条已完成的轨迹视为一个**可检查的环境（Inspectable Environment）**，并为元智能体提供4个专用工具：

| 工具 | 函数签名 | 用途 |
|------|---------|------|
| **获取解答** | `get_solution(trajectory_id)` | 提取某条轨迹的最终答案 |
| **检索轨迹片段** | `search_trajectory(id, query, top_k)` | 按关键词在轨迹中做 ROUGE-L 排名检索 |
| **读取原始步骤** | `get_segment(id, start, end)` | 深度查看某轨迹的原始工具调用与观察结果 |
| **提交答案** | `finish(answer)` | 输出综合后的最终响应 |

### 2.3 工具设计的智慧

每个工具的设计都有深刻的工程考量：

**`get_solution`**：最轻量的入口。元智能体首先浏览所有 K 条轨迹的最终答案，快速识别共识与分歧，无需读取冗长的中间过程。

**`search_trajectory`**：关键的效率工具。通过 ROUGE-L 关键词检索，元智能体可以**精确定位**某条轨迹中与特定问题相关的片段，避免"大海捞针"式地读完整轨迹。这类似于给元智能体一个"快速搜索引擎"。

**`get_segment`**：深度验证工具。当 `search_trajectory` 找到候选片段后，元智能体可以进一步读取上下文（`start` 到 `end` 的原始步骤），验证信息的准确性和推理链的可靠性。

**`finish`**：输出接口。元智能体完成分析后，将综合各条轨迹优势的最终答案提交。

### 2.4 典型工作流程

```
1. 对每条轨迹调用 get_solution()
   → 发现: 轨迹1-3认为答案是X，轨迹4-5认为是Y，轨迹6有额外细节Z

2. 对有争议的细节调用 search_trajectory()
   → 定位到相关证据片段

3. 对关键片段调用 get_segment()
   → 验证原始工具调用结果（如搜索引擎返回的原始网页内容）

4. 交叉对比轨迹质量：
   - 轨迹3的搜索来源更权威
   - 轨迹5存在推理跳跃
   - 轨迹6的细节Z在轨迹1-4中均有间接支持

5. 调用 finish()，综合X + 细节Z，排除Y
```

## 3. 实验设置

### 3.1 六大基准测试

| 基准 | 任务类型 | 难度特点 |
|------|---------|---------|
| **BrowseComp** | 网页搜索问答 | 需要精确的多跳网页浏览 |
| **BrowseComp-Plus** | 增强版网页搜索 | 更复杂的信息检索链 |
| **HLE（Humanity's Last Exam）** | 人类最难考试 | 涵盖各学科极难问题 |
| **DeepSearchQA** | 深度搜索问答 | 需要多轮深度网页检索 |
| **HealthBench** | 医疗咨询 | 需要综合多源医学信息 |
| **ResearchRubrics** | 学术研究辅助 | 需要系统性文献调研 |

### 3.2 三种基础模型家族

- **GLM-4.7**
- **Qwen3.5**
- **MiniMax-M2.5**

### 3.3 七种对比基线

**启发式方法（无需额外推理）：**

| 基线 | 方法 | 描述 |
|------|------|------|
| `pass` | 单次 | 上界参考（oracle 选最优轨迹） |
| `mv` | 多数投票 | 经典 Majority Vote |
| `wmv` | 置信度加权 | 按模型输出置信度加权投票 |
| `bon` | Best-of-N | 用奖励模型选最佳轨迹 |
| `fewtool` | 少量工具 | 仅使用 get_solution 的简化版元智能体 |

**LLM 辅助方法：**

| 基线 | 方法 | 描述 |
|------|------|------|
| `solagg` | 答案聚合 | 将 K 条轨迹的最终答案直接喂给 LLM，请其综合 |
| `summagg` | 摘要聚合 | 先摘要每条轨迹，再整合所有摘要 |

## 4. 实验结果

### 4.1 总体性能

**AggAgent 在6个基准测试上平均超越所有基线最高 +5.3%（绝对值）。**

这一提升在不同基础模型（GLM-4.7、Qwen3.5、MiniMax-M2.5）上均保持一致，证明方法的通用性而非针对特定模型的优化。

### 4.2 深度研究任务的突出表现

在 **HealthBench** 和 **ResearchRubrics** 两个深度研究类任务上，AggAgent 表现尤为突出：

| 任务类别 | AggAgent 提升（vs 最佳基线） |
|---------|--------------------------|
| 深度研究任务（HealthBench + ResearchRubrics） | **+10.3% 绝对值** |
| 全部6个基准平均 | **+5.3% 绝对值** |

深度研究任务的更大提升可以直觉理解：这类任务的不同轨迹更可能发现**互补信息**（一条轨迹找到论文A，另一条找到论文B），元智能体的综合能力在此更能发挥价值。相比之下，标准问答任务的不同轨迹往往发现相同信息，差异主要在答案质量而非信息覆盖。

### 4.3 与各基线的对比分析

| 基线 | AggAgent 优于基线的原因 |
|------|----------------------|
| `mv`（多数投票） | 不适用于开放性答案；无法利用少数但正确的轨迹 |
| `wmv`（置信度加权） | 模型置信度校准不准，权重意义有限 |
| `bon`（Best-of-N） | 单选一条轨迹，丢失其他轨迹的互补信息 |
| `solagg`（直接聚合） | 仅看最终答案，无法验证推理可靠性 |
| `summagg`（摘要聚合） | 摘要压缩导致关键细节丢失 |

### 4.4 计算成本

| 方法 | 额外计算成本 |
|------|------------|
| 直接拼接 K 条轨迹 | O(K × N) tokens — **不可行** |
| `solagg` | O(K × 最终答案长度) |
| `summagg` | O(K × 摘要长度) |
| **AggAgent** | **O(1) 额外推理（约等于1次额外 rollout）** |

AggAgent 的成本之所以是 O(1) 而非 O(K)，原因在于：
- 元智能体不需要读完所有 K 条完整轨迹
- `search_trajectory` 和 `get_segment` 实现了**按需、精准的信息检索**
- 平均下来，每次聚合的工具调用次数远小于完整轨迹长度 × K

## 5. 消融实验

### 5.1 工具重要性排序

通过逐一移除工具进行消融，发现各工具对最终性能的贡献：

| 移除工具 | 性能下降程度 | 解读 |
|---------|------------|------|
| 移除 `search_trajectory` | **最大下降** | 关键词检索是高效聚合的核心 |
| 移除 `get_segment` | 中等下降 | 深度验证影响精确性 |
| 仅保留 `get_solution` | 接近 `solagg` 水平 | 说明单纯获取答案与直接答案聚合等价 |

**关键结论：`search_trajectory` 是 AggAgent 最重要的工具。**

没有关键词检索能力，元智能体就无法高效定位证据，要么不得不读完所有轨迹（代价过高），要么只能依赖最终答案（退化为 `solagg`）。

### 5.2 K（并行轨迹数量）的影响

随着 K 的增加，AggAgent 的优势更加明显——这符合预期，因为更多轨迹提供了更多互补信息，而传统启发式方法无法有效利用这些信息。

## 6. 与相关工作的对比

### 6.1 与传统测试时扩展的对比

| 方法类别 | 适用任务 | 聚合方式 | 可行性 |
|---------|---------|---------|-------|
| Majority Vote | 分类/数学 | 直接投票 | 短形式任务有效 |
| Self-Consistency | 推理 | 路径一致性 | 封闭答案空间 |
| Best-of-N | 生成 | 奖励模型打分 | 需要可靠奖励信号 |
| **AggAgent** | 长时域智能体 | 元智能体主动检索 | **开放答案空间** |

### 6.2 与 Agent Debate / Multi-Agent 的对比

多智能体辩论（Agent Debate）框架让多个智能体**实时交互**，每个智能体可以影响其他智能体的搜索策略。AggAgent 采用不同路线：K 条轨迹**完全独立**执行，聚合在事后进行。

这种"先独立后聚合"的方式有其独特优势：
- 避免智能体间的"共识偏误"（一个智能体的错误可能传染其他智能体）
- 轨迹执行可以并行，没有通信延迟
- 聚合阶段有完整的轨迹记录可供审查

## 7. 实际应用与未来方向

### 7.1 当前适用场景

AggAgent 特别适合以下场景：

1. **深度研究助手**：需要从大量文献中综合信息，不同搜索策略发现互补文献
2. **医疗诊断辅助**：不同推理路径关注不同症状维度，综合可以降低漏诊风险
3. **竞争情报分析**：多路并行搜索覆盖更广的信息来源
4. **代码 Debug**：不同轨迹尝试不同修复策略，聚合选最优

### 7.2 未来研究方向

**方向一：自适应 K 选择**

当前 K 是超参数，固定设置可能不是最优。未来可以研究：根据问题难度动态决定需要多少条并行轨迹。

**方向二：轨迹多样性引导**

如何在生成 K 条轨迹时主动引入多样性？例如使用不同搜索策略、不同提示词，使各轨迹在信息覆盖上互补而非冗余。

**方向三：元智能体的训练**

当前 AggAgent 使用预训练 LLM 作为元智能体，零样本使用4个工具。通过专门的训练数据（正确聚合的示范），元智能体的聚合能力还有很大提升空间。

**方向四：流式聚合**

当前设计中，所有 K 条轨迹完成后才开始聚合。能否在轨迹运行过程中实时聚合，更早发现有价值的信息方向并引导后续轨迹？

**方向五：层次化聚合**

对于极大规模的 K（如 K=100），可以考虑先将 K 条轨迹分组聚合，再对组间结果做第二层聚合。

---

## 8. 总结

AggAgent 以优雅的方式解决了一个被长期忽视的问题：**如何在不超出上下文窗口的前提下，充分利用并行智能体轨迹的互补信息**。

核心贡献总结：

| 维度 | 贡献 |
|------|------|
| 问题定义 | 首次系统分析长时域任务中并行扩展的聚合瓶颈 |
| 方法设计 | 将聚合建模为元智能体任务，4个专用工具实现按需检索 |
| 计算效率 | O(1) 额外成本，而非 O(K) |
| 实验验证 | 6个基准 × 3个模型家族，平均 +5.3%，深度研究任务 +10.3% |
| 工程价值 | `pip install aggagent`，开箱即用 |

随着 AI 系统在长时域、开放性任务上的部署日益增多，"如何扩展测试时计算"和"如何聚合并行结果"将成为越来越核心的工程和研究问题。AggAgent 提供了一个清晰的框架和有力的实证支持。
