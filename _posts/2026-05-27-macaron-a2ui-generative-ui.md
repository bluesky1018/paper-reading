> 📄 **论文**：Macaron-A2UI: A Model for Generative UI in Personal Agents
> 🔗 **arXiv**：[2605.24830](https://arxiv.org/abs/2605.24830)
> 🏢 **机构**：Mind Lab

## 一句话总结

Macaron-A2UI 通过构建 14,245 个标注样本的语料库、A2UI-Bench 评测基准以及 SFT+RL 两阶段训练，使个人智能体无需推理时的长模式提示即可生成适应对话上下文的轻量级交互 UI，最优模型在 A2UI-Bench 上达到 75.6 分，超越提供完整模式的 GPT-5.4（74.1 分）。

## 背景与问题

随着个人智能体承担越来越复杂的用户任务（旅行规划、情感支持、预约挂号、多目标调度），静态纯文本聊天已逐渐成为瓶颈。一个询问多条件机票预订的用户获得的是一面墙的文字，而清单、滑块或日期选择器本可更高效地表达结构化选项、确认和状态。**生成式 UI** 因此成为不可或缺的新交互层——在运行时从交互上下文中动态合成正确的控件、选项和状态。

论文识别出三大领域空白：没有大规模 UI 接地对话监督语料库用于训练智能体侧 UI 生成；没有评测框架能分别衡量协议有效性、交互构建质量和用户侧质量；也没有证据表明模型能在不依赖推理时长模式提示的情况下内化生成式 UI 生成能力。

本文与截图转代码生成、GUI 导航智能体（WorldGUI、GUI-Actor 等）以及开放式 HTML/JS 合成等工作方向不同，聚焦于**助手侧**：给定对话上下文，在固定协议（A2UI v0.8）下产出声明式、结构化、可执行的 UI 动作序列，同时输出自然语言响应，无需自由形式代码生成。

## 核心方法

### A2UI 协议（v0.8）

A2UI 是一个声明式协议，定义四种消息类型：

| 消息类型 | 作用 |
|----------|------|
| `beginRendering` | 创建 / 启动新 UI 表面 |
| `surfaceUpdate` | 定义或更新组件树 |
| `dataModelUpdate` | 写入响应式应用状态 |
| `deleteSurface` | 移除现有表面 |

模型始终输出 `{"text_response": "...", "a2ui": [...]}` 形式的 JSON 响应，生成挑战分三层：协议有效性、交互构建质量和用户侧质量。

### 语料库构建（14,245 个样本）

| 数据来源 | 领域 | 基础对话数 | 样本总数 | UI 比例 |
|----------|------|:----------:|:--------:|:-------:|
| MultiWOZ | 任务导向 | 997 | 5,424 | 80.4% |
| SGD | 任务导向 | 3,109 | 4,757 | 79.1% |
| ESConv | 情感支持 | 100 | 1,098 | 55.0% |
| AnnoMI | 动机访谈 | 100 | 2,966 | 50.0% |
| **合计** | — | **4,306** | **14,245** | **71.7%** |

四级验证流程（格式→结构→数据绑定→语义），支持最多 3 次重试，**最终渲染通过率 99.2%**。

### A2UI-Bench（300 个任务）

三类任务：
- **原子任务**：单轮单意图，测试核心 UI 生成决策
- **深度任务**：多轮一致性，模型基于自身先前输出滚动推进
- **宽度任务**：单轮多意图组合挑战

四级评估：L1（自动化模式合规）→ L2（LLM 评判：触发合理性、组件-意图对齐）→ L3（LLM 评判：相对纯文本的增值）→ V1-V3（VLM 评判渲染截图）。

### 训练流程

两阶段 LoRA 训练：

1. **SFT**：标准自回归 NLL，lr=1×10⁻⁴，batch=32，1 epoch，max_length=4096，LoRA rank=16
2. **GRPO**：每 prompt 采样 G=8 个候选，组内中心化奖励；lr=3×10⁻⁵，50 步，温度=1.0，评判模型=GPT-5.1

奖励设计：硬性门控（格式错误、缺失 UI、渲染关键错误→零奖励），通过后加权求和：`R = 1[pass]·(0.2·S_L1 + 0.4·S_L2 + 0.4·S_L3)`

## 实验结果

### 主要基准对比（A2UI-Bench，1-5 分制）

| 模型 | 提示方式 | L1 | L2 | L3 | 平均 |
|------|:--------:|:--:|:--:|:--:|:----:|
| GPT-5.4 | 含模式 | 4.02 | 3.59 | 3.27 | 3.54 |
| Gemini-3.1-Pro | 含模式 | 4.25 | 3.20 | 2.96 | 3.42 |
| Qwen3-235B（未微调）| 含模式 | 4.00 | 2.87 | 2.76 | 3.20 |
| **Macaron-A2UI-Grande (235B)** | **无模式** | **4.67** | **3.22** | **2.91** | **3.66** |
| **Macaron-A2UI-Venti (GLM-5.1)** | **无模式** | **4.47** | **3.36** | **3.28** | **3.72** |

前沿模型在无模式提示下得分大幅下降：GPT-4o-mini 25.5，DeepSeek-V3.1 21.9，GPT-5.4 23.9。

### 训练进展（0-100 分制）

| 模型 | 未微调 | SFT 后 | RL 后 |
|------|:------:|:------:|:-----:|
| Qwen3-30B | 19.8 | 37.2 | 58.8 |
| Qwen3-235B | 21.6 | 63.6 | 74.2 |
| GLM-5.1 (Venti) | — | — | **75.6** |

## 总结

Macaron-A2UI 证明了**生成式 UI 能力无需在推理时依赖重量级模式提示**——通过训练可以学习并内化。完整的流程（协议设计→语料库构建→评测基准→SFT+RL 训练）产出的模型在最小提示场景中匹配甚至超越提供完整模式的前沿基线，最优模型（Macaron-A2UI-Venti，GLM-5.1 骨干）在 A2UI-Bench 上达到 75.6 分，而 GPT-5.4 仅为 74.1 分。

**局限性**：A2UI 协议仍在演进（v0.8），训练语料库可能未覆盖所有未来协议版本；对于复杂多轮深度任务和用户侧质量（L3），模型能力仍是瓶颈，尤其是 30B 规模；生成-验证-渲染循环的实时延迟在部署场景中仍是实际挑战。
