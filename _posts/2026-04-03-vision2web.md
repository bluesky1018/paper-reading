> 📄 **论文**：Vision2Web: A Hierarchical Benchmark for Visual Website Development with Agent Verification
> 🔗 **arXiv**：[2603.26648](https://arxiv.org/abs/2603.26648)
> 🏢 **机构**：清华大学；智谱 AI

## 一句话总结

Vision2Web 构建了首个端到端的层次化网站开发基准，从静态页面到全栈应用，涵盖 193 个任务和 1255 个测试用例，发现即便是顶尖模型在全栈开发任务上仍大幅落后，特别是在移动端适配和功能实现方面存在明显短板。

## 背景与问题

大语言模型在代码生成领域取得了显著进展，但现有评测主要聚焦于孤立的代码片段生成（如 HumanEval、MBPP），缺乏对**端到端、多页面、完整功能网站开发**的系统性评估。

真实世界的网站开发远比单函数生成复杂：开发者需要同时处理视觉设计（参考原型图）、交互逻辑（多页面导航）和后端功能（数据库、认证、API），这要求模型具备跨模态理解、长程规划和状态管理能力。

现有代码 Agent 基准在以下方面存在明显不足：
- **缺乏视觉输入**：不考虑 UI 原型图等视觉规格
- **任务过于简单**：仅评估单文件生成，忽略系统集成
- **评测可靠性差**：依赖静态比较，无法验证动态交互功能

## 核心方法

### 三层任务体系

![基准概览](https://arxiv.org/html/2603.26648v1/figures/VisionWebDev_Fig1.png)
*图1：Vision2Web 层次化基准概览，从静态页面到全栈网站的三级任务体系*

| 层级 | 描述 | 复杂度 |
|------|------|--------|
| **L1：静态网页** | 单页面；支持桌面/平板/移动端响应式复现 | ⭐⭐ |
| **L2：交互式前端** | 多页面导航逻辑；跨页面一致性 | ⭐⭐⭐ |
| **L3：全栈网站** | 需求文档 + 原型图；后端、认证、CRUD、状态管理 | ⭐⭐⭐⭐⭐ |

### 数据集构建管道

从 **63,515 个真实网站**（经 DOM 深度和标签分布筛选）出发：
1. 内容质量筛选（VLM 评分）→ 保留 7,391 页
2. 人工审核 → 最终 **193 个任务，16 个类别**，918 张原型图，1,255 个测试用例

### 基于工作流的智能体验证系统

**核心创新：** 将每个任务建模为有向依赖图（Directed Dependency Graph）：
- **功能节点**：三元组 `(目标, 操作序列, 验证条件)` → GUI Agent 自动执行验证 → **功能得分（FS）**
- **视觉节点**：`(原型图)` → VLM Judge 打分视觉保真度 → **视觉得分（VS）**

## 实验结果

### 主要结果（OpenHands 框架）

| 模型 | 静态均分 | 前端 VS/FS | 全栈 VS/FS | 全栈依赖完成率 |
|------|---------|-----------|-----------|--------------|
| Claude-Opus-4.5 | **53.4** | 46.5/66.7 | 38.4/57.6 | 96.3% |
| GPT-5 | 49.6 | 23.9/61.4 | 18.3/49.7 | 100% |
| Gemini-3-Pro | 55.8 | 29.7/40.7 | 11.7/22.6 | 77.8% |
| Gemini-3-Flash | 47.8 | 25.9/38.4 | 7.7/17.2 | 66.7% |
| Seed-1.8-VL | 1.3 | 7.5/33.9 | 0/0 | 14.8% |

![任务分布](https://arxiv.org/html/2603.26648v1/figures/task_distribution.png)
*图2：Vision2Web 任务类别分布情况*

### 关键发现

**1. 性能随复杂度系统性下降**
所有 Agent 从 L1 到 L3 都出现可测量的性能衰减，全栈任务（L3）中最强模型 Claude-Opus-4.5 的全栈功能得分仅 57.6%。

**2. 设备敏感性问题**
移动端/平板端视觉得分比桌面端低 **10–20 分**，即便是最强模型也存在明显的响应式布局能力不足。

**3. 框架影响显著**
OpenHands 整体优于 Claude Code（Claude 系列模型除外），框架选择对最终成果有实质性影响。

**4. 功能类型差异**
页面导航/认证功能较强；文件与媒体操作最弱（Opus-4.5 仅 33.3%，GPT-5 仅 16.7%）。

### 验证系统可靠性

| 评测组件 | 与人工标注一致率 |
|---------|--------------|
| GUI Agent 验证器 | **87.2%** 节点级一致（218/250 节点） |
| VLM Judge | Spearman ρ = **0.66**（中位数 0.80） |

## 总结

Vision2Web 揭示了一个重要现实：**孤立任务上的强表现不能可靠迁移到端到端系统构建**。核心贡献包括：（1）首个层次化端到端网站开发基准；（2）基于工作流的自动化评测范式；（3）系统识别了跨模态推理、持久状态管理和长程规划三大能力瓶颈。

局限性：基准构建依赖人工标注，规模扩展成本较高；VLM Judge 与人工标注的相关性（ρ=0.66）仍有提升空间；目前对于动态 JavaScript 交互的验证依赖 GUI Agent，存在验证盲区。
