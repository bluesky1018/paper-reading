> 📄 **论文**：OmniPack: Unified Token Compression for Efficient Omni-modal Large Language Models
> 🔗 **arXiv**：[2608.03812](https://arxiv.org/abs/2608.03812)
> 🏢 **机构**：西北工业大学、北京大学、阿里巴巴、清华大学

## 一句话总结
OmniPack 通过模态特定的 LLM 前压缩与查询条件的 LLM 内压缩相结合，实现了全模态大语言模型中视觉和音频 token 的高效统一压缩，在五个音视频基准上以 7.5% token 保留率取得最佳整体性能。

## 背景与问题

全模态大语言模型（Omni-LLM）能够联合处理视觉、音频和文本输入，代表性系统包括 Gemini 3.1 Pro、GPT-4o 和 Qwen2.5-Omni 等。然而，**密集化的视觉和音频 token 会产生比文本长得多的序列**，在推理时带来巨大的计算和内存开销。

高效部署需要激进的 token 压缩来去除冗余，同时保留任务相关的多模态信息。现有方法存在三个主要局限：

1. **模态割裂**：视觉、音频 token 压缩分别研究，缺乏跨模态协同
2. **无查询意识**：压缩基于结构特征而非用户查询的语义相关性
3. **两阶段不联合**：LLM 前和 LLM 内的压缩相互独立，信息损失累积

## 核心方法

### OmniPack 框架概览

![OmniPack 框架](https://arxiv.org/html/2608.03812v1/x3.png)
*图1：OmniPack 框架概览。LLM 前执行模态特定压缩（重要性选择、覆盖率选择、相似性感知 token 合并），LLM 内在第 ℓ 层 Transformer 块后执行查询条件的音视频协同压缩。*

OmniPack 的核心设计：**两阶段压缩策略**

| 阶段 | 目标 | 方法 |
|------|------|------|
| **LLM 前压缩** | 去除结构冗余，保留显著和代表性信息 | 模态特定独立压缩 |
| **LLM 内压缩** | 基于查询相关性和音视频协同精炼 token | 查询条件联合压缩 |

### 阶段一：模态特定 LLM 前压缩

由于跨模态语义尚未在编码器层充分显现，LLM 前阶段对每个模态独立处理：

**1. 重要性选择（Importance Selection）**

利用模态编码器最终注意力统计估计 token 中心性：

$$\mathbf{A}^m=\operatorname{Softmax}\left(\mathbf{Q}^m(\mathbf{K}^m)^\top/\sqrt{d}\right)$$

结合模态特定的结构变化，识别每个模态中的主导 token。

**2. 覆盖率选择（Coverage Selection）**

确保选取的 token 覆盖整个序列，避免信息盲区。

**3. 相似性感知 Token 合并（Similarity-aware Token Merging）**

将相似的 token 合并为一个，在减少数量的同时保留语义多样性。

### 阶段二：查询条件 LLM 内压缩

在前 $\ell$ 个 Transformer 块之后，对压缩后的序列执行查询条件的音视频协同压缩：

设文本隐藏状态为 $\mathbf{H}_\ell^q=\{\mathbf{h}_j^q\}_{j=1}^{N_q}$，对其均值池化得到全局查询向量，用于度量每个音视频 token 与查询的相关性，实现以下三重精炼：

- **文本相关性**：保留与查询语义最相关的 token
- **音视频协同**：利用视觉信息引导音频 token 选择（反之亦然）
- **模态内代表性**：保留最具代表性的 token 避免冗余

## 总结

OmniPack 通过将模态特定的结构感知压缩与任务感知的查询条件压缩相结合，解决了全模态 LLM 中 token 压缩的核心挑战。该方法无需重新训练，可直接应用于现有 Omni-LLM，在极低 token 保留率（7.5%）下仍保持优异性能。

**核心创新**：(1) 两阶段统一压缩框架，LLM 前结构感知 + LLM 内查询条件；(2) 音视频协同压缩策略充分利用跨模态相关性；(3) 无训练自由，可即插即用于各种 Omni-LLM。

**局限性**：当前方法在极端压缩率（<7%）下性能下降较明显；音频与视频的比例参数需要针对不同任务调整；方法对 Transformer 架构有依赖性，其他架构的适用性待研究。
