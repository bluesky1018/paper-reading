> 📄 **论文**：GameCraft-Bench: Can Agents Build Playable Games End-to-End in a Real Game Engine?
> 🔗 **arXiv**：[2606.17861](https://arxiv.org/abs/2606.17861)
> 🏢 **机构**：CUHK-SZ、USTB、SJTU、NUS、SLAI、腾讯混元

## 一句话总结

GameCraft-Bench 是首个满足"引擎落地 + 完整制品 + 交互验证"三重要求的游戏生成基准，评估了 7 个前沿编程智能体，发现即使最强智能体也只能达到 41.46% 的整体得分——端到端游戏生成远未解决。

## 背景与问题

游戏生成是编程智能体的新兴应用：将自然语言规格说明转化为可玩的交互系统。与普通代码任务不同，游戏生成需要脚本、场景、资产、渲染和运行时交互协同产生连贯的游戏体验。

现有游戏生成基准存在明显缺陷：
- **OpenGame-Bench**：支持完整制品生成，但面向 Web 游戏而非真实引擎，不通过游戏交互评判质量
- **GameDevBench**：在真实引擎中评估，但只研究局部教程驱动的编辑，而非完整游戏构建
- 没有任何基准同时满足：真实引擎开发环境 + 完整可启动制品 + 交互式验证

本文提出三个评估**必要条件（Desiderata）**：
1. **引擎落地（Engine Grounding）**：在真实游戏引擎中开发，使用原生文档和资产
2. **制品完整性（Artifact Completeness）**：智能体必须提交可启动的完整游戏
3. **交互验证（Interactive Verification）**：通过实际玩家输入和游戏回放验证，而非静态代码检查

## 核心方法

![GameCraft-Bench总览](https://arxiv.org/html/2606.17861v1/figures/benchmark_title.png)
*图1：GameCraft-Bench 基准总览——140 个任务横跨 15 个游戏类别，在 Godot 引擎中评测*

**基准构建：**
- 平台：**Godot 游戏引擎**（真实生产级引擎）
- 规模：**140 个任务**，跨越 **15 个游戏类型**（卡牌游戏、平台跳跃、塔防、闲置游戏等）
- 每个任务包含自然语言游戏规格说明，覆盖游戏机制、进度系统、视觉呈现等

![评估框架五阶段流程](https://arxiv.org/html/2606.17861v1/x1.png)
*图2：五阶段评估流程——任务打包 → 智能体构建 → 验证检查 → 回放交互 → 评分打分*

**评估框架（五阶段流程）：**
1. **任务打包**：提供 Godot 环境、文档、共享资产
2. **智能体开发**：创建场景、编写脚本、配置输入、运行调试，迭代改进
3. **制品验证**：验证器检查是否能启动（失败则得分为 0）
4. **回放交互**：在固定 1280×720 视窗中回放鼠标键盘事件，录制游戏视频
5. **评分打分**：多模态 Judge 根据隐藏评分标准评估四个维度

**四个评分维度：**
- **核心机制（Core Mechanics）**：游戏的基本规则是否正确实现
- **内容深度（Content Depth）**：关卡、道具、进度等内容的丰富程度
- **功能视觉（Functional Visuals）**：视觉反馈是否正确响应交互
- **美术呈现（Art and Presentation）**：整体视觉质量和游戏感

![游戏示例展示](https://arxiv.org/html/2606.17861v1/x2.png)
*图3：GameCraft-Bench 中不同游戏类型的示例截图*

**提交合同：** 智能体必须提交完整的 Godot 项目（包含所有场景、脚本、资产、输入配置）和可回放的演示轨迹（记录鼠标键盘事件序列）。孤立的代码片段或不完整场景不计入得分。

## 实验结果

**评测智能体（7个前沿配置）：**
- Claude Code（Opus-4.7）
- Claude Code（MiMo-V2.5-Pro）
- Codex（GPT-5.5）
- Codex（DeepSeek-V4-Pro）
- Kimi Code（Kimi-K2.6）
- Code Buddy（GLM-5.1）
- Code Buddy（MiniMax-M2.7）

| 智能体配置 | 整体得分 |
|-----------|---------|
| 最强智能体 | **41.46%** |
| 多数智能体 | 显著低于 41% |

![各智能体性能对比](https://arxiv.org/html/2606.17861v1/x6.png)
*图4：各智能体在不同维度和游戏类型上的性能对比*

**关键发现：**
- 失分并非源于单一能力缺失，智能体在核心机制、内容深度、功能视觉、美术呈现四个维度**均表现欠佳**
- 性能在不同游戏类型间差异显著，说明当前智能体难以泛化适应多样化的游戏规格
- 多模态 Judge 与人类评分基本对齐，但在内容多样性和视觉呈现上人类评价稍严格

## 总结

GameCraft-Bench 填补了游戏生成评估的重要空白：通过在真实 Godot 引擎中的端到端评测，揭示了当前编程智能体的实际局限——它们往往能生成"游戏状"的代码片段，但在将完整规格说明转化为可玩、视觉连贯的真实游戏制品方面仍然存在显著差距。

这一发现对于 AI 辅助游戏开发具有重要意义：当前工具链可以辅助开发者完成局部任务，但自主的端到端游戏生成还需要在游戏引擎集成、长时序规划、运行时调试和多组件协调等方面取得更大突破。

局限性在于基准目前仅覆盖 Godot 引擎，且主要关注 2D 游戏类型；评分标准依赖 LLM Judge，在内容多样性和艺术质量维度的评估仍存在一定主观性。
