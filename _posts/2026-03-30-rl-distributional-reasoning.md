## 一句话总结

本文提出 **Multi-Answer RL**，通过强化学习训练语言模型在单次前向传播中同时生成多个合理答案及其置信度，从而突破传统后训练方法将答案分布坍缩为单一众数的局限，在医疗诊断、模糊问答、代码生成等任务上显著提升覆盖率、多样性和校准质量，同时将 token 消耗削减近一半。

---

## 背景与问题

### 标准后训练的根本缺陷

现代大语言模型（LLM）在后训练阶段（RLHF、RLVR 等）被优化为对每个问题给出**一个**最优答案。这在测试题这类单一正确答案的场景下没有问题，但在大量真实应用中却存在根本性的错配：

- **医疗鉴别诊断**：患者的症状可能同时对应多种疾病，医生需要给出完整的鉴别诊断列表，而非单一猜测。
- **模糊问答**：问题本身可能存在歧义，或者上下文信息不完整，存在多个同等合理的答案。
- **代码生成**：同一功能可以有多种正确实现方式，返回多个候选方案对用户更有价值。

现有解决"多样性"的方法（如多次采样、Best-of-N、集成学习）本质上是**事后补救**——模型本身仍然只会生成单个答案，多样性来自多次独立调用。这带来两个问题：

1. **计算冗余**：多次生成中存在大量重复的推理 token，同样的中间步骤被反复计算。
2. **缺乏校准**：模型无法在单次输出中对不同答案的可信度进行显式建模。

此外，强化学习中的**熵坍缩**（entropy collapse）问题已有文献记录——RL 训练天然倾向于压低输出的多样性，让模型越来越依赖单一高奖励路径。

### 已有工作的局限

- **RLVR**（基于验证的强化学习）：使用二元正确性奖励 `R = 1[y ≡ y*]`，只优化单答案正确性，不关注分布。
- **RLCR**（Damani et al., 2025）：联合优化正确性与校准，使用 Brier Score 作为校准奖励，但仍以单答案为基本单位。

两者均无法让模型学会在**一次**推理中覆盖答案空间的多个合理区域。

## 核心方法

### 问题形式化

将任务从"给定问题 x，找到单一答案 y*"重新定义为：

> 给定问题 x，找到**答案集合** Y*(x) = {y1*, y2*, ..., yN*}，其中 N 是真实有效答案的数量。

模型需要在单次前向传播中输出 K 个答案的集合 A = {a1, ..., aK}，以及（可选的）对应置信度 Q = {q1, ..., qK}。

![图1：标准RL（单答案）与Multi-Answer RL（答案分布）的概念对比](https://arxiv.org/html/2603.24844/x1.png)

### Multi-Answer RLVR

集合级别的奖励函数定义为已覆盖的正确答案数量：

```
R_RLVR^multi(A, Y*) = Σᵢ₌₁ᴷ 𝟏[aᵢ ∈ Y*]
```

同时引入**格式奖励**（format reward）来强制执行答案的唯一性，防止模型通过重复输出同一答案来刷分：

```
R_format(A) = 𝟏[所有 aᵢ 互不相同]
```

这个框架是单答案 RLVR 的自然推广，涵盖四种特殊情况：
- N=1, K=1：退化为标准 RLVR
- N=1, K>1：等价于 Pass@K
- N>1, K≤N：部分集合恢复
- N>1, K≥N：完整集合恢复

### Multi-Answer RLCR

在 Multi-Answer RLVR 基础上，要求模型为每个答案 aᵢ 额外输出置信度 qᵢ ∈ [0,1]。使用**Multi-Brier Score** 作为校准奖励：

```
R_Brier^multi(A, Q, Y*) = (1/K) Σᵢ₌₁ᴷ (qᵢ − 𝟏[aᵢ ∈ Y*])²
```

完整目标函数：

```
R_RLCR^multi = R_RLVR^multi − λ · R_Brier^multi
```

其中 λ 为惩罚系数，平衡覆盖率与校准精度。

**概率解释**：
- 当 N=1 时（单一真实答案），K 个置信度可以被解释为一个**离散概率分布**，qi 表示 ai 是正确答案的概率。
- 当 N>1 时（多个真实答案），输出对应一个**多元伯努利分布**，qi 是 ai 属于答案集合的边缘概率。

### 训练设置

- **基础模型**：Qwen3-8B
- **RL 算法**：GRPO（移除了标准差归一化以提高训练稳定性）
- **训练超参**：每个 prompt 采样 32 次响应，温度 0.7，批大小 1536，最大长度 1536 token，训练 1 epoch
- **硬件**：NVIDIA A100 和 H100 GPU

## 实验设计

### 数据集

| 数据集 | 任务类型 | K | 说明 |
|--------|----------|---|------|
| **DDXPlus** | 医疗鉴别诊断 | 3 | 多个同时成立的正确诊断 |
| **HotPotQA-Modified** | 模糊多跳问答 | 3 | 单一金标准答案，但上下文故意缺失以制造歧义 |
| **MBPP** | 代码生成 | 3 | 多种合法实现方式 |

### 对比方法（7个基线）

1. Base Model Zero-Shot
2. RLVR Single（标准提示，生成1个答案）
3. RLVR Single w/ Multi-Prompt（要求生成K个但用单答案目标训练）
4. **RLVR Multi**（本文方法）
5. RLCR Single（带校准，生成1个答案）
6. RLCR Single w/ Multi-Prompt
7. **RLCR Multi**（本文方法）

### 评估指标

**正确性指标：**
- Coverage（平均每个集合中正确答案数）
- Pass@1（Top-1 准确率）
- Token Efficiency（平均 token 数，越少越好）
- Uniqueness（生成答案的唯一性）

**校准指标：**
- Brier Score
- ECE（期望校准误差）
- Set ECE（集合级别的校准误差）

## 实验结果

### 正确性与效率（K=3）

**医疗诊断（DDXPlus）：**

| 方法 | 平均正确数 ↑ | 多样性 ↑ | Token数 ↓ | Top-1 ↑ |
|------|-------------|----------|-----------|---------|
| RLVR Single | 0.62 | 0.62 | 1191 | 0.50 |
| **RLVR Multi** | **0.79** | **1.00** | **677** | 0.42 |
| RLCR Single | 0.65 | 0.50 | 1378 | 0.55 |
| **RLCR Multi** | **0.77** | **1.00** | **510** | 0.43 |

**代码生成（MBPP）：**

| 方法 | 平均正确数 ↑ | 多样性 ↑ | Token数 ↓ | Top-1 ↑ |
|------|-------------|----------|-----------|---------|
| RLVR Single | 0.98 | 2.09 | 511.73 | 0.29 |
| **RLVR Multi** | **1.35** | **2.98** | **235.49** | **0.49** |
| RLCR Single | 0.89 | 2.13 | 518.07 | 0.27 |
| **RLCR Multi** | **1.38** | **2.94** | **250.94** | **0.48** |

代码生成任务上，Multi-Answer RL 将 Top-1 准确率提升超过 **50%**，同时将 token 消耗削减超过 **一半**。

![图2：DDXPlus（左）和MBPP（右）上Coverage vs. K的对比；以及等效采样预算下RLVR-Multi与RLVR-Single的对比](https://arxiv.org/html/2603.24844/x2.png)

### 校准结果

RLCR Multi 在 DDXPlus 和 MBPP 上的 Set ECE、Top-1 ECE 和 Brier Score 上均优于 RLVR Multi。

在 HotPotQA-Modified 上，RLCR Multi 虽然改善了 RLVR Multi 的校准，但 Top-1 表现略低于 RLCR Single。作者将此归因于模型学习到了一种隐性先验——将置信度强制归一化为 1（类似概率分布），而非将每个 qi 视为独立的伯努利概率。

![图3：DDXPlus上的校准曲线对比；RLCR-Multi（左）与RLVR-Multi（右），点的大小与每个桶中的样本数成正比](https://arxiv.org/html/2603.24844/x3.png)

### 多样性分析

在**等效采样预算**（共 30 个答案）的条件下进行对比：
- RLVR-Multi（10次推理 × 每次3个答案）
- RLVR-Single（30次独立推理 × 每次1个答案）

结果：RLVR-Multi 生成的**唯一答案数量几乎是后者的两倍**（平均 8 个 vs 4 个）。

这揭示了单答案方法的根本缺陷：即便多次独立采样，模型仍然倾向于反复生成相似的答案（因为它被训练为优化单一众数），而 Multi-Answer RL 训练模型主动探索答案空间的不同区域。

![图4：DDXPlus测试集5000个问题上每个问题唯一诊断数量的分布](https://arxiv.org/html/2603.24844/x4.png)

### Token 效率的深层原因

为什么 Multi-Answer RL 生成更少的 token？

作者通过分析 RLVR-Single 的多次采样发现：不同采样之间存在**大量的推理 token 重叠**（subsequence overlap）——模型在每次独立推理中重复相同的中间步骤。

![图5：RLVR-Single独立采样间的子序列重叠分析，揭示推理token的大量冗余](https://arxiv.org/html/2603.24844/x5.png)

Multi-Answer RL 迫使模型在单次推理中共享这些公共中间步骤，只在最后分叉出不同的答案，从而实现了自然的 token 压缩。

### K 值的扩展性

在 DDXPlus 上测试 K ∈ {2, 3, 4, 5}，训练稳定收敛，平均正确答案数随 K 单调增长，说明方法具有良好的扩展性。

![图6：RLVR-Multi在K∈{2,3,4,5}下的训练曲线，收敛稳定](https://arxiv.org/html/2603.24844/x6.png)

![图7：DDXPlus上RLVR和RLCR的Single vs. Multi方法平均token使用量对比](https://arxiv.org/html/2603.24844/x7.png)

![图8：RLVR-Single（30次采样）与RLVR-Multi（10×3）生成的唯一答案多样性词云对比](https://arxiv.org/html/2603.24844/x8.png)

## 关键洞察与讨论

### 为什么 Multi-Answer RL 能提升 Top-1 准确率？

直觉上看，让模型生成 K 个答案可能会"稀释"其对最佳答案的专注度，导致 Top-1 下降。但实验表明，在代码生成任务上 Top-1 反而提升了 50%+。

原因在于：生成多样化答案集合的训练压力迫使模型进行**更深入的问题理解**——它必须从多个角度思考问题，而非沿着单一高概率路径贪婪解码。这种更全面的理解反过来提升了单个答案的质量。

医疗诊断任务上 Top-1 略有下降（从 0.55 降至 0.43），说明任务特性有所不同：DDXPlus 的金标准是一组固定诊断，模型在追求集合覆盖率时可能牺牲了对"最可能单一诊断"的优化。

### 局限性

1. **单答案任务上的 Top-1 劣势**：当用户只需要一个最佳答案时，单答案目标仍然更有针对性。
2. **任务范围**：实验局限于问答类任务，开放式生成（如摘要、创作）的效果尚待验证。
3. **串行生成**：K 个答案在单次前向传播中串行生成，尽管比多次独立调用更高效，但无法并行化。
4. **校准的概率解释问题**：当 N>1 时，模型有时会错误地将置信度视为分布而非独立概率，需要更精细的提示设计或目标函数来区分这两种情形。

## 总结

本文的贡献可以从三个层面理解：

**技术层面**：提出了一个统一的集合级 RL 框架（Multi-Answer RLVR 和 Multi-Answer RLCR），通过集合覆盖奖励和唯一性格式奖励，直接将分布式推理能力嵌入模型参数中。

**工程层面**：在等效信息量下，将 token 消耗减少约 44-56%，这对于生产环境中的推理成本具有直接价值。

**认知层面**：揭示了标准 RL 后训练的一个根本偏差——它将"找到正确答案"等同于"找到唯一答案"，而本文论证了这两者在很多真实场景中并不等价。让模型学会"我不确定，这些都可能是答案"比让模型学会"我确定，只有一个答案"在某些场景下更诚实，也更有用。

这项工作为构建具有**认知不确定性意识**（epistemic uncertainty awareness）的语言模型提供了一条切实可行的路径，特别适用于医疗、法律、科学研究等高风险决策场景。
