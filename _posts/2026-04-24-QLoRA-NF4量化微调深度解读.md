## 基本信息

- **作者**: Tim Dettmers, Artidoro Pagnoni, Ari Holtzman, Luke Zettlemoyer
- **机构**: University of Washington
- **发表**: NeurIPS 2023 (Oral)
- **arXiv**: [2305.14314](https://arxiv.org/abs/2305.14314)

## 一句话总结

提出 **QLoRA**——把"量化 + LoRA 微调"两条路线彻底整合,让**单张 48GB GPU 就能微调 65B 模型**,质量与全精度 16-bit 微调不可区分。三个核心创新:**NF4 (NormalFloat4)** 数据类型(理论上对正态分布最优的 4-bit 量化)、**Double Quantization**(把量化常数自己也量化一次省显存)、**Paged Optimizer**(用 Nvidia Unified Memory 处理 optimizer state 溢出)。用这套组合微调出的 **Guanaco** 在 Vicuna benchmark 上达到 ChatGPT 99.3% 的水平——**单 GPU、24 小时训练**。QLoRA 是个人和小团队微调大模型的事实标准。

## 背景:微调大模型为什么这么贵

### 微调的显存成本

对 65B 模型做 full fine-tuning:

- **Weight**:130 GB(FP16)
- **Gradient**:130 GB
- **Optimizer state (AdamW)**:260 GB(一阶 + 二阶矩,都 FP32)
- **Activation**:数十 GB(取决于 batch/seq)

**总计约 >780 GB**——需要 **10+ 张 A100-80GB**。一次微调成本动辄几千美元。

### LoRA(Low-Rank Adaptation)的贡献

LoRA(Hu 2021)提出:不更新 $W$,只更新一个**低秩补丁** $\Delta W = BA$,其中 $A \in \mathbb{R}^{r \times d}, B \in \mathbb{R}^{d \times r}$,$r$ 很小(如 16)。

$$
W' = W + BA,\quad \text{only train } A, B
$$

- Trainable 参数量从 65B 降到 ~0.1%(65M)
- Optimizer state 相应降到 ~1 GB
- **但 base weight 还是要 16-bit 保留**——仍然 130 GB

LoRA 省了 gradient / optimizer,没省 weight。QLoRA 的目标:**也把 weight 的显存压下来**。

## 核心创新一:NF4 数据类型

### 4-bit 量化的挑战

4-bit 只有 16 个 code words。对权重分布做 INT4 量化时,精度浪费在"稀有"的数值点上——而 LLM 的权重**近似服从标准正态分布** $\mathcal{N}(0, \sigma^2)$。

### NF4 的思想:分位数量化

NormalFloat4 的设计:**让 16 个 code words 在正态分布的 16-quantile 处**——每个 code word 在分布中代表等概率的一段。

具体:对 $\mathcal{N}(0, 1)$ 的 CDF $\Phi$:

$$
q_i = \Phi^{-1}\!\left(\frac{i}{17}\right),\quad i = 1, \ldots, 16
$$

得到 16 个非均匀分布的 code words:在 0 附近密集,在尾部稀疏——**与权重的实际分布匹配最好**。

![NF4 vs INT4:INT4 均匀分布在 [-1, 1],NF4 在 0 附近密集尾部稀疏。对正态分布权重,NF4 的量化误差显著小于 INT4。](/assets/img/qlora/x2.png)
_Figure 2:NF4 与 INT4 的 code word 分布对比_

### 信息论最优

作者证明:**对固定 bit 宽度,分位数量化是 information-theoretically optimal 的**。NF4 对真实 LLM 权重的量化误差比 INT4 / FP4 小 30-50%。

### 零点对称

NF4 还保证 0 是一个 code word(**准确存储零权重**),这对 sparse 权重特别重要。

## 核心创新二:Double Quantization

### 问题:量化常数自己也占显存

Block-wise 量化为每 64 个 weight 存一个 FP32 scale。对 65B 模型:

- 权重:65B × 4-bit = 32.5 GB
- Scale:65B / 64 × 32-bit = **4 GB**

4 GB 看起来不多,但对"能不能塞下 48GB 卡"至关重要。

### 解法:Scale 也量化

Double Quantization 做两次量化:

1. **第一层**:把权重按 64 一组量化为 NF4,每组一个 FP32 scale $c_2$
2. **第二层**:把 $c_2$ 再按 256 一组量化为 FP8,每组一个 FP32 scale $c_1$

最终每个 weight 的平均 overhead 从 0.5 bit 降到 **0.127 bit**——省了约 75% 的 scale 存储。

![Double Quantization 的块结构:每层的 quantization constants 自身再被量化一次,scale overhead 从 0.5 bit/weight 降到 0.127 bit/weight。](/assets/img/qlora/x3.png)
_Figure 3:Double Quantization 的两层块结构_

65B 模型 scale 从 4 GB → **~1 GB**,省的 3 GB 在 48GB 卡上是关键差别。

## 核心创新三:Paged Optimizer

### 问题:Optimizer state 突然暴涨

LoRA 的 optimizer state 虽然小(~2 GB for 65B+LoRA),但训练中偶尔遇到长序列 batch 时,activation memory 突发上涨,可能 OOM。

### 解法:Unified Memory Paging

用 **CUDA Unified Memory (UVA)** 把 optimizer state 放在可分页的内存——平常在 GPU,显存紧张时自动 page out 到 CPU RAM。

这像 OS 的虚拟内存机制——**用延迟换稳定**。发生溢出时训练不挂,只是这一步慢一点。

## 训练流程

![QLoRA 的训练:前向时 4-bit 权重 dequant 到 BF16 参与计算,LoRA adapter 加到输出上。反向时只给 adapter 计算梯度,4-bit base weight 完全冻结。](/assets/img/qlora/x4.png)
_Figure 4:QLoRA 前向和反向传播_

1. **Load**:base model 用 NF4 + Double Quantization 加载
2. **LoRA**:在每个 linear layer 加 BF16 的 LoRA adapter($r = 64$ 典型)
3. **Forward**:对每个 linear,NF4 权重 → BF16 dequant → 参与矩阵乘 → 加上 LoRA 输出
4. **Backward**:只反向传播到 LoRA adapter(梯度不流入 4-bit base)
5. **Update**:AdamW 更新 LoRA adapter 的 BF16 参数
6. **Optimizer state**:Paged Optimizer 自动管理显存

## 实验结果

### 质量:与 FP16 全量微调等效

![各量化方案的微调质量对比:FP16 full / LoRA / QLoRA 的下游任务准确率几乎重合。Int4 LoRA(非 NF4)明显掉分。](/assets/img/qlora/x5.png)
_Figure 5:QLoRA vs FP16 LoRA——质量几乎一致_

在 Alpaca、FLAN、Self-Instruct 等 instruction tuning 数据集上:

| 配置 | LLaMA-65B fine-tune | GPU 需求 | 训练时间 |
|------|---------------------|---------|----------|
| FP16 full | baseline MMLU 63.2 | 16× A100 | ~1 周 |
| FP16 LoRA | MMLU 63.1 | 8× A100 | ~3 天 |
| **QLoRA (NF4)** | **MMLU 63.0** | **1× A6000 48GB** | **24 小时** |

**质量差距 < 0.2 分,资源需求降低 16×**。

### Guanaco:ChatGPT 的 99.3%

用 QLoRA 在 65B LLaMA 上对 OASST1 数据集微调 24 小时,得到 **Guanaco-65B**:

- Vicuna benchmark:达到 ChatGPT 的 **99.3%**
- 只用 **1 张 A100-80GB 或 2 张 RTX 6000** 训练

这证明:**微调质量不受 4-bit 量化影响**——量化的误差被 LoRA adapter 吸收了。

## 工程影响

### 1. 让微调大模型民主化

QLoRA 发布前:微调 65B 需要几万美元。发布后:**150 美元预算的 A6000 租赁 + 24 小时 = 世界级 65B 模型**。整个 open-source LLM 社区的微调门槛掉到个人可承担。

### 2. 引爆 instruction tuning 社区

2023 年下半年爆发的数百个 chat / instruction 模型(Vicuna、WizardLM、Zephyr、Mistral-Instruct、各种角色扮演模型等)几乎全部用 QLoRA 训练。**QLoRA 几乎是 2023-2024 年开源指令微调的默认方案**。

### 3. 推动 PEFT 生态

HuggingFace 的 [PEFT](https://github.com/huggingface/peft) 库把 QLoRA 集成为**一行代码**:`load_in_4bit=True`。从此 LoRA / QLoRA / DoRA / VeRA 等各种 parameter-efficient fine-tuning 技术在同一个框架下蓬勃发展。

### 4. 启发"量化无损微调"理论

QLoRA 实证上证明:**4-bit 基座 + 小适配器的微调质量 = FP16 全量微调**。这让学界重新思考"模型的有效表达能力究竟需要多少 bit"——后续 1.58-bit (BitNet)、2-bit 训练等更激进的尝试部分受此鼓励。

## 局限

### 1. Inference 时仍需 dequant

QLoRA 的推理**每次都要把 NF4 dequant 成 BF16**参与矩阵乘。这比 pure INT4 推理(AWQ / GPTQ + Marlin kernel)慢 2-3×——QLoRA 是"训练友好"而不是"推理友好"的格式。

### 2. LoRA 本身的局限

- $r$ 太小表达力不够(某些复杂任务需要 $r \geq 128$)
- 基座权重冻结,某些低层特征无法更新

### 3. NF4 对非正态权重可能次优

某些 attention 层的权重分布可能偏态 / 重尾,NF4 的"正态假设"不完全准。

### 4. Double Quantization 的 overhead

Double Quantization 省显存但**稍增加 dequant 时间**(~5% 速度损失)。生产部署可选择性启用。

## 读完这篇你真正该带走的 4 件事

<callout emoji="white_check_mark" background-color="light-green" border-color="green">
1. **"冻结 4-bit 基座 + 可学低秩 adapter"是无损微调范式**:这个组合在数学上是因为 LoRA 空间足够大,吸收了 4-bit 量化的误差。理解这一点就理解了为什么 QLoRA 不掉分
2. **分位数量化(NF4)优于均匀量化(INT4)**:让 code words 匹配权重的真实分布,比硬塞入均匀网格误差更小——这个思想在其他需要量化的场景(如 activation、gradient)也值得借鉴
3. **量化常数自己也是量化对象**:Double Quantization 把 "meta data" 二次量化——这种"递归压缩"思路在 compression 领域有很长历史,QLoRA 第一次把它用到 LLM 微调
4. **Paged Optimizer 把 OS 的内存管理搬到 GPU**:与 PagedAttention 异曲同工,再次证明系统思想可以救 GPU 训练/推理的内存危机
</callout>
