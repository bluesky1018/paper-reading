> 📄 **论文**：MerchantBench: Benchmarking LLM Agents for Long-Term Coherence in E-Commerce Operations
> 🔗 **arXiv**：[2607.28956](https://arxiv.org/abs/2607.28956)
> 🏢 **机构**：阿里巴巴集团、浙江大学等

## 一句话总结
MerchantBench 是首个面向电商场景"长期一致性"评估的 LLM 智能体基准，基于真实98,843条商品数据构建365天订单级仿真环境，揭示了当前最先进LLM与人类参与者之间存在巨大差距。

## 背景与问题

大型语言模型（LLM）智能体已被广泛用于自主工具调用、规划与决策，现有基准主要聚焦于有明确终止条件的任务（如网页交互、应用控制等）。然而，现实部署往往要求智能体具备"**长期一致性（Long-Term Coherence）**"——即在延伸的时间跨度内保持目标导向行为，并根据积累的证据不断调整决策。

评估这种能力需要一个**持久化环境**：历史动作约束未来选择、反馈在不同延迟后才到来、非一致行为会产生可量化的累积影响。卖家侧电商运营恰好满足这些要求——它涵盖周期性的商品采购、上架定价、现金流管理和混合延迟的反馈适应等高度相互依赖的决策链条。

现有电商基准仅关注短时交互（如单次购物、客服对话），无法评估智能体在长达一年的真实运营场景中是否能保持策略一致性。

## 核心方法

### MerchantBench 框架

MerchantBench 建立在真实1688批发市场的98,843条商品数据之上，模拟完整的365天订单周期（8,760个小时步），构成一个**有限视野部分可观测马尔可夫决策过程（POMDP）**：

$$\mathcal{M}=\langle\mathcal{S},\mathcal{A},P,\mathcal{O},Z,R,\mu_{0},H_{c}\rangle$$

智能体通过26个工具与环境交互，需协调四大核心决策模块：

| 模块 | 描述 |
|------|------|
| **商品采购（Product Sourcing）** | 根据每日市场报告选择商品上架 |
| **上架与定价控制** | 动态调整价格以适应市场竞争 |
| **现金流管理** | 平衡进货成本与订单结算的时间差 |
| **混合延迟反馈适应** | 处理上游供应商事件与下游订单结果之间的延迟差异 |

![MerchantBench 总体框架](https://arxiv.org/html/2607.28956v1/x2.png)
*图1：MerchantBench 整体架构。商家智能体通过上游供应商模拟和下游订单级仿真协调四类决策，在365天内应对即时供应商事件和延迟的订单结果。*

### 环境设计

**上游供应商模拟**：包含动态变化的采购价格、库存可用性和到货时间，并模拟三类突发事件：价格变动、产品下架、发货延迟。

**下游订单仿真**：将产品级日需求转化为个体订单，需求由真实历史数据标定：

$$\lambda_{m,i,t}=D_{i,d(t)}w_{c(i),h(t)}r_{m,t}\ell_{m,i,t}(p_{m,i,t}/p_{i}^{\mathrm{ref}})^{-\epsilon_{i}}$$

![订单级动态耦合](https://arxiv.org/html/2607.28956v1/x1.png)
*图2：订单级动态将即时流动性压力与延迟反馈相耦合。新订单在结算前预占可用现金，而异常结果（如退款）会更晚显现并影响店铺评分。*

![真实需求模式](https://arxiv.org/html/2607.28956v1/x3.png)
*图3：98,843件商品的真实世界需求模式和标定风险分布。须状线覆盖第10至第90百分位，箱型图显示四分位距。*

## 实验结果

### 实验配置

评估了8个LLM在两种智能体框架（ReAct 和 Hermes）下的表现，共48次运行：

| 模型 | 框架 |
|------|------|
| GPT-5.6 Sol | ReAct / Hermes |
| Claude Opus 4.8 | ReAct / Hermes |
| Qwen3.7-Max / Plus | ReAct / Hermes |
| GLM-5.2 | ReAct / Hermes |
| DeepSeek-V4-Pro / Flash | ReAct / Hermes |
| Kimi K2.6 | ReAct / Hermes |

### 主要发现

**核心结论**：最优LLM配置（Qwen3.7-Max + Hermes）仅实现人类参与者平均最终净资产的 **27.3%**，揭示出当前LLM在长期一致性上的显著差距。

- **ReAct框架**：GPT-5.6 Sol 最终净资产最高，变异系数仅3.3%（最稳定）
- **Hermes框架**：Qwen3.7-Max 最终净资产最高，但波动性较大
- 跨框架均值：GPT-5.6 Sol 综合表现最佳

### 失效模式分析

轨迹分析揭示了LLM智能体的三类典型失效模式：
1. **运营活跃度下降**：随时间推移，工具调用减少，决策窗口利用率降低
2. **过早放弃目标**：无充分证据下停止关键运营操作
3. **策略跳变**：在缺乏充分证据支撑的情况下频繁调整策略方向

## 总结

MerchantBench 填补了现有 LLM 智能体评测在长期一致性方面的空白，通过真实电商数据构建了高度可信的测试环境。实验结果表明，即使是最先进的 LLM，在需要跨越数百个决策步骤、处理延迟反馈和维持策略连贯性的任务中，仍与人类水平存在巨大鸿沟。

**主要贡献**：(1) 提出长期一致性这一新评估维度；(2) 构建365天订单级电商仿真环境；(3) 识别LLM智能体的具体失效模式，为改进方向提供参考。

**局限性**：评估场景聚焦于中国电商平台（1688），跨文化泛化能力有待验证；此外，365天仿真对计算资源要求较高。
