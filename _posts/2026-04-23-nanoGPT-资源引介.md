## 基本信息

- **作者**: Andrej Karpathy
- **类型**: 开源代码仓(MIT License)
- **仓库**: [karpathy/nanoGPT](https://github.com/karpathy/nanoGPT)

## 一句话总结

一个**极简、可读、可训、可复现**的 GPT 实现。整个 `model.py` 大约 300 行,训练脚本几十行,就能在单张 GPU 上训练出一个 GPT-2 级别的小模型。定位是 "**让你真正读懂一个 decoder-only Transformer 的每一行**",而不是生产框架。karpathy 本人也拿它来做教学视频 *Let's build GPT*(YouTube 2 小时,配套本仓库)。

## 为什么值得 clone 下来看

现代 Transformer 代码库(HuggingFace、Megatron、FSDP 等)加了太多工程细节:
- 分布式并行
- 混合精度 + gradient checkpointing
- 各种 attention 变体的 dispatcher
- 千层继承 / config 抽象

这些都是生产必需,但**掩盖了 Transformer 的本来面目**。nanoGPT 反其道而行:**不抽象、不泛化、不考虑部署**,只把 GPT 的核心计算写出来。结果就是一个可以**整体读完**的仓库——这在现代 ML 代码里非常罕见。

## 仓库结构(4 个文件就是核心)

- `model.py` —— GPT 模型定义(MultiHeadAttention + MLP + block)
- `train.py` —— 训练 loop(AdamW + LR schedule + eval + save)
- `sample.py` —— 推理 loop(prompt → generate tokens)
- `configurator.py` —— 轻量 config 覆写工具

数据准备脚本 `data/shakespeare/prepare.py` 把文本转成 bin,就是所有"数据 pipeline"。

## 使用场景

- **第一次想真正读懂 Transformer 代码**:从 `model.py` 开始,读一两小时就能理解因果 mask、多头、positional embedding、LayerNorm 位置等每个细节
- **手写每一种 attention 变体的 toy 版**:clone 一份,把 MHA 换成 GQA / MQA / RoPE / FlashAttention / MLA,都能在 < 50 行 diff 内完成,还能训出来验证
- **做小规模消融实验**:研究者常用它跑 ≤ 125M 的 small-scale 实验,验证某个假设再去上大模型
- **教学**:karpathy 的 *Let's build GPT* 视频完全基于这个仓库,是入门教材

## 何时不该用

- 训**百亿参数**以上模型:缺分布式、缺 FSDP、缺训练稳定性 hacks
- 部署到生产环境:缺 serving、量化、batching、streaming
- 研究 novel attention 架构**到 scaling law 级别**:单机规模验证有限

以上场景切到 Megatron / GPT-NeoX / HuggingFace Trainer / vLLM 更合适。

## 值得学的工程实践

- **配置极简**:用 Python 脚本直接 override 全局变量,而不是 Hydra/YAML 嵌套
- **数据预处理单文件**:每个数据集一个 `prepare.py`,bin 格式直接 mmap 进训练,IO 极快
- **Eval 集成在 train.py**:不用 callbacks / hooks,直接 inline
- **测试方式**:rev-match 与 HuggingFace GPT-2 权重加载,确认数值完全一致

这套"**简单 > 灵活**"的工程哲学,非常适合 AI 研究个人仓库参考。
