## 一句话总结

SPPO 将长链推理任务从 Token 级 MDP 重新建模为**序列级上下文赌博机（Sequence-Level Contextual Bandit）**，用一个轻量标量价值函数替代传统 PPO 的 Token 级 Critic，在单次采样（N=1）条件下实现了比 GRPO（N=8）更高的性能与吞吐量。

---

## 背景与问题

### PPO 在长推理任务中的困境

将强化学习（RL）应用于大语言模型（LLM）推理能力训练已成为主流范式，其中 PPO（Proximal Policy Optimization）是最具代表性的算法之一。然而当推理轨迹（Chain-of-Thought，CoT）变得极长时，标准 Token 级 PPO 会遭遇两个根本性问题：

**1. 信用分配失效（Credit Assignment Failure）——"尾效应"**

在稀疏奖励场景下（仅在序列末尾给出 0/1 奖励），PPO 依赖 GAE（Generalized Advantage Estimation）在每个 Token 时间步计算优势值：

$$\hat{A}_t^{GAE} = G_t - V(s_t)$$

理想情况下，Critic 应在整条推理链上准确估计每个中间状态的价值。但实验发现，Token 级 Critic 会过度拟合序列末尾的语义线索（如"答案为……"等结束标志），导致优势信号在序列中段几乎消失，形成所谓的**"尾效应（Tail Effect）"**。

下图展示了这一现象——正确轨迹（蓝色）与错误轨迹（红色）的 $V(s_t)$ 曲线在序列绝大部分位置都高度重叠，仅在最后几个 Token 处才出现分叉：

![尾效应示意图：Token级Critic仅在序列末尾区分正确与错误轨迹](https://arxiv.org/html/2604.08865/x1.png)

**2. 显存开销巨大**

传统 PPO 需要维护一个与策略模型同等量级的 Critic 网络，当策略模型达到 7B 甚至更大规模时，显存占用将成倍增加，严重限制了可训练的批大小和吞吐量。

### GRPO 的优势与局限

为了规避上述问题，GRPO（Group Relative Policy Optimization）通过**组内归一化**计算优势值，完全去除了 Critic 网络：

$$\text{Adv}(s_p, a) = \frac{R - \mu_g}{\sigma_g}$$

其中 $\mu_g$ 和 $\sigma_g$ 分别是同一 Prompt 下 N 个采样答案奖励的均值与标准差。这种方式天然具有对 Prompt 难度的适应性——GRPO 实际上已经在隐式地将整条响应视作一个原子动作（即上下文赌博机），而非 Token 级 MDP。

然而 GRPO 的代价是**必须每个 Prompt 采样 N 次**（通常 N=8）。这导致：
- 吞吐量下降约 5.9 倍（相比 N=1）
- 无法充分利用单次高质量轨迹中的学习信号

### 核心观察：GRPO 的本质是上下文赌博机

论文作者通过推导（详见附录 A）发现：在 Bernoulli 奖励假设下，GRPO 的优势函数等价于：

$$\text{Adv} = \begin{cases} \sqrt{\frac{1-\hat{p}}{\hat{p}}} & R=1 \\ -\sqrt{\frac{\hat{p}}{1-\hat{p}}} & R=0 \end{cases}$$

其中 $\hat{p}$ 是对 Prompt $s_p$ 可解概率的估计。下图直观展示了 GRPO 优势值与 Prompt 难度的关系——本质上，GRPO 已经将问题建模为一个以 Prompt 为上下文、整条响应为动作的**上下文赌博机**：

![GRPO优势值与Prompt难度的关系，揭示其隐式的赌博机建模本质](https://arxiv.org/html/2604.08865/x2.png)

## 核心方法

### SPPO 的形式化建模

SPPO 将推理任务显式地建模为**序列级上下文赌博机**，元组定义如下：

- **上下文 S**：仅包含静态 Prompt $s_p$
- **动作 A**：整条响应序列 $a_{seq} = (y_1, \ldots, y_T)$ 作为一个整体单元
- **奖励 R**：整条响应的整体正确性 $r(s_p, a_{seq})$

这一建模将时间视野压缩为 $H=1$，彻底消除了 Token 级信用分配的需求。价值函数因此简化为对 Prompt **可解性（solvability）的标量估计** $V(s_p)$，与具体响应内容无关。

下图展示了 SPPO 的整体架构——轻量标量 Critic $V_\phi(s_p)$ 与策略模型解耦，为整条响应提供统一的优势信号：

![SPPO整体架构：解耦标量价值模型与序列级优势计算](https://arxiv.org/html/2604.08865/x3.png)

### 价值函数训练

Critic $V_\phi(s_p)$ 使用**二元交叉熵（BCE）损失**训练，预测给定 Prompt 的可解概率：

$$\mathcal{L}_V(\phi) = -\mathbb{E}\left[R \cdot \log V_\phi(s_p) + (1-R) \cdot \log(1 - V_\phi(s_p))\right]$$

优势值计算简洁直观：

$$A(s_p, a) = R - V_\phi(s_p)$$

这意味着：
- 对于困难 Prompt（$V_\phi \approx 0.5$）上的正确答案 → 较强正向激励
- 对于简单 Prompt（$V_\phi \approx 0.8$）上的错误答案 → 较强负向惩罚
- 自然实现了难度自适应的奖励归因

### 策略优化目标

SPPO 的策略目标沿用 PPO 的 Clipped Surrogate 形式，但将**同一序列级优势值广播至所有 Token 位置**：

$$J_{SPPO}(\theta) = \mathbb{E}\left[\min\left(r_t(\theta) \cdot A(s_p, a), \text{clip}(r_t(\theta), 1-\varepsilon, 1+\varepsilon) \cdot A(s_p, a)\right)\right]$$

正确推理链中的所有 Token 获得等量正向强化，错误推理链中的所有 Token 获得等量负向惩罚。这从根本上消除了尾效应——优势信号不再依赖 Token 位置，而是由整体正确性决定。

### 解耦 Critic 策略（Decoupled Critic）

论文进一步提出了一种**异构 Critic 策略**：用较小的 1.5B 模型作为 Critic 指导较大的 7B 策略模型训练。

这一策略的合理性在于：**标量可解性估计在本质上远比生成式推理简单**，一个小模型完全有能力判断"这个问题大概率能解出来吗"，却不一定能生成完整的解题过程。

实测效果：7B 策略 + 1.5B Critic 组合相比 7B+7B 同构设置减少约 **12.8% 的显存占用**，且性能不降反升。

## 实验结果

### 实验配置

- **模型**：DeepSeek-R1-Distill-Qwen-1.5B 和 7B
- **训练数据**：DeepScaleR（1.5B）、DAPO-17K（7B）
- **评估指标**：Average@16，覆盖 AIME24、AIME25、AMC23、MATH500、Minerva Math
- **基线方法**：标准 PPO、ReMax、RLOO、GRPO（N=8）
- **训练框架**：verl 库
- **硬件**：4×A100（1.5B），4×H100（7B）

### 主要结果

| 方法 | AIME24 | AIME25 | AMC | MATH | Minerva | 平均 |
|------|--------|--------|-----|------|---------|------|
| **1.5B 基础模型** | 27.50 | 21.67 | 71.56 | 83.73 | 20.35 | 44.96 |
| PPO | 27.50 | 20.83 | 70.63 | 81.38 | 19.89 | 44.06 |
| ReMax | 31.67 | 25.42 | 71.88 | 84.38 | 20.40 | 46.74 |
| RLOO | 30.42 | 21.67 | 72.81 | 84.10 | 21.73 | 46.15 |
| GRPO（N=8） | 30.00 | 26.25 | 73.13 | 83.88 | 22.15 | 47.08 |
| **SPPO** | **34.17** | 25.83 | **74.38** | 83.78 | 22.15 | **48.06** |
| **7B 基础模型** | 41.25 | 26.67 | 79.38 | 87.20 | 27.94 | 52.49 |
| PPO | 45.20 | 35.42 | 85.31 | 88.48 | 27.80 | 56.44 |
| GRPO（N=8） | 47.08 | 35.00 | 86.25 | 90.15 | 28.74 | 57.44 |
| **SPPO** | 50.83 | 35.00 | 86.25 | 90.13 | 28.35 | 58.11 |
| **SPPO + 小 Critic** | **52.29** | 34.58 | **87.19** | 89.88 | **28.86** | **58.56** |

SPPO 在两个模型规模上均超越了 GRPO（N=8），且仅需 N=1 的单次采样。7B 策略 + 1.5B Critic 的解耦配置达到了最高综合平均分。

### 损失函数消融实验

为了厘清 SPPO 的增益究竟来自"序列级赌博机建模"还是仅来自"BCE 损失"，论文设计了"PPO + BCE"消融实验——将 BCE 损失套用在 Token 级框架上。

结果如图所示：PPO+BCE 同样出现性能崩溃，与标准 PPO 的表现相近，两者均在 500 步因性能崩溃被提前终止。这有力地证明 SPPO 的核心增益来自**赌博机建模本身**，而非 BCE 损失：

![损失函数消融：PPO+BCE同样崩溃，证明SPPO增益来自赌博机建模](https://arxiv.org/html/2604.08865/x4.png)

### Critic 校准分析

为评估 Critic 的预测质量，论文对 200 个 Prompt 计算了 AVG@64 的实证通过率，并与 Critic 预测值作散点对比：

![Critic校准：预测概率vs实证通过率，Pearson r=0.642](https://arxiv.org/html/2604.08865/critic.png)

主要发现：
- **Pearson r = 0.642，Spearman ρ = 0.664**——Critic 与实际难度有显著正相关
- 实证分布呈双峰（0 或 1），而 Critic 预测近似正态分布，中心约在 0.6–0.7 处
- Critic 整体偏保守（"回归均值"），但这种偏差在优化中是有益的——困难问题上偶尔的正确答案会获得较强激励

### RLVR 控制任务基准

为了在排除分布式训练干扰因素的条件下验证算法本身的有效性，论文将 5 个经典控制任务改造为稀疏二值奖励（$\gamma=1.0$）场景：

| 任务 | 时间步数 | 成功标准 |
|------|---------|---------|
| 精准 CartPole | H=200 | 末态角度 |θ| ≤ 0.5° |
| MountainCar | H=1000 | x ≥ 0.45 |
| Hopper（MuJoCo） | H=1000 | 存活 + 前进 > 1.0m |
| LunarLander | H=1000 | 稳定着陆，|x| < 0.4 |
| Pendulum | H=1000 | cos θ > 0.8 |

下图展示了 5 个任务上 SPPO 与标准 PPO 的对比：

![RLVR控制任务：SPPO（蓝色）在Hopper、MountainCar等高难度任务上稳定收敛，PPO崩溃](https://arxiv.org/html/2604.08865/x7.png)

关键发现：标准 PPO 在 Hopper 和 MountainCar 上完全无法收敛（Token 级 Critic 无法在长时间稀疏奖励下传播信号），而 SPPO 通过序列级可解性估计稳定解决了所有任务。

## 深度分析：为什么这个方法有效？

### 1. 建模层面的根本矫正

标准 PPO 将文本生成建模为 Token 级 MDP，但推理任务的奖励是**整体性的**——一条正确的推理链如果中途一个 Token 替换为同义词，奖励不会变化。这种奖励结构与 Token 级 MDP 本身就是不匹配的。SPPO 通过显式承认这一点，将建模单元与奖励粒度对齐，从根本上解决了信用分配问题。

### 2. 方差-偏差权衡的优化

- 标准 PPO：高偏差（Critic 拟合失败）+ 低方差（单次采样）
- GRPO（N=8）：低偏差（组归一化准确）+ 高方差（依赖多次采样）
- **SPPO**：低偏差（标量可解性易于学习）+ 低方差（单次采样即可）

### 3. Critic 解耦的理论支撑

"判断一道题能不能解" 远比 "解这道题" 容易。用小模型做前者，用大模型做后者，这种任务解耦符合直觉，也得到了实验的有力支撑。

## 总结

SPPO 是一篇思路清晰、实验扎实的工作。它的核心贡献不是一个复杂的新算法，而是一个**建模视角的根本转变**：将长链推理任务从 Token 级 MDP 重新定义为序列级上下文赌博机。这一转变带来了：

- **优化稳定性**：彻底消除尾效应，整条序列获得统一的正确优势信号
- **高吞吐量**：N=1 单次采样，约 5.9× 吞吐量提升相比 GRPO（N=8）
- **显存效率**：解耦 Critic 策略节省 ~12.8% 显存，且性能更优

**局限性**：SPPO 依赖可验证的结果奖励，目前难以直接扩展至没有明确答案验证器的开放式生成任务。

对于研究者而言，SPPO 提供了一个重要启示：**当任务结构本身不符合 MDP 假设时，与其在 MDP 框架内打补丁，不如直接换一个更合适的框架。**
