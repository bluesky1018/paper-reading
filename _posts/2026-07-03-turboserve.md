> 📄 **论文**：TurboServe: Serving Streaming Video Generation Efficiently and Economically
> 🔗 **arXiv**：[2606.19271](https://arxiv.org/abs/2606.19271)
> 🏢 **机构**：上海交通大学、生数科技、清华大学

## 一句话总结

TurboServe 是首个专为流式视频生成负载设计的服务系统，通过迁移感知的会话放置与负载驱动的 GPU 自动扩缩容相结合，相比基线将最坏情况 Per-Chunk 延迟降低 37.5%，总 GPU 运营成本降低 37.2%。

## 背景与问题

当前视频生成服务系统（如 FastVideo、xDiT、vLLM-Omni 等）主要针对**无状态、一次性生成请求**优化——每个请求独立调度、独立分配资源、完成即释放。然而，**流式视频生成**打破了这一假设：用户对应**持久化会话**，模型需要在保留上下文与缓存时序状态（KV Cache 等元数据）的同时，持续接收新的提示词或交互信号，交替经历"活跃生成"与"用户空闲"阶段。

![有状态会话 vs 无状态请求](https://arxiv.org/html/2606.19271v1/x1.png)
*图1：无状态一次性生成（上）与有状态流式生成会话（下）的对比。流式生成需要在跨空闲期间保持会话状态。*

这带来两大核心挑战：

1. **会话时长异质性**：不同会话的持续时间差异悬殊（从单段短视频到数十分钟的迭代生成），初始均衡的放置方案随着长时会话的积累会逐渐失衡，导致某些 GPU 成为瓶颈。

2. **时序用户需求异质性**：用户交替处于活跃与空闲状态，系统级活跃会话数随时间剧烈波动。静态 GPU 配置在低需求期浪费资源、在高需求期造成延迟超标，面临根本性的权衡困境。

![流式视频生成负载特征](https://arxiv.org/html/2606.19271v1/x2.png)

## 核心方法

TurboServe 将服务问题形式化为**在线调度问题**，联合协调会话放置与 GPU 弹性配置。

### 动机分析

研究团队通过三组对照实验揭示了三个关键洞察：

- **洞察1（会话迁移减少瓶颈延迟）**：仅引入周期性会话迁移，最坏情况 Per-Chunk 延迟降低 26.53%
- **洞察2（自动扩缩容提升资源效率）**：仅引入动态 GPU 配置，总 GPU 成本降低 32.57%
- **洞察3（两者应协同设计）**：联合策略中，迁移使负载信号更准确从而提升扩缩决策质量；扩缩时的重均衡使新 GPU 立即被充分利用

### 系统架构

TurboServe 由四个核心组件构成：

![TurboServe 系统概览](https://arxiv.org/html/2606.19271v1/x5.png)
*图4：TurboServe 系统架构。闭环调度器通过放置控制器、自动扩缩容控制器与会话管理器实现对会话和 GPU 资源的联合管理。*

1. **负载检测器（Workload Detector）**：利用滑动窗口监控近期会话事件，提取需求量与需求变化率等负载信号。

2. **放置控制器（Placement Controller）**：执行**迁移感知的重均衡**，通过将会话从过载 GPU 迁移至轻载 GPU 来降低最大 Per-GPU 负载（即最坏情况延迟）。迁移通过 NCCL GPU-GPU 传输实现，保证会话状态的在线安全迁移。

3. **自动扩缩容控制器（Autoscaling Controller）**：根据运行时的负载、利用率和 Per-Chunk 延迟反馈动态调整 GPU 预算，在高需求期扩容、低需求期缩容。

4. **会话管理器（Session Manager）**：跟踪会话生命周期（执行、挂起、恢复、迁移），通过 **GPU-CPU 状态卸载**机制将空闲会话状态转移到主机内存，释放 GPU 资源供活跃会话使用。

### 关键运行时支持

- **合并 Chunk 执行（Coalesced Chunk Processing）**：将同一 GPU 上的并发活跃会话分组为 Chunk Batch，单次模型调用服务所有会话，提升 GPU 利用率。
- **GPU-CPU 状态卸载**：空闲会话的持久状态从 GPU 内存复制到主机内存，恢复时反向操作，将会话生命周期与 GPU 驻留解耦。
- **基于 NCCL 的 GPU-GPU 迁移**：支持在线会话重均衡，无需中断其他会话的生成。

在生数科技的真实生产 Trace 上进行评估，最大测试集群规模达 64 块 NVIDIA B300 GPU：

| 总 GPU 运营成本 | 3.99$ | ~2.50$ | **降低 37.2%** |

## 总结

TurboServe 以"流式视频生成服务"为核心场景，率先揭示了有状态多会话服务中延迟不均衡与资源浪费的根本矛盾，并通过会话迁移与 GPU 自动扩缩容的闭环联合设计加以解决。来自生产环境的 Trace 验证了系统在真实工作负载下的效果，具有很强的实用性。

局限性方面，迁移和 GPU 状态卸载/恢复会引入额外的内存带宽开销，在会话迁移频率极高时可能抵消部分收益；此外，扩缩容决策的滞后性在极端突发流量下可能仍存在短暂的延迟超标窗口。
