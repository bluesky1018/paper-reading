> 📄 **论文**：(1D) Ordered Tokens Enable Efficient Test-Time Search
> 🔗 **arXiv**：[2604.15453](https://arxiv.org/abs/2604.15453)
> 🏢 **机构**：EPFL VILAB & Apple

## 一句话总结

通过系统研究发现，具有粗粒度到细粒度（coarse-to-fine）结构的一维有序 Token 比传统二维网格 Token 更适合测试时搜索，并可实现训练自由的文本到图像生成。

## 背景与问题

自回归（AR）生成模型依赖 Tokenization 将原始数据转换为更易建模的单元。最常见的方式是将图像编码为二维空间网格 Token（对应图像的局部区域），然后以光栅扫描顺序依次预测。

**核心问题**：Token 的结构设计会影响模型进行测试时搜索（test-time search）的能力吗？

测试时搜索通过探索多个候选生成并由验证器评估，可显著提升生成质量和可控性——但这需要中间生成状态具有可被验证器可靠评估的语义含义。

本文的核心假设：**具有粗粒度到细粒度结构的一维有序 Token**（如 FlexTok）在中间状态上携带全局语义信息，比二维网格 Token 更适合搜索引导。

## 核心方法

### 1D 有序 Token 的可搜索潜在结构

一维有序 Token（如 FlexTok）将图像压缩为具有语义排序的序列：
- 早期 Token 捕捉高层语义（如"植物"）
- 后期 Token 逐步细化细节（如"盆栽植物"→"盆栽植物和一个物体"）
- 支持从任意数量的 Token 解码图像

这使得验证器可以在生成过程的任意中间阶段进行有效评估，从而实现有效的搜索引导。

### Search-over-Tokens（SoTo）框架

本文提出 **SoTo** 评估框架，系统研究不同 Token 结构在测试时搜索中的表现：

- **搜索算法**：Best-of-N、束搜索（Beam Search）、前瞻搜索（Lookahead Search）
- **验证器**：文本-图像对齐分数、语义相似度等
- **AR 先验**：条件先验、无条件先验、均匀先验

![SoTo评估框架](https://arxiv.org/html/2604.15453v1/x4.png)

*图7：与 Janus（2D 网格 Token）在 best-of-N 设置下的测试时扩展对比*

### DreamBench++ 概念保留结果

| 方法 | DINO-I | CLIP-I | CLIP-T |
|------|--------|--------|--------|
| FlexTok（基线） | 32.5 | 68.1 | 34.1 |
| **FlexTok + 束搜索** | **50.9 (+18.4)** | **76.5 (+8.4)** | 33.1 |
| Janus（基线） | 34.8 | 69.0 | 35.5 |
| Janus + 前瞻搜索 | 40.7 (+5.9) | 71.9 (+2.9) | 35.6 |

FlexTok（1D 有序）通过搜索获得的提升（+18.4 DINO-I）**远超** Janus（2D 网格，+5.9 DINO-I），且使用更少的计算量。

### 不同先验下的无 AR 模型生成

| 先验类型 | 搜索 | 单对象准确率 | 两对象准确率 |
|---------|------|------------|------------|
| 均匀先验 | ✓ | 79% | 32% |
| 无条件 AR 先验 | ✓ | 更高 | 更高 |
| 条件 AR 先验 | ✓ | **最优** | **最优** |

即使使用**均匀先验**（无 AR 模型），搜索也能实现合理的图像生成！

## 总结

本文系统揭示了 Token 结构对测试时搜索能力的深远影响：一维有序 Token 的粗粒度到细粒度语义结构使验证器能够在生成早期进行有效引导，从而实现更好的测试时扩展。这为自回归图像生成的推理时扩展提供了重要的实践指导：**Token 结构选择与搜索算法同等重要**。

**局限性**：目前主要在图像生成任务上验证，对其他模态（视频、音频）的适用性有待探索。束搜索等算法在 1D Token 上表现更好，但计算开销随搜索宽度显著增加。
