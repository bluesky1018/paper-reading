## 一句话总结

提出 **Mamba**——以**选择性状态空间模型(Selective SSM)**为核心的新型序列模型架构。相比 Transformer,它:
1. 时间复杂度为**真正的线性** $O(N)$(而非 $O(N^2)$)
2. 推理阶段**无需 KV cache**,只维护一个固定大小的隐状态
3. 首次在**语言建模任务上**追平甚至超越同规模 Transformer
4. 通过 **Selection Mechanism + Hardware-Aware Parallel Scan** 同时解决了早期 SSM "上下文不敏感" 和 "训练慢" 两大痛点

是线性注意力/SSM 路线历史上最具影响力的一步,与 FlashAttention 同出 Tri Dao 之手,风格一脉相承:**从第一性原理重构计算图**。

## 背景:SSM 是什么?为什么之前不好用?

### 状态空间模型的定义

一个**连续时间线性 SSM** 定义为一对常微分方程:

$$
h'(t) = A h(t) + B x(t)
$$

$$
y(t) = C h(t)
$$

- $h(t)$:隐状态(记忆)
- $x(t)$:输入
- $y(t)$:输出
- $A, B, C$:可学习矩阵

**离散化**后变成递归:

$$
h_t = \bar A h_{t-1} + \bar B x_t,\quad y_t = C h_t
$$

这就是 **S4、Mamba、RetNet、RWKV** 等一众"线性 attention/recurrent"模型的统一底座。

### 为什么是"线性"?

- 每步用**固定大小**的 $h$ 压缩整个历史 → 推理 $O(1)$ 空间、$O(N)$ 时间
- 训练时可以展开成**全局卷积**:$y = K * x$,用 FFT 做到 $O(N \log N)$

**对比 Transformer**:attention 每步要访问所有历史 token,推理是 $O(N)$ 空间 + $O(N)$ 时间(KV cache)。长序列下 SSM 占便宜。

### 早期 SSM (S4) 的致命弱点:内容不敏感

S4 的 $A, B, C$ 是**输入无关的常数**矩阵。这意味着:

- 无论当前 token 是什么,状态更新规则不变
- **无法根据内容选择性记忆/遗忘**

这在需要"按 token 决定做什么"的任务上(如语言建模)天生吃亏——语言里有大量"这个词重要、那个词丢掉"的判断。

![选择机制的核心:把 S4 里恒定的 (A, B, C) 改成输入依赖的 (A(x), B(x), C(x))。模型现在可以根据当前 token 决定"记多少、记哪些、怎么读出"。这是 Mamba 相对 S4 的关键飞跃。](/assets/img/mamba/x2.png)
_Figure 2:Selection 机制——让 SSM 参数成为输入的函数,实现 token 级选择性_

## 核心贡献 1:Selection Mechanism

**把 SSM 的 $B, C$ 参数做成输入的函数**:

$$
B_t = \text{Linear}_B(x_t),\quad C_t = \text{Linear}_C(x_t),\quad \Delta_t = \text{Linear}_\Delta(x_t)
$$

$\Delta_t$ 是每 token 的**时间步长**(离散化参数),本质是门控:

- $\Delta_t$ 大 → **"关注此 token,重置状态"**(更新权重高)
- $\Delta_t$ 小 → **"忽略此 token,保持历史"**(更新权重低)

递推规则变成:

$$
h_t = e^{-\Delta_t A} h_{t-1} + \Delta_t B_t x_t
$$

$$
y_t = C_t h_t
$$

这就是论文标题里的 "**Selective**" —— 模型可以按 token 自适应地选择**记什么/忘什么/读什么**。

**代价**:$A_t, B_t, C_t$ 随 token 变化,**不再是时不变卷积**,S4 那套 FFT 训练技巧用不了了。

## 核心贡献 2:Hardware-Aware Parallel Scan

解决"训练怎么做"的问题。

### 难点

Mamba 的递推:

$$
h_t = \alpha_t h_{t-1} + \beta_t
$$

其中 $\alpha_t = e^{-\Delta_t A}$ 是每步不同的。朴素实现需要**逐步串行**,GPU 利用率低,而且中间状态 $h_t$ 物化到 HBM 会爆显存。

### 解法:Parallel Scan + SRAM Tiling

**并行扫描(Parallel Scan)**:
一个线性递推 $h_t = \alpha_t h_{t-1} + \beta_t$ 可以用 $O(\log N)$ 步并行完成,复杂度 $O(N \log N)$ 但 wall-clock 快很多倍。

**硬件感知(Hardware-Aware)**:

作者把算法组织成"scan in SRAM":

1. 把 $(A, B, C, \Delta)$ 一次性加载到 SRAM
2. 在 SRAM 内部做 scan,**不把中间隐状态 $h$ 写回 HBM**
3. 反向传播用 recomputation(和 FlashAttention 同出一辙)

<callout emoji="zap" background-color="light-orange" border-color="orange">
**这就是 Tri Dao 的味道**:减少 HBM IO,就算 FLOPs 多一些也无所谓。Mamba 训练速度比等规模 S4 还快,且真正做到了 GPU 友好。
</callout>

## 核心贡献 3:简化架构(Mamba Block)

把 Selective SSM 嵌入一个极简 block:

![Mamba block 架构:输入经过线性投影 → 1D 短卷积 → Selective SSM → 逐元素乘以门控分支 → 线性投影输出。完全没有 attention、也没有 MLP。](/assets/img/mamba/x3.png)
_Figure 3:Mamba block——无 attention、无 MLP 的单一 block 设计_

```
x → Linear(d, 2·d_inner)       # 分裂成 main 和 gate 两路
main: Conv1d(kernel=4) → SiLU → SelectiveSSM(...)
gate: SiLU
out = main * gate → Linear(d_inner, d)
```

**对比 Transformer block**:

| 组件 | Transformer | Mamba |
|------|-------------|-------|
| 混合器 | Multi-Head Attention | Selective SSM |
| 通道混合 | MLP (SwiGLU) | (吸收进 gate 分支) |
| 残差 + Norm | 有 | 有 |
| 推理状态 | KV cache $O(N)$ | 固定 $h$,$O(1)$ |

一个 block 解决所有事——**没有 attention 和 MLP 的交替,也没有 cross-attention**。

## 实验结果

### Scaling Laws(最重磅)

![Mamba 与 Transformer 在 Chinchilla 训练 setting 下的 scaling law:Mamba 与 Transformer++ (最强变体) 持平或略好,并首次在超过 1B 规模上跑赢 attention。](/assets/img/mamba/x4.png)
_Figure 4:Scaling Laws——Mamba 首次在 1B+ 规模上与现代 Transformer 打平_

这张图在发表时是**震撼的**:
- 之前所有"线性/recurrent"模型(Linformer、Performer、RWKV、RetNet)在大规模下都追不上 Transformer
- Mamba 在 125M → 1.3B 的每个规模上都至少打平 Transformer++(GLU + RoPE + SwiGLU 的强化版)

### 关键下游表现

| 模型 | 参数 | Pile PPL ↓ | LAMBADA | PIQA | Arc-E |
|------|------|-----------|---------|------|-------|
| Pythia-1B (Transformer) | 1B | — | 56.1 | 70.7 | 47.0 |
| RWKV-1.5B | 1.5B | — | 56.4 | 72.4 | 45.1 |
| **Mamba-1.4B** | 1.4B | **7.33** | **64.9** | **74.2** | **48.0** |
| Mamba-2.8B | 2.8B | — | **69.2** | **75.2** | **61.0** |

**Mamba-2.8B 下游表现接近 Pythia-7B/Llama-7B**,参数少一半以上。

### 长序列任务

- **Selective Copy**(从上下文复制指定 token):S4 几乎 0%,Mamba 100%
- **Induction Heads** 合成任务:线性 attention 只能到 256 长度,Mamba **外推到 1M**
- **DNA、音频建模**:在百万级序列上优势更明显

### 推理吞吐

- 5× 于同规模 Transformer
- 没有 KV cache:**batch 越大、context 越长,优势越放大**

## 为什么影响如此巨大

### 1. 第一次证明 SSM 能做 LM

在 Mamba 之前,SSM 系工作(S4、H3、RetNet)都在长程合成任务上赢,但语言建模始终差 Transformer 一截。**Mamba 是第一个在 LM scaling law 上追平 Transformer 的 SSM**,让 "可能用 SSM 替代 attention" 从幻想变成讨论话题。

### 2. 启动了 Hybrid 架构主流化

虽然 Mamba 本身是纯 SSM,但社区很快意识到:

- Mamba 长上下文记忆吃亏(state 容量有限)
- Transformer 长上下文算力吃亏(KV cache 太大)
- **几层 full attention + 大量 Mamba/SSM 层**是最优 trade-off

这条路催生了 **Jamba、Zamba、Qwen3.5、MiniMax-01**等一系列 hybrid 架构。Qwen3.5 的 18 linear + 6 full 结构(我在另一篇已解读)就是这条路线的代表。

### 3. 给 Tri Dao 系统 ML 工作打上了惊叹号

- FlashAttention (2022):让 attention 不再 memory-bound
- Mamba (2023):用硬件感知 scan 让 SSM 训得动
- Mamba-2 (2024):把 SSM 与线性 attention 在数学上统一(SSD)
- FlashAttention-3 (2024):适配 Hopper

**"系统优化决定算法能否存活"** 这个哲学,被 Tri Dao 一次次验证。

### 4. Mamba-2 更新:与线性 attention 打通

Mamba-2 发现 **Mamba 的 scan 等价于一个特殊形式的 linear attention**(Structured State-Space Duality, SSD),从此 SSM 和线性 attention 不再是两条路线,而是**同一个框架下的不同参数化**。这是 2024 年最重要的理论统一之一。

## 读完这篇你真正该带走的 4 件事

<callout emoji="white_check_mark" background-color="light-green" border-color="green">
1. **SSM ≠ 慢**:只要选对算法组织(parallel scan),加上硬件感知的 SRAM tiling,SSM 可以训得很快
2. **选择性是 SSM 真正能打 LM 的钥匙**:Selection Mechanism 让 SSM 从 "平等对待每个 token" 变成 "按内容决定记忆",是从 S4 到 Mamba 的关键一跃
3. **固定大小状态 vs KV cache**:二者都是对历史信息的压缩。KV cache 保真但线性增长,state 固定但有容量上限。这个 trade-off 决定了 hybrid 架构的设计空间
4. **Tri Dao 风格:永远从第一性原理重写数据流**。FlashAttention 这样、Mamba 这样,后续 Mamba-2、FA-3 也都这样
</callout>
