> 📄 **论文**：DeepSeek-V4.1-Flash: Pushing the Limits of KV Cache Compression
> 🔗 **arXiv**：[2609.19969](https://arxiv.org/abs/2609.19969)
> 🏢 **机构**：DeepSeek-AI

## 一句话总结

DeepSeek-V4.1-Flash 是一个 552B 参数的多模态 MoE 模型，通过 Causal Encoder-Decoder 架构、CSA2 压缩稀疏注意力和 FP4 KV 缓存等创新，将每 token 全局 KV 缓存压缩至 DeepSeek-V4-Flash 的 1/4，持久 KV 缓存降至 1/8，同时支持高达 100 万 token 的超长上下文。

## 背景与问题

随着大语言模型向长上下文 Agent 方向发展，模型推理面临的核心瓶颈从计算量转移到了 KV 缓存的存储与带宽消耗。当输入序列增长到百万 token 级别时，KV 缓存对 HBM 容量和 I/O 带宽造成的压力成为部署的主要障碍。

以 DeepSeek-V4 为例，其全局注意力分支（处理完整上下文）与局部滑动窗口注意力（SWA）的组合，在长序列场景下全局 KV 仍占据大量运行时内存。如何在不牺牲模型能力的前提下，系统性地压缩 KV 缓存，是 DeepSeek-V4.1-Flash 要解决的核心问题。

从 DeepSeek-V1 到 V4.1-Flash，全局 KV 缓存已实现约 437 倍的压缩，其中 V4.1-Flash 相比 V4-Flash 进一步降低约 4 倍，而上下文窗口从 4K 扩展到 1M（256 倍）时，解码 FLOPs 仅增加 1/4。

## 核心方法

### Causal Encoder-Decoder（CED）架构

CED 架构受 YOCO 启发，将 40 层 Transformer 分为 20 层因果编码器 + 20 层解码器。解码器层的全局 KV 直接从编码器第 L/2 层的隐藏状态投影得到，而无需各自独立计算：

```
Cₗ = H_{L/2} Wₗ^{KV},  l > L/2
```

这一设计使得预填充复杂度从 O(NL) 降至 O(NL/2)，有效减半预填充计算量。

### 压缩稀疏注意力 CSA2

CSA2 在 CSA 基础上进一步精简，采用三种静态模式：

| 模式 | 主 KV | Top-K 索引 |
|------|-------|-----------|
| Full | 重新计算 | 新计算 |
| Reindex | 复用前 Full 层 | 本层重评分 |
| Reuse | 复用前 Full 层 | 直接复用 |

通过层间 KV 复用，全局 KV 存储进一步降低。分层稀疏索引器（Hierarchical Sparse Indexer）在解码阶段先筛选候选块（2048 块 × 8 = 16384 个候选位置），后续层只对候选集评分，使得解码器的注意力计算成本与上下文长度解耦。

![CSA2 层内 KV 复用示意](https://arxiv.org/html/2609.19969/x2.png)
*图：CSA2 三种模式的 KV 计算路径*

### FP4 主 KV 缓存

V4.1-Flash 采用 E2M1 格式（每 16 个通道一个 E4M3 缩放因子，NVFP4 风格），SWA KV 缓存保留 FP8，全局 KV 降为 FP4，存储量约为 FP8 的一半。量化感知训练（QAT）在后训练阶段引入，量化在 RoPE 编码之后应用。

### SWA 有界重放（Bounded Replay）

生产环境中，SWA KV 的持久化（V4 方案中需缓存 L×n_win token）代价过高。V4.1-Flash 将 SWA KV 存储于分布式内存池（占主机 DRAM 的约 10%），TTL 仅数分钟。对于缓存缺失情况，采用"有界重放"：仅重算最近 n_win=128 个 token 的 SWA KV，从而将持久 KV 缓存从 1/4 进一步降至 1/8。

### 其他关键组件

- **Engram**：196B 参数的条件记忆模块，以 FP8 精度存储 N-gram 嵌入，通过 RDMA 从主机内存预取
- **DSpark**：投机解码模块，一次前向并行生成 5 个草稿位置，使用轻量级马尔可夫头建模草稿依赖
- **单趟 mHC（Mega-mHC）**：将激活内存流量降至理论下界 (2n+2)d，是原版的一半

### 优化器创新

论文提出 Sinkhorn 均衡更新，用于 Engram 嵌入和 token 嵌入的优化，通过交替行/列 ℓ₂ 归一化均衡更新矩阵的行列 RMS，仅需动量缓冲区（无需 Adam 二阶矩），学习率修正系数 γ=0.18。

## 实验结果

### 关键参数对比

| 指标 | 值 |
|------|---|
| 总骨干参数 | 552B |
| Engram 参数 | 196B |
| 激活参数（预填充） | 8B |
| 激活参数（解码） | 16B |
| 最大上下文长度 | 100 万 token |
| 预训练数据量 | 45T token |
| 每 token 全局 KV | 890 字节 |
| 相比 V4-Flash 全局 KV | 约 1/4 |
| 相比 V4-Flash 持久 KV | 约 1/8 |
| 相比 DeepSeek-V1 全局 KV | 约 1/437 |

### 基础模型性能

V4.1-Flash-Base（8B/16B 激活参数）在世界知识、推理和代码能力上与 DeepSeek-V4-Pro-Base（49B 激活参数）相当，在保留评估集上提升 5%–10%，仅使用 1/3 总参数和 1/4 激活参数。

### 后训练性能

- **Terminal-Bench 2.1 / DeepSWE v1.1 / AutomationBench**：与闭源前沿模型持平
- **多模态**：在视觉推理和专业图表基准上超越 Kimi-K3
- 能完成 95% 以上真实世界任务

## 总结

DeepSeek-V4.1-Flash 通过系统性的架构创新（CED、CSA2、FP4 KV、SWA Bounded Replay、Engram、DSpark）实现了 KV 缓存的极致压缩，是目前已知最激进的 KV 压缩方案之一。552B 参数、100 万 token 上下文的规模与 8B/16B 激活参数的高效率形成鲜明对比，展示了 MoE 架构在超长上下文部署上的巨大潜力。

局限性方面，模型在以科学为导向的 Agent 任务（Terminal-Bench 4.0）和整体多模态性能上与最大规模的闭源模型仍有差距，未来方向是架构、预训练和后训练的联合扩展。
