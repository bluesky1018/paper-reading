> 📄 **论文**：DeNovoSWE: Scaling Long-Horizon Environments for Generating Entire Repositories from Scratch
> 🔗 **arXiv**：[2606.10728](https://arxiv.org/abs/2606.10728)
> 🏢 **机构**：中国人民大学、字节跳动

## 一句话总结

提出 DeNovoSWE：4818个高质量"从文档生成完整代码仓库"任务实例的大规模数据集，配合难度感知轨迹过滤策略，将 Qwen3-30B-A3B 在 BeyondSWE-Doc2Repo 基准上的得分从 5.8% 提升至 47.2%。

## 背景与问题

基于 LLM 的代码 Agent 已在 SWE-bench 等基准上取得显著进展，但这些基准主要聚焦于**修复现有代码库中的已知 bug**（单一 issue 修复）。真实世界中更具挑战性的任务是：**给定高层规格说明文档，从零构建完整代码仓库**。

现有长程代码能力基准（如 BeyondSWE-Doc2Repo、NL2RepoBench）已开始评估这一能力，但训练数据严重匮乏——现有 SWE 训练数据集仍主要集中在单一 issue 修复，缺乏大规模可验证的完整仓库生成数据。

从零生成代码仓库面临三大核心挑战：
1. **文档构建**：需要生成全面、结构化且与可执行行为一致的仓库文档
2. **评估设计**：需要通过可执行测试客观评估多样化仓库的生成质量
3. **防泄漏执行**：需要严格沙箱化防止 Agent 通过外部渠道获取参考实现

## 核心方法

### DeNovoSWE 数据集构建

![DeNovoSWE系统概览](https://arxiv.org/html/2606.10728v1/figures/main.png)
*图1：DeNovoSWE 概览（左）：从单一 issue 修复到全仓库生成的任务范围扩展；（右）DeNovoSWE 相比已有数据集规模对比，约46倍于 NL2Repo*

采用**分治（Divide-and-Conquer）**范式结合迭代**批评-修复（Critic-Repair）**机制：

![系统详细流程](https://arxiv.org/html/2606.10728v1/figures/system.png)
*图2：DeNovoSWE 框架详细流程：分阶段进行仓库能力分解和文档生成*

**第一阶段：分解（Divide）**
- **仓库能力分解**：由概述撰写 Agent 探索整个仓库生成高层摘要，再由能力撰写 Agent 识别主要功能能力，每个能力对应文档中的一个章节
- **仓库剖析（Repository Profiling）**：执行单元测试并捕获运行时追踪，将被测试覆盖的函数/类分为直接组件、核心间接组件和非核心组件
- **映射关联**：将剖析出的函数类与仓库能力相关联

**第二阶段：合并（Conquer）**

通过三个沙箱化 Agent 迭代精化文档：
- **草稿 Agent**：为每个仓库能力生成初始文档
- **批评 Agent**：识别结构缺陷、API 覆盖不足等问题
- **修复 Agent**：根据批评修订文档，多轮迭代直到质量达标

**泄漏防止机制**
- 预清理：精确移除源代码实现、测试套件及 pip 缓存
- Git 历史清除：完全销毁并重新初始化 .git 目录
- 运行时拦截：命令限制策略 + LLM-as-judge 审计

### 难度感知轨迹过滤

对于长程仓库生成任务，固定阈值过滤过于严格——即使强力 Agent 也难以获得满分轨迹。本文提出**难度感知轨迹过滤**策略：

![难度与轨迹分数关系](https://arxiv.org/html/2606.10728v1/figures/difficulty.drawio.png)
*图3：难度分数越高，轨迹得分越低（左）；DeNovoSWE 覆盖全范围难度分布（右）*

**三维度难度评估：**
- 结构信号：目标任务范围内可执行 Python 代码行数
- LLM 信号：两个独立 LLM 标注器的 5 级质量判断
- 融合权重：通过 Pearson 相关系数最大化校准最优权重

**自适应过滤阈值：**

| 难度分数范围 | 过滤阈值 |
|------------|---------|
| [0.0, 0.2) | 0.90 |
| [0.2, 0.4) | 0.85 |
| [0.4, 0.6) | 0.80 |
| [0.6, 0.8) | 0.70 |
| [0.8, 1.0] | 0.60 |

## 实验结果

### BeyondSWE-Doc2Repo 与 NL2RepoBench 对比

| 模型 | Doc2Repo | NL2Repo |
|------|---------|---------|
| GPT-5.4 (CodeX) | 0.617 | - |
| DeepSeek-V4-Pro | 0.566 | - |
| Gemini3-Pro | 0.520 | - |
| Qwen3-30B-A3B-Instruct（基础） | 0.058 | 0.043 |
| Scale-SWE-Agent（issue级SWE数据训练） | 0.292 | 0.183 |
| **DeNovoSWE-Agent-30A3B** | **0.472** | **0.230** |
| Qwen3.5-35B-A3B（基础） | 0.438 | 0.235 |
| **DeNovoSWE-Agent-35A3B** | **0.500** | **0.271** |

- Qwen3-30B 从 5.8% 提升至 **47.2%**（提升约 41 个百分点）
- Qwen3.5-35B 达到 50.0%，与 Gemini3-Pro（52.0%）差距仅 2.4 个百分点

## 总结

DeNovoSWE 填补了长程仓库生成训练数据的重要空白。通过分治文档生成、迭代批评修复和难度感知过滤三项关键技术，构建了迄今最大规模的可验证全仓库生成数据集（4818个实例，约为已有数据集的46倍）。

**主要贡献：**
- 自动化沙箱流水线实现大规模高质量数据构建，无需人工标注
- 难度感知过滤在数据质量与任务多样性之间取得更好平衡
- 训练后的 DeNovoSWE-Agent 达到接近闭源前沿模型的性能水平

**局限性：**
- 数据构建依赖强力专有模型（GPT-5.4/5.5）
- 目前聚焦于 Python 仓库，跨语言泛化有待验证
- 完全成功率仍远低于商业前沿模型（最高 50% vs GPT-5.4 CodeX 的 61.7%）
