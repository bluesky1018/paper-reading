## 一句话总结

**Code2World** 提出用 **生成可渲染 HTML 代码** 的方式来模拟 GUI 界面的下一状态，结合渲染感知强化学习（RARL），让 8B 模型达到 GPT-5 水准的 GUI 预测能力，并将 Gemini-2.5-Flash 在 AndroidWorld 上的成功率提升 **+9.5%**。

---

## 背景：GUI 智能体的核心挑战

当前 GUI 自动化智能体（如手机/桌面操作助手）面临一个根本问题：**智能体无法预知自己的操作会导致什么界面变化**。

现有方案存在两个主要局限：
- **直接像素生成**：预测下一帧截图，计算代价高、细节模糊
- **无世界模型**：智能体只能"盲目"执行操作，无法提前规划

Code2World 的核心洞见：GUI 界面本质上是结构化的——可以用 **HTML/代码** 来精确表达。

---

## 方法框架

![Code2World 整体框架](https://arxiv.org/html/2602.09856/x1.png)

*图：Code2World 框架概览 —— 输入当前截图和操作指令，输出可渲染的 HTML 代码，渲染后得到预测的下一界面状态*

### 核心思路：代码即世界模型

Code2World 将"预测下一 GUI 状态"转化为"生成可渲染代码"的问题：

```
输入：当前截图 + 操作描述
输出：HTML/代码（渲染后 = 下一界面状态）
```

这样做的优势：
- **精确性**：代码可以精确描述每个 UI 元素的位置、内容、状态
- **可验证性**：代码可以被直接渲染，产生可视化反馈
- **结构化**：便于智能体解析和规划

![AndroidCode 数据集示例](https://arxiv.org/html/2602.09856/x2.png)

*图：AndroidCode 数据集构建流程 —— 将 Android 操作轨迹翻译为高保真 HTML 代码*

团队构建了 **AndroidCode** 数据集：
- **规模**：超过 80,000 个高质量屏幕-操作对
- **来源**：将 GUI 操作轨迹转换为高保真 HTML
- **质量**：人工验证渲染效果与原始截图的一致性

## 训练方法：RARL（渲染感知强化学习）

![RARL 训练流程](https://arxiv.org/html/2602.09856/x3.png)

*图：RARL 训练框架 —— 将渲染结果作为奖励信号，驱动代码生成质量提升*

训练分两阶段：

### 阶段 1：SFT 冷启动
- 在 AndroidCode 数据集上进行监督微调
- 让模型学会基本的"截图 → HTML"映射

### 阶段 2：RARL 强化学习
- 将生成的 HTML **实际渲染**成图像
- 计算渲染结果与真实下一帧的相似度作为奖励
- 奖励信号驱动模型生成视觉上更准确的代码

> 关键创新：**用渲染结果本身作为奖励**，而非用文本相似度——这让模型真正优化的是"界面看起来是否正确"

## 应用：规划辅助框架

![Propose-Simulate-Select 框架](https://arxiv.org/html/2602.09856/x5.png)

*图："提议-模拟-选择"三步规划框架，利用 Code2World 预测多条操作路径的结果*

Code2World 作为世界模型，支持 **"提议-模拟-选择"** 规划管线：

1. **Propose（提议）**：智能体生成多个候选操作
2. **Simulate（模拟）**：Code2World 预测每个操作的界面结果
3. **Select（选择）**：选择预测结果最优的操作执行

这让智能体能在执行前"想象"不同操作的后果，显著提升规划质量。

## 总结

Code2World 提供了一种优雅的 GUI 世界建模思路：**不生成像素，而是生成结构化代码**。这一转变带来了精确性、可验证性和可渲染性三重优势。通过 RARL 训练方法，8B 的小模型达到了 GPT-5 级别的 GUI 预测能力，并成功赋能现有 GUI 智能体，将 Gemini-2.5-Flash 的 AndroidWorld 成功率从 41.4% 提升到 50.9%。

这项工作为构建更智能的 GUI 自动化系统开辟了新路径。
