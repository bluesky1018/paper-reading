## 一句话总结

MedOpenClaw 提出了一套可审计的医学影像 AI Agent 运行时框架，让大视觉语言模型（VLM）能够像真实放射科医生一样操控 3D Slicer 浏览完整医学影像研究（而非预选的 2D 切片），并配套发布了 MedFlow-Bench 基准，揭示出"专业工具反而降低模型表现"这一反直觉现象。

---

## 背景与问题

### 现有医学影像评测的根本缺陷

当前医学视觉语言模型（VLM）的评测范式存在系统性偏差：

1. **数据偏差**：评测只使用预先筛选好的、诊断相关的 2D 图像切片，而非完整的 3D 影像研究
2. **过程不透明**：模型的推理决策过程是"黑盒"的，无法追溯和审计
3. **与临床脱节**：真实放射科工作流需要：
   - 浏览完整的 3D 检查序列（可能包含数百张切片）
   - 动态调节窗宽窗位（Windowing）
   - 跨模态对比（如 CT 与 PET 联合分析）
   - 执行病灶测量与分割
   - 参考临床上下文信息

**核心矛盾**：现有基准测试的性能提升无法直接迁移到临床实践，因为二者的任务设定从根本上就不同。

### 研究核心问题

> 当 VLM Agent 被要求以透明、可回放、可审计的方式搜索完整医学影像研究时，其表现如何？专业临床工具的加入是否能提升诊断性能？

### MedOpenClaw 运行时框架

MedOpenClaw 是一个位于骨干 VLM 与医学影像查看器（3D Slicer）之间的 API 层，**无需修改查看器源代码**即可实现外部控制。

#### 三层动作架构

```

┌─────────────────────────▼───────────────────────────┐
│              MedOpenClaw 运行时（API层）               │
│  ┌──────────────────────────────────────────────┐   │
│  │  Layer 1: 原始查看器操作（Primitive Actions） │   │
│  │  - 序列选择（Series Selection）               │   │
│  │  - 切片滚动（Slice Scrolling）                │   │
│  │  - 窗宽窗位调节（Windowing）                  │   │
│  └──────────────────────────────────────────────┘   │
│  ┌──────────────────────────────────────────────┐   │
│  │  Layer 2: 证据操作（Evidence Operations）     │   │
│  │  - 书签视图（Bookmarked Views）               │   │
│  │  - 分割掩码记录（Masks）                      │   │
│  │  - 测量日志（Measurement Logs）               │   │
│  └──────────────────────────────────────────────┘   │

└─────────────────────────┬───────────────────────────┘
                          │ REST API
┌─────────────────────────▼───────────────────────────┐
│            3D Slicer（医学影像查看器）                 │
│         WebServer REST 端点 + 命名桥接处理器           │
└─────────────────────────────────────────────────────┘
```

#### 关键设计原则

- **禁止任意代码执行**：明确禁止 Agent 执行任意 Python 代码，以维护可审计性
- **完整操作日志**：每次工具调用均记录参数、查看器状态快照和操作产物（Artifacts）
- **可回放性**：所有操作轨迹可被完整回放，满足临床和监管合规要求

### MedFlow-Bench 评测基准

#### 评测 Episode 定义

每个评测任务（Episode）由以下四要素构成：

```
Episode = {
    影像研究包（Study Package）,
    任务提示词（Task Prompt）,
    允许的动作空间（Allowed Action Space）,
    标准答案模式（Canonical Answer Schema）
}
```

#### 两大影像模块

**模块一：脑部 MRI（Brain MRI）**
- 数据集：UCSF-PDGM（术前弥漫性胶质瘤）
- 特点：多序列（T1、T2、FLAIR、DWI 等）
- 任务：基于多模态 MRI 序列的综合诊断推理

**模块二：肺部 CT/PET（Lung CT/PET）**
- 数据集：NSCLC 放射基因组学数据集
- 5 个结构化诊断任务：
  1. 肿瘤位置（Tumor Location）
  2. T 分期（T Stage）
  3. N 分期（N Stage）
  4. 组织学分类（Histology）
  5. 组织病理学分级（Histopathological Grade）

#### 答案评估协议

| 协议类型 | 说明 |
|---------|------|
| 选择题（MCQ） | 提供选项，直接判断 |
| 开放式（Open-ended） | 由 LLM 评判语义等价性 |

#### 三条评测轨道

| 轨道 | 名称 | 工具限制 | 目的 |
|------|------|---------|------|
| Track A | 纯查看器（Viewer-Only） | 仅原始查看器操作 | 基线能力评测 |
| Track B | 工具使用（Tool-Use） | 不限制专家工具访问 | 工具增强效果评测 |
| Track C | 开放方法（Open-Method） | 任意流程（绕过 MedOpenClaw） | 性能上界估计 |

## 实验结果

### Track A：纯查看器基线结果

| 模型 | 脑部 MRI 准确率 | 肺部 CT/PET 综合得分 |
|------|--------------|-------------------|
| GPT-5.4 | 0.61 | 0.32 |
| GPT-5-mini | 0.43 | 0.20 |
| Gemini-3.1-flash | 0.56 | 0.52 |
| Gemini-3.1-pro | 0.63 | 0.31 |

**关键发现**：
- 所有前沿模型均能完成基础的 3D 影像浏览任务
- 组织病理学分级预测对所有模型接近随机水平（该任务需要整合影像与临床知识）
- Gemini-3.1-flash 在肺部 CT/PET 任务上表现最优（0.52），显示不同模型在不同影像模态上各有优势

### Track B：工具使用消融实验（核心发现）

| 模型 | 配置 | 脑部 MRI | 肺部 CT/PET |
|------|------|---------|-----------|
| GPT-5-mini | 仅原始操作 | 0.43 | 0.20 |
| GPT-5-mini | + 分割工具 | 0.45 | **0.14** ↓ |
| GPT-5.4 | 仅原始操作 | 0.61 | 0.32 |
| GPT-5.4 | + 分割工具 | **0.57** ↓ | **0.27** ↓ |

**反直觉发现——"工具使用悖论"（Tool-Use Paradox）**：

> 在大多数情况下，添加专业分割工具**降低**了模型的诊断性能。

## 深度分析

### "工具使用悖论"的根本原因

论文将这一现象归结为 VLM 的**空间坐标精度缺失**：

```
问题链：
VLM 缺乏毫米级空间坐标精度
        ↓
无法准确为临床算法提供种子点（Seed Points）
        ↓
分割掩码与实际病灶对齐偏差
        ↓
错误的定量特征进入推理链
        ↓
误导后续诊断决策
        ↓
最终性能下降（低于不使用工具的基线）
```

这揭示了一个重要洞见：**工具增强的收益前提是 Agent 有能力正确使用工具**。当工具使用本身引入错误时，工具反而成为噪声源。

### 可审计性的临床价值

MedOpenClaw 的有界运行时产生"透明证据轨迹"，直接对应：
- **临床要求**：诊断决策需可解释、可追溯
- **监管要求**（如 EU AI Act、FDA 510(k)）：高风险 AI 系统须具备可审计性
- **医疗责任**：当 AI 辅助诊断出现错误时，可回溯操作历史进行责任认定

### 从基准到临床的直接迁移路径

由于 MedOpenClaw 的动作空间直接镜像了真实放射科医生的工作流程，基准测试上的改进可**直接迁移**到下游临床应用 **MedCopilot**，这解决了现有医学 AI 基准与临床实用性之间的"翻译鸿沟"。

---

## 局限性与未来方向

1. **空间推理能力**：当前 VLM 缺乏精确的 3D 坐标感知能力，这是解锁工具增强潜力的关键瓶颈
2. **组织病理学分级**：所有模型在该任务上近乎随机，说明影像-病理联合推理仍是开放问题
3. **数据覆盖**：目前仅覆盖脑 MRI 和肺 CT/PET，需扩展到更多影像模态和器官系统
4. **工具设计优化**：需要探索对 VLM 更友好的工具接口设计，降低空间坐标精度要求

---

## 总结

MedOpenClaw 从三个层面推进了医学 AI 的边界：

| 维度 | 贡献 |
|------|------|
| **技术框架** | 首个将 VLM 与医学影像标准查看器（3D Slicer）原生集成的可审计运行时 |
| **评测范式** | MedFlow-Bench 将评测粒度从"预选 2D 切片"提升至"完整 3D 影像研究" |
| **科学发现** | 揭示"工具使用悖论"：VLM 空间推理能力不足导致专业工具反噬性能 |

**一个关键结论**：

> 基于查看器的完整影像研究推理对前沿 VLM Agent 而言已是可行现实；但可靠的工具增强执行仍是未解的核心挑战，其根本障碍在于 VLM 的毫米级空间坐标感知能力。

这项工作为医学 AI 从"实验室基准"走向"临床可审计部署"提供了一条清晰的技术路径。
