> 📄 **论文**：HISA: Efficient Hierarchical Indexing for Fine-Grained Sparse Attention
> 🔗 **arXiv**：[2603.28458](https://arxiv.org/abs/2603.28458)
> 🏢 **机构**：Yufei Xu, Fanxu Meng, Fan Jiang, Yuxuan Wang, Ruijie Zhou, Jiexi Wu, Zhixin Pan, Zhaohui Wang, Xiaojuan Tang, Wenjie Pei, Tongxuan Liu, Di Yin, Xing Sun, Muhan Zhang 等

## 一句话总结

HISA 将稀疏注意力的 Token 级索引器从 O(L²) 的全前缀扫描改造为两阶段层次化搜索（块级粗筛 + Token 级精筛），在不修改下游注意力算子、无需重新训练的前提下，于 32K/128K 上下文下实现 2×/4× 的索引加速，并保持超过 99% 的 Token 选择一致性。

## 背景与问题

随着大语言模型（LLM）的上下文窗口从 4K 扩展到 128K 甚至更长，长上下文推理的效率问题愈发关键。Token 级稀疏注意力（如 DeepSeek 稀疏注意力，DSA）通过为每个查询选择最相关的 top-k 个 Token，显著减少了注意力计算量，是解决长上下文效率问题的重要路径。

然而，DSA 面临一个被忽视的瓶颈：**索引器本身的计算复杂度**。DSA 的索引器需要对每个查询扫描整个前缀（长度 L），以评分每个历史 Token 的相关性，其复杂度为：
- 每查询：O(L)
- 每层：O(L²)

这与稠密注意力的渐近复杂度相同！换言之，虽然 DSA 通过稀疏注意力降低了注意力计算本身的代价，但索引器的扫描代价却成为了新的性能瓶颈，在超长上下文（128K+）下尤为显著。

核心研究问题：**能否在不改变最终稀疏注意力模式的前提下，降低索引器的搜索代价？**

## 核心方法

HISA（Hierarchical Indexing for Sparse Attention）提出了一种两阶段层次化搜索策略，将 Token 级扁平扫描转化为块级粗筛 + Token 级精筛的两步流程。

*图：原始 DSA 的 Token 级扁平扫描——对整个前缀逐一评分*

![HISA 层次化索引器示意](https://arxiv.org/html/2603.28458/x2.png)
*图：HISA 的层次化块-Token 搜索——先筛块，再精筛 Token*

### 核心算法

**前置步骤：块划分与池化键**

将长度为 L 的前缀划分为 M = ⌈L/B⌉ 个大小为 B 的连续因果块 B₁, ..., B_M。

对每个块通过均值池化生成代表键：

```
k̃ᵦᴵ = Pool({kₛᴵ | s ∈ B_b})
```

池化键与 KV 缓存一起增量维护，无需额外存储开销。

**第一阶段：块级粗筛**

复用 DSA 的查询表示和门控权重，但对池化的块代表键进行评分：

```
J_{t,b} = Σⱼ w_{t,j}^I · ReLU((q_{t,j}^I)ᵀ k̃ᵦᴵ)
```

保留得分最高的 m 个块：C_t = TopK(J_{t,:}, m)

候选 Token 池：Ω_t = ∪_{b∈C_t} B_b

**强制包含**（仿照 MoBA 设计）：首块和末尾两块始终纳入候选池，分别覆盖系统提示和最近上下文，并简化打包序列的边界处理。

**第二阶段：Token 级精筛**

仅在候选池 Ω_t 上应用原始 DSA 评分：

```
I_{t,s}^H = Σⱼ w_{t,j}^I · ReLU((q_{t,j}^I)ᵀ kₛᴵ),  s ∈ Ω_t
```

最终选择：T_t^H = TopK({I_{t,s}^H | s ∈ Ω_t}, k)

**可行性约束**：m·B ≥ k（候选池必须足够大以包含 k 个最终 Token）

### 复杂度分析

| 指标 | DSA（原始）| HISA |
|------|----------|------|
| 每查询代价 | O(L) | O(L/B + mB) |
| 每层代价 | O(L²) | O(L²/B + LmB) |

当 B 和 m 适当设置时（如 B=128, m=64），候选池大小为 8K，而原始 DSA 需扫描全部 128K Token，理论加速比约为 16×（实际受 GPU 并行效率影响）。

### 边界状态

| 条件 | 行为 |
|------|------|
| t ≤ k | 选择所有前缀 Token，等价于稠密注意力 |
| k < t ≤ mB | 选择所有块，等价于原始 DSA |
| t > mB | 层次化剪枝生效，HISA 效率优势显现 |

## 实验结果

### 索引器内核级加速

在 DeepSeek-V3.2 上评测，配置：查询块大小=1024，B=128，top-m=64，top-k=2048。

| 上下文长度 | HISA 加速比 |
|-----------|------------|
| 4K | ~1×（收益极小） |
| 32K | **~2×** |
| 128K | **~4×** |

*图：DSA vs. HISA 索引器内核延迟（4K-128K 上下文长度）*

关键发现：HISA 的第二阶段 Token 级精筛使其能在块内进一步聚焦关键 Token，避免了纯块稀疏方法在中间位置的性能下降。

### LongBench 结果（Table 1）

在 DeepSeek-V3.2 上，所有方法保留 2048 个 Token：

| 索引器 | 单文档QA | 多文档QA | 摘要 | 少样本 | 合成 | **平均** |
|--------|---------|---------|------|--------|------|---------|
| DSA（原始） | 0.5089 | 0.5266 | 0.2211 | 0.6224 | 0.6983 | **0.5155** |
| **HISA（本文）** | 0.4917 | 0.5196 | 0.2213 | 0.6162 | 0.7083 | **0.5114** |
| 块稀疏 | 0.4836 | 0.4976 | 0.2190 | 0.5945 | 0.6867 | **0.4963** |

HISA 与 DSA 的差距在 0.5% 以内，远小于块稀疏方法的差距（约 2%）。

### Token 选择一致性：IoU 分析

定义：IoU(T_t^H, T_t) = |T_t^H ∩ T_t| / |T_t^H ∪ T_t|

在 DeepSeek-V2-Lite 原型上，使用 LongBench 输入评测：

- **每层平均 IoU**：所有层均 >99%
- **不同上下文长度下平均 IoU**：即使在最长上下文下仍 >99%
- **最差情况（per-input 最小 IoU）**：>90%

约 10% 的下界对应边界情况：某个语义重要的 Token 所在块的池化代表键不够显著。

### 超参数灵敏度（候选池大小固定为 mB=8192）

| 配置 | B | m | 特点 |
|------|---|---|------|
| 细粒度 | 64 | 128 | 多文档 QA 更优 |
| **中间（推荐）** | **128** | **64** | 整体最优均衡 |
| 粗粒度 | 256 | 32 | 单文档 QA 略优 |

三种配置均在 DSA 的 2% 范围内，B=128, m=64 的中间配置取得最佳整体均衡。

## 总结

HISA 将稀疏注意力的索引瓶颈从 O(L²) 降至 O(L²/B + LmB)，通过巧妙的层次化两阶段设计，以极低的 Token 选择精度损失（IoU >99%）换取 2-4× 的实质性加速，且无需任何模型重训练，是即插即用的工程优化方案。

**主要贡献**：（1）精确识别了稀疏注意力系统中索引器的 O(L²) 性能瓶颈；（2）提出了块级粗筛 + Token 级精筛的两阶段层次化索引方案；（3）通过 TileLang 定制 GPU 内核实现了工程上的高效加速；（4）全面验证了方法在准确性（>99% IoU、接近 DSA 的 LongBench 分数）和效率（2-4× 加速）上的双重优势。

**局限性**：当前报告的加速比为索引器内核级别，端到端吞吐量收益受稀疏 MLA、KV 缓存管理等其他系统组件影响；均值池化在块跨越语义边界时可能损失信息；对于分布式推理系统的集成需要进一步工程投入。未来可探索训练感知的块评分、自适应块大小以及与推测解码等技术的协同优化。
