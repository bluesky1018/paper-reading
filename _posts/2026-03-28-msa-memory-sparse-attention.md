> 📄 **论文**：MSA: Memory Sparse Attention for Efficient End-to-End Memory Model Scaling to 100M Tokens
> 🔗 **arXiv**：[2603.23516](https://arxiv.org/abs/2603.23516)
> 🏢 **机构**：Evermind、Shanda Group、北京大学

## 一句话总结

MSA（内存稀疏注意力）提出了一种端到端可训练的稀疏注意力框架，仅需 2 块 A800 GPU 即可实现 1 亿 Token 的推理，相对 16K Token 的性能仅下降不到 9%，在 9 个长文本问答基准上超越了包括 Qwen3-235B 等大模型在内的同骨干 RAG 方法。

## 背景与问题

人类记忆能力据估计约为 10⁹ 比特，对应约 2-3 亿个 Token。然而，当前最先进的大语言模型的上下文窗口通常仅支持 128K 到 1M Token，距离人类记忆容量还有数量级的差距。更重要的是，即使是声称支持百万 Token 的模型，其性能往往随上下文长度的增加而显著退化。

现有的三类长期记忆方案各有其根本性局限：

| 方案类型 | 代表方法 | 主要局限 |
|---|---|---|
| 基于参数的记忆 | LoRA、Titans | 灾难性遗忘，容量无法扩展 |
| 外部存储 | RAG、MemAgent | 非端到端，精度受限 |
| 基于潜在状态 | RWKV、DeltaNet | 固定大小状态，极长上下文下遗忘严重 |

**RAG（检索增强生成）**是目前最广泛使用的方案，但它存在两个根本缺陷：首先，检索模块与生成模块分离训练，无法进行端到端优化；其次，生成模块无法根据任务需要动态调整检索策略，对多跳推理等需要跨文档综合信息的任务支持有限。

MSA 的核心洞察是：通过将稀疏检索机制直接集成到 Transformer 的注意力层中，并进行端到端联合训练，可以同时获得 RAG 的无限记忆容量优势和参数化方法的精确建模能力。

## 核心方法

### 整体架构

MSA 在 Transformer 架构的基础上引入了路由键投影器（Router K Projector），通过学习路由机制实现对相关文档的稀疏检索，将内存检索和答案生成融合为单一的联合优化框架。

![MSA 层架构示意](https://arxiv.org/html/2603.23516/x2.png)
*图2：MSA 层架构，展示路由 K/Q 投影器、分块均值池化、Top-k 选择和稀疏注意力集成*

### 稀疏注意力机制

**文档路由策略**：

给定文档集合 $\mathcal{D} = \{d_1, d_2, \ldots, d_N\}$，MSA 引入了额外的路由键投影矩阵 $W^h_{KR}$。具体流程如下：

1. **分块压缩**：对每个文档，将其 Key/Value 按固定块大小（64 个 Token）进行均值池化，得到压缩的路由键 $\bar{K}^R$ 和内容键值对 $(\bar{K}, \bar{V})$
2. **相关性评分**：计算查询的路由表示与压缩路由键的余弦相似度；文档级分数取其所有块分数的最大值
3. **Top-k 选择**：选取最相关的 k 个文档（默认 k=16），将其压缩 KV 拼接到当前查询上下文之前
4. **稀疏注意力**：仅对查询上下文和选中文档执行注意力计算，实现线性复杂度

**关键设计决策**：MSA 的路由机制仅应用于模型**后半层**（lower layers 缺乏足够的语义抽象能力，不适合做路由决策）。

### 位置编码设计

MSA 采用"双重 RoPE"策略解决位置外推问题：
- **文档独立位置 ID**：每个文档的位置 ID 从 0 重新开始，与文档总数解耦，使得在 64K Token 上训练的模型可以外推至 1 亿 Token
- **全局 RoPE**：查询和生成内容使用全局位置 ID（偏移 k，即检索文档数），保持生成上下文的连续性

### Memory Interleave（多跳推理）

对于需要跨多个文档综合信息的多跳推理任务，MSA 引入了 Memory Interleave 机制：

1. 模型生成文档 ID（而非直接生成答案）
2. 系统检索对应文档的原始文本并追加到查询上下文
3. 重复上述过程，直到模型从 ID 生成模式转换为答案生成模式
4. **每轮检索的文档数量由模型自适应决定**，无需人工设定

![MSA 推理流程与 Memory Interleave](https://arxiv.org/html/2603.23516/x3.png)
*图3：三阶段推理流程，展示迭代文档 ID 生成→文本检索→上下文扩展的循环过程*

### 百万级 Token 推理的系统优化

**Memory Parallel**：
- 路由键（$\bar{K}^R$）存储在 GPU VRAM（100M Token 约需 56GB）
- 内容键值对（$\bar{K}, \bar{V}$）卸载至 CPU DRAM（否则需要 169GB+ 显存）
- 每块 GPU 保存完整模型副本，通过分布式评分和全局 reduction 选择 Top-k 文档
- Tiling 机制防止大规模评分时的 OOM 问题

### 训练策略

**持续预训练**（158.95B Token）：引入辅助对比损失 $\mathcal{L}_{aux}$ 监督逐层路由学习，采用两阶段学习率调度（预热阶段强调辅助损失，主训练阶段强调语言模型损失）。

**后训练（SFT）**：两阶段渐进式扩展，Stage 1 在 8K 上下文建立指令跟随能力，Stage 2 扩展至 64K 上下文。

## 实验结果

### 与百万级上下文模型的对比

![上下文长度 vs 性能](https://arxiv.org/html/2603.23516/x1.png)
*图1：MS MARCO 数据集上性能随上下文长度（16K–100M Token）的变化。MSA 在 100M Token 时仍保持约 3.669 分，仅比 16K 时的 4.023 分下降 8.8%*

### 与同骨干 RAG 的对比（Qwen3-4B）

在 9 个长文本问答基准上，MSA 与各类 RAG 变体的对比：

| 数据集 | 最佳 RAG 得分 | MSA（自适应）得分 |
|---|---|---|
| MS MARCO v1（734万Token）| 3.032 | **4.141** |
| Natural Questions（147万Token）| 3.494 | **3.545** |
| DuReader（28万Token）| 3.848 | **4.155** |
| TriviaQA-10M（1000万Token）| 4.430 | **4.621** |
| NarrativeQA | 3.638 | 3.395 |
| PopQA | 3.315 | **3.433** |
| 2WikiMultiHopQA | 3.330 | **4.280** |
| HotpotQA | 4.022 | **4.061** |
| MuSiQue | 1.965 | **2.211** |
| **平均** | **3.372** | **3.760** |

MSA 在除 NarrativeQA 外的所有数据集上均优于最佳 RAG，平均提升分别为：相对标准 RAG +16.0%，RAG+重排序 +11.5%，HippoRAG2 +14.8%。

### 针刺测试（NIAH/RULER 基准）

![RULER 基准测试结果](https://arxiv.org/html/2603.23516/x4.png)
*图4：NIAH（RULER）测试结果，从 32K 到 1M Token。MSA 在 1M Token 时保持 94.84% 准确率（仅下降 3.93 个百分点），而 Qwen3-4B 在 1M Token 时崩溃至 24.69%*

### 消融实验

| 变体 | 平均分 | MS MARCO | NQ | 2WikiMultiHopQA |
|---|---|---|---|---|
| MSA-S2（完整） | **3.976** | **4.141** | **3.545** | **4.280** |
| MSA-S1（仅8K上下文） | 3.694 | 3.197 | 3.493 | — |
| 去除 Memory Interleave | 3.497 | 3.175 | — | 3.250（-19.2%）|
| 去除持续预训练 | 2.537（-31.3%）| 2.267 | — | — |
| 去除原始文本 | 2.325（-37.1%）| 2.625 | — | — |

关键发现：去除原始文本（仅用压缩特征）导致最严重的性能下降（-37.1%），说明检索原始文本对精确理解至关重要；持续预训练（-31.3%）和 Memory Interleave（在 HotpotQA 上 -19.2%）对多跳推理同样不可或缺。

## 总结

MSA 通过将稀疏检索机制直接集成到 Transformer 注意力层中，实现了三个目标的统一：终身记忆容量（无需预定义文档数量上限）、端到端优化（检索与生成联合训练）以及线性推理复杂度（通过 KV 压缩和分块 Top-k 检索）。在 2 块 A800 GPU 上实现 1 亿 Token 推理的工程成就，为大规模长文本处理提供了切实可行的方案。

在与强大基线的对比中，一个 4B 参数的 MSA 模型在 9 个 QA 基准的平均得分（3.760）不仅超越了同骨干的各类 RAG 方法，还在部分数据集上接近了使用 Qwen3-235B 的最佳 RAG 系统，充分体现了端到端优化的价值。

然而，MSA 目前仍有其局限性：对于需要对多个文档之间强耦合依赖关系进行建模的任务（如需要细粒度跨文档推理的 NarrativeQA），性能略弱于专门优化的方法。此外，Memory Interleave 在处理复杂多跳推理链时仍有改进空间。未来的工作可以探索更复杂的路由策略、自适应压缩率以及对跨文档强依赖场景的专项优化。
