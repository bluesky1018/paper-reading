## 基本信息

- **作者**: Zirui Liu, Jiayi Yuan, Hongye Jin, Shaochen Zhong, Zhaozhuo Xu, Vladimir Braverman, Beidi Chen, Xia Hu
- **机构**: Rice University, CMU, Stevens Institute of Technology
- **发表**: ICML 2024
- **arXiv**: [2402.02750](https://arxiv.org/abs/2402.02750)

## 一句话总结

提出 **KIVI**——首个在**不需要任何 fine-tune / 校准**的前提下把 **KV cache 压到 2-bit** 的方法。核心洞察:**K 和 V 的数值分布完全不同,应该用不同的量化粒度**。K 的 outlier 集中在某些 channel(需要 per-channel),V 的 outlier 均匀分布(用 per-token 即可)。这一差异化粒度让 2-bit 量化几乎不掉质量,KV cache 显存压到 **1/8**,batch size 提升 **2.35-3.47×**,decode 吞吐提升 **2.35×**。KIVI 是 KV cache 量化从"实验室想法"走向"生产实用"的关键一步。

## 背景:KV cache 为什么是 decode 瓶颈

对 7B 模型 + 32K context + batch 32:

- Weight: 14 GB(FP16)
- KV cache: $32 \times 32\text{K} \times 32 \times 128 \times 2 \times 2 = 16$ GB

**KV cache 反而比 weight 还大**。长 context + 大 batch 场景,KV 才是真正的显存主导,也是 decode 带宽瓶颈的来源。

INT4 KV 量化有了(KVQuant, Hooper 2024),但**INT2 一直做不到**——之前的方法在 2-bit 下 PPL 暴涨。KIVI 的贡献:找到了 2-bit KV 成功的关键。

---

## 核心机制:K 和 V 差异化量化

### 观察 K 的分布

![K 的每个 channel 的 magnitude 在不同 token 上几乎恒定——某些 channel 系统性地比其他大 10-100×。这就是 K 的 "channel outlier" 现象。](/assets/img/kivi/x2.png)
_Figure 2:K 的 channel-wise magnitude——稳定 outlier pattern_

对 K 做细致观察:

- 某些 channel(如 channel 42、89)在几乎所有 token 上都比其他 channel 大 10-100×
- 这些 outlier channel **集中且稳定**——不同 token 都在同样这些 channel 上出问题
- 这非常像 LLM.int8() 发现的 activation outlier

### V 的分布不同

- V 的 channel-wise magnitude 相对均匀
- outlier 更多出现在**某些特定 token 上**(如 BOS token、句号 token 等),不是特定 channel
- 更适合 per-token 量化

### 差异化量化方案

基于这两个观察,KIVI 设计:

- **K: per-channel 量化** — 每个 channel 独立 scale,正好隔离 outlier channel
- **V: per-token 量化** — 每个 token 独立 scale,正好隔离 outlier token

这个设计看似小差异,但对 2-bit 决定性:2-bit 只有 4 个 code word,粒度错了就全完。

### 滚动 + 残差存储

KIVI 还加了一个实用小技巧:**最近 $R$ 个 token 保留 FP16**,只对老 token 2-bit 化。

- $R$ 通常 128
- 最近 tokens 精度不损,长尾累积性误差可控
- 对 decode 最近 few-shot prompt 特别友好

![KIVI 的存储结构:older tokens 用 2-bit(K per-channel, V per-token),最近 R=128 tokens 保留 FP16 作为滚动缓冲。随着生成推进,FP16 buffer 满后新的被量化推进到 2-bit 池。](/assets/img/kivi/x3.png)
_Figure 3:KIVI 的滚动 KV 结构_

## 实验结果

### 质量:LLaMA-2 7B @ 2-bit KV

WikiText PPL:

| 方法 | bits | PPL |
|------|------|-----|
| FP16 | 16 | 5.47 |
| INT4 (both per-channel) | 4 | 5.52 |
| INT2 (both per-channel) | 2 | 8.73(差) |
| INT2 (both per-token) | 2 | 9.31(差) |
| **KIVI (K per-ch, V per-tok)** | **2** | **5.53** |

在 2-bit 精度下,差异化粒度让 PPL 几乎不掉(0.06 差距),朴素统一粒度则 +3 甚至 +4。

### 显存 + 吞吐

- KV cache: **1/8 of FP16**
- LLaMA 7B @ A100-80GB: batch size 从 20 → **58**
- Throughput: **2.35-3.47× of FP16 baseline**

## 工程影响

### 1. KV 量化从辅助优化变为一线

之前 KV 量化相对 weight 量化不受重视。KIVI 证明**把 KV 压到 2-bit 可行**,让 KV 量化进入主流推理栈。vLLM、TensorRT-LLM 陆续加入 KIVI 风格的 KV 量化选项。

### 2. K/V 的分布差异是一个重要发现

"K 有 channel outlier, V 有 token outlier" 的观察启发了后续一批工作:

- **KVQuant** (Hooper 2024):类似的差异化但配合 non-uniform quantization
- **QAQ** (2024):进一步精细化 K/V 独立处理
- **ThinK** (2024):K 的 pruning 基于 channel outlier 结构

### 3. 零校准的工程优势

KIVI 不需要 calibration data——任何模型直接应用。这让**部署阶段的集成成本几乎为零**,大幅降低推广门槛。

### 4. 长 context 场景的关键基础设施

对 100K-1M context 的模型,KV cache 是主要成本。KIVI 让"128K context 的 LLaMA-70B 塞进单卡"从不可能变为可能,直接影响 RAG、agent、长文档处理的经济性。

---

## 局限

1. **极致压缩下仍有退化**:虽然 2-bit 的 PPL 几乎不掉,但在复杂推理任务(MATH、HumanEval)上仍有 1-2 分损失
2. **滚动缓冲区大小敏感**:$R$ 太小质量下降,太大压缩优势减弱。实用中 128 是经验值
3. **和 MLA 不直接兼容**:MLA 的 latent 表示分布与标准 MHA 不同,需要重新设计量化粒度
4. **decode-only 优化**:prefill 阶段帮助有限(prefill 的 KV 还要算出来)

## 读完这篇你真正该带走的 4 件事

<callout emoji="white_check_mark" background-color="light-green" border-color="green">
1. **K 和 V 是两种完全不同的张量**:K 有 channel outlier,V 有 token outlier。之前人们用同一套方案,KIVI 第一次指出应该差异化处理
2. **不同量化粒度对应不同 outlier 模式**:per-channel 吸收 channel outlier,per-token 吸收 token outlier——粒度与 outlier 方向的"对齐"是低 bit 量化成功的关键
3. **滚动 FP16 窗口是实用的防御层**:对最近 tokens 保持高精度,长尾用低精度。这种"新旧分层"思想在很多系统里都有用
4. **2-bit KV 是长 context 经济性的最后一公里**:weight 量化早就解决,KV 最后被解决——这是现在大 context 低成本部署的关键拼图
</callout>
