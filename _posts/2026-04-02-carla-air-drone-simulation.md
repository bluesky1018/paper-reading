> 🏢 **机构**：Hong Zhang, Yanci Wen, Hanxuan Chen 等

## 一句话总结

CARLA-Air 将高保真城市驾驶模拟器 CARLA 与物理精确的多旋翼飞行模拟器 AirSim 融合在单一 Unreal Engine 进程中，提供了同步的 18 种传感器模态采集能力，为空地具身智能研究建立了统一的开源仿真基础设施。

## 背景与问题

低空经济、具身智能和空地协同系统的融合发展，对能够在单一物理一致环境中联合建模空中和地面智能体的仿真基础设施提出了迫切需求。然而，现有开源平台存在明显的领域分割问题：

- **城市驾驶模拟器**（如 CARLA）提供丰富的交通人口和逼真的城市场景，但缺乏空中动力学支持；
- **多旋翼模拟器**（如 AirSim）提供物理精确的飞行动力学，但缺乏逼真的地面场景；
- **跨进程桥接协同仿真**方案虽可连接异构后端，但引入了同步开销，且无法保证现代感知和学习流水线所需的严格时空一致性。

尤其值得关注的是，AirSim 的上游开发已停止维护，其庞大的用户群需要一个基于现代、活跃维护的基础设施的可持续演进路径。

## 核心方法

### 系统架构

CARLA-Air 通过**单进程架构**解决了 Unreal Engine 4 的根本约束——每个世界只允许一个活动游戏模式（GameMode）。

**关键设计洞见**：CARLA 的子系统通过继承和特权类关系紧密耦合到其游戏模式；而 AirSim 的飞行逻辑派生自通用 Actor 基类（而非游戏模式基类），可以作为普通世界 Actor 在任何时刻产生。

**解决方案**：引入 `CARLAAirGameMode`，通过类继承继承 CARLA 游戏模式基类，占据唯一的游戏模式槽位；然后通过组合将 AirSim 飞行 Actor 作为标准世界 Actor 生成。这使所有地面仿真子系统通过标准 UE4 生命周期获取，而空中飞行 Actor 则在世界初始化后任意时刻产生。

### 关键能力

**1. 单进程空地集成**
- 共享物理 tick，共享渲染管线
- 严格的跨所有传感器视角的时空一致性
- 单帧跨进程数据传输时间恒定小于 0.5ms（与传感器数量无关）

**2. 完整 API 兼容性**
- CARLA 和 AirSim 原生 Python API 完全保留
- 支持 ROS 2 接口
- 现有代码库零修改迁移

**3. 光真实物理一致的仿真世界**
- 规则合规的交通流
- 社会感知行人
- 空气动力学一致的多旋翼无人机动力学
- 同步采集最多 18 种传感器模态（RGB、深度、语义分割、LiDAR、雷达、IMU、GNSS、气压计等）

**4. 可扩展资产流水线**
- 支持导入自定义机器人平台、无人机配置、载具和地图

## 实验结果

**性能基准测试**（NVIDIA RTX A4000，AMD Ryzen 7 5800X，Ubuntu 20.04）：

| 配置 | FPS | VRAM (MiB) | CPU (%) |
|------|-----|------------|---------|
| 轻量级地面 | ~35 | ~4000 | ~38 |
| 轻量级联合（含无人机） | ~29 | ~4000 | ~54 |
| 中等联合 | ~22 | ~5500 | ~61 |
| 重度联合 | ~15 | ~7200 | ~72 |

关键发现：
- **帧率影响**：地面共同托管导致约 6.5 FPS 下降，空中物理引擎贡献另外 6.5 FPS 的下降，但空中开销完全体现在 CPU 利用率上（54% vs 38%），VRAM 占用基本不变
- **内存稳定性**：3 小时稳定性测试（357 个产生/销毁周期）中，VRAM 漂移约 10 MiB（线性回归 R²=0.11），确认无显著内存积累
- **延迟优势**：单进程架构下跨进程数据传输延迟恒定小于 0.5ms，而桥接协同仿真延迟随传感器数量近线性增长

## 总结

CARLA-Air 通过优雅的单继承加组合的架构设计，解决了 UE4 单游戏模式约束这一核心工程挑战，为空地具身智能研究提供了统一的高保真仿真平台。该平台不仅继承并扩展了已停止上游开发的 AirSim 的空中仿真能力，还在保持完整 API 兼容性的前提下，提供了跨 18 种传感器模态的时空一致数据采集能力。

**局限性**：当前系统基于 UE4，未来升级到 UE5 需要解决新的兼容性问题；性能基准测试在特定硬件配置下进行，实际性能因硬件和场景复杂度而异；大规模多智能体场景（数十架无人机同时运行）的可扩展性有待进一步验证。
