> 📄 **论文**：InCoder-32B: Code Foundation Model for Industrial Scenarios
> 🔗 **arXiv**：[2603.16790](https://arxiv.org/abs/2603.16790)
> 🏢 **机构**：北京航空航天大学、IQuest Research、上海交通大学等

## 一句话总结

InCoder-32B 是首个 32B 参数规模的工业代码基础模型，统一覆盖芯片设计、GPU 内核优化、嵌入式系统、编译器优化和三维建模五大工业编程领域。

## 背景与问题

随着代码大语言模型（Code LLM）的飞速发展，Qwen、DeepSeek、Claude 等模型在通用编程任务上取得了显著进步，甚至能在竞技编程中取得金牌级成绩。然而，这些模型在工业场景中的表现却大幅下滑——原因在于工业编程任务对硬件语义推理、专用语言构造和严格资源约束有着根本性的不同要求。

以 CUDA 内核优化为例，顶级模型在 Triton 算子生成任务上的调用成功率仅为 28.80%；在 Verilog 硬件描述任务中，通过仿真验证和形式等价检查的代码仅占 33.3%。工业代码智能领域长期缺乏高质量的开源大模型和对应的训练范式。

现有的工业数据极度稀缺且难以获取——GitHub 上公开的 Verilog 代码不足总量的 0.1%，CUDA 内核代码更是零散分布于各类专业仓库中。如何在数据匮乏的条件下训练出具备工业编程能力的大模型，是本文要解决的核心挑战。

## 核心方法

InCoder-32B 采用"通用预训练 → 工业中训 → 执行验证后训练"的三阶段训练策略，并引入了多个创新机制。

### 模型架构与训练概览

![InCoder-32B 工业代码智能范围](https://arxiv.org/html/2603.16790v1/x1.png)
*图1：InCoder-32B 覆盖的工业代码智能领域。左侧为通用软件开发任务，右侧为工业编程领域（芯片设计、GPU 内核优化、CAD/CAM 建模、编译器优化等）。*

### 阶段一：通用代码预训练

在海量通用代码数据上从零训练 32B 参数模型，建立扎实的代码基础能力。数据来源包括 GitHub 仓库级代码、StackOverflow 讨论、开源技术文档，以及通过 OCR 提取的技术文献内容。

### 阶段二：工业代码中训

中训阶段分为两个子阶段，渐进式扩展上下文窗口：
- **Stage 2.1**：8K → 32K token，注入精选工业代码数据
- **Stage 2.2**：32K → 128K token，引入合成工业推理数据

工业数据构建采用"模拟环境驱动"策略，为四大工业领域（芯片设计、GPU 优化、三维建模、代码优化）分别搭建自动化仿真环境，生成可验证的合成数据。

*图2：RMS Normalization 在大空间维度（512×512）上的 CUDA 网格配置策略对比。左图为 Claude 的错误配置（超出 CUDA 硬件限制），右图为 InCoder-32B 的正确实现（展平为一维网格）。*

![InCoder-32B 三阶段训练流程](https://arxiv.org/html/2603.16790v1/x3.png)
*图3：InCoder-32B 完整训练流程，包含预训练、中训（渐进式上下文扩展）和基于执行反馈的后训练三个阶段。*

### 阶段三：执行接地后训练

后训练阶段引入"执行接地验证"机制——对于每个训练样本，通过实际运行代码来验证其正确性，并将执行反馈用于模型优化，确保模型生成的代码不仅语法正确，还能通过功能测试。

![合成数据生成流程](https://arxiv.org/html/2603.16790v1/x4.png)
*图4：工业场景合成数据生成流程，包含场景规格定义、种子代码生成和带自动验证的 QA 对生成三个环节。*

### 工业领域专项覆盖

**芯片设计**：覆盖 Verilog/SystemVerilog 硬件描述语言，支持 RTL 代码生成、Bug 修复和形式验证。

**GPU 优化**：支持 CUDA 和 Triton 内核编写，需理解 CUDA 线程块层次、共享内存管理和 Tensor Core 使用。

**三维建模**：支持 CAD/CAM 代码生成（OpenSCAD、CadQuery），可直接从自然语言描述生成三维模型。

**编译器优化**：涵盖 C/C++ 编译优化、汇编级代码理解和嵌入式系统固件开发。

## 总结

InCoder-32B 填补了工业代码智能领域缺乏高质量开源大模型的空白。通过三阶段训练范式和模拟环境驱动的数据合成策略，该模型在工业编程任务上取得了显著进步，同时保持了与同规模通用代码模型相当的通用代码能力。

本工作的主要局限在于：(1) 工业数据覆盖仍不全面，部分细分工业领域（如光刻、EDA 工具等）尚未涵盖；(2) 执行验证依赖仿真环境，对于某些真实硬件场景可能存在差距；(3) 128K 长上下文能力在超长 RTL 设计任务上仍有提升空间。未来工作可进一步扩展工业数据规模并引入更强的形式验证机制。
