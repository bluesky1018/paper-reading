## 基本信息

- **作者**: Sang Michael Xie, Hieu Pham, Xuanyi Dong 等
- **机构**: Google DeepMind, Stanford
- **发表**: NeurIPS 2023
- **arXiv**: [2305.10429](https://arxiv.org/abs/2305.10429)
- **全名**: *DoReMi: Optimizing Data Mixtures Speeds Up Language Model Pretraining*

## 一句话总结

提出 **DoReMi (Domain Reweighting with Minimax optimization)**——**用一个小的 proxy 模型自动学出最优的数据混合比**。核心思路:不同 domain(Wikipedia、代码、ArXiv、网页...)的**最优比例**一直是经验调参(The Pile、LLaMA 的比例都是团队手拍),DoReMi 用 **Group Distributionally Robust Optimization (Group DRO)** 让**小 proxy 模型学出一个让"最难 domain 最容易学"的权重分布**。把这个权重配比用到大模型训练,**平均每 domain 的 perplexity 降 6.5%,下游 accuracy 提升 6.5%**,同时**训练速度快 2.6×**。DoReMi 证明"数据配比本身就是一个可优化的维度",开启了"自动化数据工程"的研究方向。

![DoReMi 的核心思想:先在小模型上用 Group DRO 学出权重 alpha,然后用 alpha 作为采样比例训大模型。小 proxy 的权重可以 transfer 到大模型训练。](/assets/img/doremi/x1.png)

## 背景:数据配比的"黑魔法"

### 大模型训练的数据配比

每个大模型训练都要决定:

- **Wikipedia vs Common Crawl 的比例?**
- **代码占多少?**
- **多语言比例?**
- **学术论文?**

例如 LLaMA 用:

- Common Crawl 67%
- C4 15%
- GitHub 4.5%
- Wikipedia 4.5%
- Books 4.5%
- ArXiv 2.5%
- StackExchange 2%

**这个配比哪来?**——团队经验 + 少量消融实验。没有**系统化**方法。

### 问题

- **调参空间巨大**:N 个 domain 有 N-1 维权重空间
- **成本高**:每个配比实验要跑一个完整 training run
- **"最优" 依 model size 变化**:小模型最优 ≠ 大模型最优(但没法直接在大模型 search)

### DoReMi 的想法

**能不能用小模型自动搜出好配比,然后用到大模型?**

---

## 核心机制:Group DRO

### Distributionally Robust Optimization

标准训练最小化**平均 loss**:

$$
\min_\theta \mathbb{E}_{x \sim P_{\text{train}}}[L(x; \theta)]
$$

Group DRO 最小化**最坏 domain 的 loss**:

$$
\min_\theta \max_{P \in \mathcal{P}} \mathbb{E}_{x \sim P}[L(x; \theta)]
$$

其中 $\mathcal{P}$ 是 domain 分布的集合。这让模型**对最难的 domain 也能做好**——即学到一个 robust 的表示。

### DoReMi 的训练流程

![DoReMi 的训练:同时训 proxy model(policy)和 domain weights $\alpha$。在每个 step,算 proxy 对每个 domain 的 "excess loss"(proxy loss 比 reference model 多多少)。excess loss 大的 domain 分配更高权重——让 proxy 专注在"还没学好"的 domain。](/assets/img/doremi/x2.png)
_Figure 2:DoReMi 的动态权重学习_

**Stage 1: 训 reference model**

用 uniform 或原始配比训一个小 reference model(280M)。

**Stage 2: 训 proxy model with Group DRO**

同样 280M 大小。但现在:

- **动态维护 domain weights $\alpha$**
- 每 step 计算每个 domain 的 **excess loss**:$L_{\text{proxy}}(\text{domain}_i) - L_{\text{ref}}(\text{domain}_i)$
- excess loss 大 → **这个 domain 还没学好,给它更多权重**
- 用 Group DRO 的 multiplicative weights update:$\alpha_i \leftarrow \alpha_i \exp(\eta \cdot \text{excess}_i)$

训练收敛后得到 **optimal $\alpha^*$**。

**Stage 3: 用 $\alpha^*$ 训大模型**

把学到的权重直接用于训大模型(8B),按 $\alpha^*$ 的比例采样数据。

### 为什么 "excess loss" 有意义

$L_{\text{proxy}} - L_{\text{ref}}$ 反映 **"proxy 在这个 domain 还没学到的部分"**——这些 domain 还有学习空间。把权重倾向这些 domain,**让整体训练更有效**。

## 实验结果

### The Pile(22 domain)

在 The Pile 上 DoReMi 学出的权重与原 Pile 权重差异显著:

- 学术/technical 内容权重**上升**(ArXiv、PubMed)
- 某些冗余内容权重**下降**
- 下游 accuracy 整体提升

### 8B 模型上的效果

| Metric | Baseline | **DoReMi** |
|--------|----------|-----------|
| 每 domain 平均 PPL | — | **-6.5%** |
| 下游 accuracy | — | **+6.5%** |
| 训练速度(达到同性能) | 1× | **2.6×** |

## 工程影响

### 1. 把"数据配比"变为可优化维度

DoReMi 之前,配比靠拍脑袋。DoReMi 让**数据配比**成为与 hyperparameter 一样的可系统优化对象。

### 2. 小 proxy 可 transfer

小模型学出的 domain weight 能 transfer 到大模型——这是关键的**工程可行性**。毕竟没人能在 70B 上做 grid search。

### 3. 启发更多数据工程研究

DoReMi 之后:

- **Data Mixture Inference**(Liu 2024):逆向推断现有模型的 data mix
- **Dynamic Data Mixing**(各种 curriculum work)
- **Data Selection for LLM**(各种 filtering 论文)

"data engineering as a first-class research direction" 正在形成。

### 4. 在 LLaMA 3、Qwen 等产品中应用

LLaMA 3 的数据混合是通过类似 proxy-based 方法搜索;Qwen 系列也有类似工程。DoReMi 及变体成为**大模型训练的标配**。

### 5. 连接 fairness 和 efficiency

Group DRO 最初是 **fairness** 领域工具(保护少数群体)。DoReMi 把它用到 **efficiency**(让训练更快)—— 这种跨领域思想的迁移很有启发性。

---

## 局限

### 1. Proxy 和大模型不完全一致

小模型的 optimal weight **不一定完全等于**大模型的——有 transfer gap。DoReMi 论文显示效果好,但理论不是严格的。

### 2. Domain 划分的 arbitrariness

"什么是一个 domain?"——Wikipedia 是一个还是多个?要看粒度。Domain 划分的不同会影响 DoReMi 结果。

### 3. 计算开销

Stage 1 + Stage 2 需要训两个 280M 模型——虽然比在 8B 上 search 便宜,但也不是 free。

### 4. 对冷门 domain 可能不利

如果某些 domain 特别难(outlier),Group DRO 会给它大权重——但这些 domain 可能**根本学不会**,浪费计算。
