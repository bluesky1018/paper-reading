## 一句话总结
提出 MAPD（多智能体协议蒸馏）框架，通过结构化 JSON 协议作为中间表示，有效结合知识蒸馏和强化学习，将专有模型的搜索推理能力迁移到开源小模型。

## 背景与问题

**Agentic Search**（代理式搜索）是指让 LLM 交替执行推理与检索操作的智能搜索范式——模型不再是被动接受检索结果，而是主动规划检索策略、迭代获取证据、逐步构建答案。

然而，用强化学习（RL）优化 Agentic Search 面临两大核心挑战：

1. **RL 信号稀疏**：最终答案是否正确的信号无法有效指导中间步骤的推理和检索决策
2. **知识蒸馏受阻**：从专有模型蒸馏时，由于 logits 不可见、分词器不兼容，传统的 logit-matching 蒸馏方法无效；而直接模仿轨迹只会迁移"风格"，而非真正的推理能力

这种"分布鸿沟"导致开源小模型与专有模型（如 GPT-4、Claude）在搜索推理质量上存在显著差距。

## 核心方法

### MAPD 框架设计

MAPD 的核心创新是引入**结构化、风格标准化的 JSON 协议**作为中间表示，连接蒸馏与 RL 两个训练目标。

![MAPD架构](https://arxiv.org/html/2607.24280v1/x1.png)
*图：MAPD 框架整体架构，展示离线多智能体系统和学生模型的协议驱动训练*

### 离线多智能体分解系统

专有教师模型不再直接参与学生模型训练，而是驱动一个离线多智能体系统：

1. **查询分解代理**：将复杂问题拆解为子查询
2. **检索执行代理**：执行搜索并收集证据
3. **失败修复代理**：识别并修复失败的检索步骤
4. **协议生成代理**：将轨迹转换为标准化 JSON 协议

生成的 JSON 协议包含三个关键字段：
- `task_type`：任务类型分类
- `reasoning_plan`：推理规划路径
- `grounding_facts`：接地事实证据

### 特权学生分支

训练阶段，学生模型包含两个分支：

| 分支 | 训练时 | 推理时 |
|------|-------|-------|
| 协议分支（特权） | 接收完整 JSON 协议 | 不可用 |
| 标准分支 | 仅接收问题 | 正常使用 |

协议分支提供密集的蒸馏信号，弥补 RL 信号的稀疏性；同时 RL 目标保证模型学习真正的推理技能而非风格模仿。

### 风格标准化

JSON 协议通过标准化格式解耦了教师模型的"风格偏好"与实际推理内容，有效防止"风格漂移"和"冗长退化"——这是直接轨迹模仿的常见问题。

## 实验结果

在 7 个问答基准上的评测结果：

| 模型 | 平均成功率 |
|------|----------|
| Qwen3-1.7B + MAPD | 39.4% |
| Qwen3-4B + MAPD | 44.4% |
| 竞争蒸馏基线 | 显著落后 |
| 竞争 RL 基线 | 显著落后 |

- **跨教师泛化**：MAPD 在不同专有教师模型（不同风格）下均保持性能稳定
- **防止退化**：有效抑制了直接模仿导致的冗长和风格问题
- **参数高效**：在极小模型（1.7B）上也取得了有竞争力的结果

## 总结

MAPD 提供了一种优雅的解决方案，通过结构化中间协议弥合了开源与闭源搜索代理之间的能力差距。将知识蒸馏与强化学习的优势有机结合，既利用了专有模型的推理质量，又通过 RL 确保真正的技能习得。

局限性方面：JSON 协议的设计本身依赖专有多智能体系统的构建，增加了数据准备成本；且当前实验规模集中在 1.7B-4B 参数模型，在更大规模模型上的效果有待验证。
