## 基本信息

- **作者**: Rafael Rafailov, Archit Sharma, Eric Mitchell, Stefano Ermon, Christopher D. Manning, Chelsea Finn
- **机构**: Stanford
- **发表**: NeurIPS 2023 (Oral)
- **arXiv**: [2305.18290](https://arxiv.org/abs/2305.18290)
- **全名**: *Direct Preference Optimization: Your Language Model is Secretly a Reward Model*

## 一句话总结

提出 **DPO (Direct Preference Optimization)**——用一个漂亮的数学推导把 RLHF 的三阶段(SFT → RM → PPO)压成两阶段(SFT → DPO),**完全去掉 RM 和 PPO**。关键洞察:在 KL 约束下,最优 policy 和 reward function 之间有**解析对应关系**——因此可以把 preference data 直接优化成 policy,**策略本身就隐式包含了 reward**。DPO 只需要一个额外的 loss(类似一个加权 SFT),无需 RL 框架、无需 critic 网络、无需 reward hacking 防御。实验上 DPO 在多个任务上**持平或超过 PPO**,且训练简单 5-10×。DPO 迅速成为开源 LLM post-training 的事实标准,被 LLaMA 3、Qwen2.5、Mistral 等广泛采用。

![DPO vs PPO:PPO 需要 reward model + RL,DPO 直接在 preference data 上做 supervised 优化,用解析公式把 RM 消掉。简洁、稳定、不需要 RL 框架。](/assets/img/dpo/x1.png)

## 背景:PPO 的痛点

### RLHF 的复杂性

InstructGPT 的 PPO 阶段需要:
- 训练 reward model(6B 级别)
- 保留 SFT 模型 作为 reference
- 运行 PPO:policy + value network + reward model 同时在 GPU
- KL penalty 调参敏感
- **Reward hacking**:policy 经常"作弊"满足 RM,产生奇怪输出

工程复杂度高,资源需求大。

### Can we skip PPO?

Stanford 团队的问题:**能不能不做 RL,直接在 preference data 上优化 policy?**

他们的答案:可以——用一个数学 trick。

## 核心推导

### RLHF 的优化目标

RLHF 目标:

$$
\max_\pi \mathbb{E}_{x \sim \mathcal{D}, y \sim \pi} [r(x, y)] - \beta D_{KL}(\pi \| \pi_{\text{ref}})
$$

这是个有 KL 约束的 reward maximization。

### 关键 insight:最优解有 closed form

对上面的优化问题,**最优 policy** 有解析解:

$$
\pi^*(y|x) = \frac{1}{Z(x)} \pi_{\text{ref}}(y|x) \exp\!\left(\frac{1}{\beta} r(x, y)\right)
$$

其中 $Z(x)$ 是归一化常数。

**反过来解**,reward 可以用 optimal policy 表示:

$$
r(x, y) = \beta \log\frac{\pi^*(y|x)}{\pi_{\text{ref}}(y|x)} + \beta \log Z(x)
$$

### 带入 Bradley-Terry preference model

RM 的训练目标是 Bradley-Terry:

$$
P(y_w \succ y_l | x) = \sigma(r(x, y_w) - r(x, y_l))
$$

**把上面的 $r$ 表达式带入**,$\log Z(x)$ 消掉(因为两边都有),得到:

$$
P(y_w \succ y_l | x) = \sigma\!\left(\beta \log\frac{\pi(y_w|x)}{\pi_{\text{ref}}(y_w|x)} - \beta \log\frac{\pi(y_l|x)}{\pi_{\text{ref}}(y_l|x)}\right)
$$

### DPO Loss

用 maximum likelihood 优化:

$$
\mathcal{L}_{\text{DPO}} = -\mathbb{E}_{(x, y_w, y_l)}\!\left[\log\sigma\!\left(\beta \log\frac{\pi_\theta(y_w|x)}{\pi_{\text{ref}}(y_w|x)} - \beta \log\frac{\pi_\theta(y_l|x)}{\pi_{\text{ref}}(y_l|x)}\right)\right]
$$

**就这一条 loss 就够了**——优化 $\pi_\theta$,等同于做 RLHF 但不需要 RM、不需要 PPO。

### 直观理解

![DPO loss 的直观:让 winner 的 log-prob 比 loser 高(相对 reference)。这个梯度方向天然偏向"用户偏好的 completion"。](/assets/img/dpo/x2.png)
_Figure 2:DPO loss 梯度方向_

DPO loss 的梯度:

$$
\nabla \mathcal{L} \propto \sigma(\text{reward diff}) \cdot \nabla[\log \pi_\theta(y_w) - \log \pi_\theta(y_l)]
$$

含义:**增加 winner 的 log-prob,减少 loser 的 log-prob,且按"当前 reward 差距"加权**——差距小(模型还分不清)就学多点,差距大(模型已经会了)就学少点。

像一个自适应的对比 SFT。

## 实验结果

### 1. Controlled sentiment

在 IMDb 情感控制任务(生成积极评价):

![DPO 和 PPO 在 sentiment control 任务上达到的 reward-KL 帕累托:DPO 比 PPO 略好,且完全不需要 RL。](/assets/img/dpo/x3.png)
_Figure 3:Sentiment control 任务对比_

DPO **帕累托领先 PPO**——同 KL 约束下 reward 更高。

### 2. Summarization(TL;DR)

Human preference win rate vs PPO (175B):

- SFT: 36%
- PPO: 50%(基准)
- **DPO**: **54%**

**DPO 比 PPO 略优**,训练简单很多。

### 3. 单轮对话(Anthropic HH)

HH(Helpfulness/Harmlessness)benchmark:

- SFT: 39%
- PPO: 50%
- **DPO**: **56%**

![DPO 在多任务上都持平或超过 PPO,且 token efficiency(训练数据利用率)更高。](/assets/img/dpo/x4.png)

## 优势全景

### 1. 工程简单

PPO:需要 Actor + Critic + RM + SFT 四个模型同时在 GPU
DPO:只需 Policy + SFT(作为 $\pi_{\text{ref}}$)两个

**训练成本降 2-3×**。

### 2. 更稳定

PPO 对超参极敏感(KL coefficient、GAE lambda 等),容易发散。
DPO 是标准 supervised loss,稳如 SGD。

### 3. 数据利用率高

PPO 需要 policy 在线生成 rollouts,每条数据只用一次。
DPO 是 offline——整个 preference dataset 可以多 epoch 训,利用率高。

### 4. 没有 reward hacking(某些形式)

PPO 有一个"policy 作弊欺骗 RM"的问题。DPO 没有显式 RM,但**隐式 reward 仍可能 hacking**(例如 policy 学会让 winner 大而 loser 小,但两者都是坏 output)。

## 历史影响

### 1. 开源 LLM post-training 的事实标准

DPO 发布后(2023-05),几个月内所有主流开源 LLM 的 post-training 都切到 DPO:

- **Zephyr 7B**(HuggingFace,2023-10)
- **Tulu 2**(AllenAI,2023-11)
- **LLaMA 2 / 3 post-training**(LLaMA 3 明确提到 DPO)
- **Mistral / Mixtral Instruct**
- **Qwen 2 / 2.5 Chat**
- **DeepSeek Chat**

几乎 **所有开源模型** 都用 DPO 或其变体。

### 2. 催生 DPO 变体家族

DPO 简单的数学让后续改进层出不穷:

- **IPO** (2023):修正 DPO 在某些情况的不稳
- **SimPO** (2024):去掉 reference model,length normalization
- **KTO** (2024):只用"好坏标签",不需成对数据
- **ORPO** (2024):SFT + preference 合并为单阶段

每一个都是对 DPO 的小改进,反映 DPO 作为基础工作的生命力。

### 3. 推动对 RLHF 的理解

DPO 的数学推导揭示:**RLHF 的 RL 其实是可避免的**——preference 优化本质是一个统计推断问题。这让 RLHF 研究更清晰。

### 4. 降低了对齐的门槛

PPO 要有 RL 经验的工程师 + 大算力。DPO 用一张 GPU 就能跑。**让开源社区能参与对齐研究**——这极大推动了 alignment 的民主化。

## 局限

### 1. 需要 high-quality preference data

和 PPO 一样,DPO 的质量上限由 preference data 决定。标注员的偏好 biases 会直接反映到模型。

### 2. Reference model 的选择重要

$\pi_{\text{ref}}$ 通常是 SFT 模型。如果 SFT 差,DPO 的起点就差——这和 PPO 一样。

### 3. "Distribution drift" 问题

DPO 是 off-policy(不是自己在线生成 rollouts)。如果 preference data 的分布和当前 policy 分布差太远,DPO 学不好。这催生了 **Iterative DPO**(LLaMA 3 用的那种)。

### 4. 不适合 online RL

某些场景(如 Agent 训练)需要和环境持续交互。DPO 是离线的,不直接适用 agent RL——这是 GRPO / PPO 的地盘。
